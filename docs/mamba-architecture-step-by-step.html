第 1 章

在标准 Transformer 中，每一层都有两个子模块：一个用于跨 token 混合（Attention），一个用于逐 token 处理（FFN）。Mamba 用一个统一的模块同时取代了这两者。

第 4 章

步骤 2 —— Conv1D（局部上下文）

在进入 SSM 之前，我们对 token 序列运行一个深度可分离的 1D 卷积（depthwise 1D convolution）。「深度可分离」意味着每个通道独立进行卷积——通道之间没有混合。当卷积核大小 k=4（在我们的例子中是 2）时，每个 token 都会与其紧邻的前一个 token 混合。

第 7 章

步骤 5 —— 离散化（Discretization）

SSM 是在连续时间中定义的，但我们以离散步骤处理 token。我们必须使用步长 Δt 将连续参数 A 和 B 转换为它们的离散时间等价形式。

离散化公式

衰减（decay，保留多少旧状态）
Āt = exp(A × Δt)
输入缩放（input scale，写入多少新输入）
B̄t = Δt × Bt

可学习的基参数 A

A 是一个对角矩阵（以向量形式存储），包含可学习的负值。它们代表「自然」的衰减速率。

第 8.5 章

并行扫描（Parallel Scan）究竟如何计算 SSM

第 8 章展示了一个 token 的更新。在训练期间，我们需要长序列中 每个 token 的隐藏状态。普通的递推会从左到右依次进行： h1、然后是 h2、然后是 h3。Mamba 使用并行扫描，让其中许多合并操作同时发生。

玩具设置：一个通道，一个状态维度

为什么是 20 轮？

1024 = 210。上扫需要 10 个树层级来构建 G[1:1024]。下扫需要 10 个树层级来将正确的左侧上下文分发给每个 token。 因此依赖深度约为 10 + 10 = 20 轮，而不是 1024 次从左到右的等待。

这是否意味着只需要 20 次计算？

不是。总运算量并不会变成 20 次操作。真正减少的是 关键路径：即必须等待前面步骤的步骤数量。

顺序递推

h1 等待h0
h2 等待h1
h3 等待h2
...
h1024 等待h1023
工作量：约 1024 次状态更新
依赖深度：1024 轮

第 1 轮：512 次对合并同时进行
第 2 轮：256 次块合并同时进行
...

因此，扫描甚至可能比普通的从左到右循环做更多的原始合并簿记工作。 它能取胜，是因为 GPU 讨厌长的依赖链，而喜欢同时进行大量独立操作。

预填充（Prefill）对比：Mamba 有扫描 vs 无扫描

这对预填充（prefill）很重要：在生成开始之前处理整个 prompt。 在单 token 解码期间，Mamba 只更新一次状态，因此扫描在那里并不是主要技巧。 在预填充期间，扫描让 prompt 的 token 以并行批次的方式运行。

针对 N=1024 的预填充方法 原始递推工作量 顺序等待次数 墙钟时间直觉
无并行扫描 约 1024 次更新 1024 必须沿着序列逐个 token 推进。
有并行扫描 O(1024) 次合并 约 20 许多合并同时发生；等待链是树的高度。

有用的速度直觉

如果递推依赖是整个瓶颈，且 GPU 有足够的并行工作， 那么对 1024 个 token 而言，依赖深度的改善大约为 1024 / 20 ≈ 51×。实际的端到端预填充加速会更小，因为 投影、卷积、内存搬运、kernel 开销和硬件限制也同样重要。

底层心智模型：Mamba 不能使用固定的卷积核，因为每个 token 都会创建 自己的 at 和 bt。但每个 token 仍然会创建一个可复合的仿射函数。 并行扫描把「逐个执行 N 步递推」变成了「在一棵树中复合许多小函数，然后读出每个前缀」。

第 9 章

缓存了什么——以及为什么 Mamba 永不增长

在推理期间，每个模型都必须记住一些关于已经见过的 token 的信息。 问题是：需要记多少？这正是 Mamba 与 Transformer 根本不同的地方。

Transformer 的问题：KV Cache 无限增长

在 Transformer 中，自回归生成期间，每个新 token 都需要关注 所有先前的 token。为避免重新计算过去 token 的 Key 和 Value， 它们被存储在一个 KV cache 中。

Transformer 的 KV Cache —— 每层

存储： 到目前为止见过的每个 token 的 K 向量 + V 向量 形状： 2 × N × d 当 N=100K 时： 2 × 100,000 × 2,048 × 2 字节 = 每层 781 MB

KV cache 随序列长度线性增长。在长上下文中，它可能超出 GPU 内存。

Mamba 的状态：固定大小，无论序列多长

Mamba 没有 KV cache。相反，它维护一个固定大小的隐藏状态， 该状态会随着每个 token 被更新——而不是追加。处理完一个 token 后， 旧状态就消失了，只剩下更新后的状态。以下是确切存储的内容：

Mamba 推理状态 —— 每层

1. SSM 隐藏状态
h ∈ ℝE × n

E 个扩展维度中的每一个都维护自己的 n 维状态向量。 这个状态概括了所有过去的 token——就像一段被压缩的记忆。

玩具：E=4, n=2 → 8 个数字
真实：E=4096, n=16 → 65,536 个数字
2. Conv1D 缓冲区
buf ∈ ℝE × (k-1)

Conv1D 需要看到前 k-1 个 token 的 x' 值（其中 k 是卷积核大小，通常为 4）。 这是一个很小的循环缓冲区。

玩具：E=4, k=2 → 4 个数字
真实：E=4096, k=4 → 12,288 个数字
每层总状态： E × n + E × (k − 1)
玩具：8 + 4 = 12 个数字
真实：65,536 + 12,288 = 77,824 个数字
在 FP16 下：77,824 × 2 字节 = 每层 156 KB
关键点：这个状态是固定的。Token 1 和 token 1,000,000 使用 完全相同的状态内存量。状态不会增长——它会被原地更新。 旧信息通过递推被压缩进状态中，而不是原样存储。

为什么是 E × n？理解状态的形状

你可能会问：为什么状态是 E × n，而不是 d × d 或 N × d？ 让我们追溯每个维度的来源：

E （扩展维度） 输入 x（维度 d）被向上投影到维度 E = 2d。SSM 运行 E 份独立的递推副本——每个扩展维度一份。每份副本都有自己的状态。 n （状态维度） 每份独立的 SSM 副本维护一个 n 维状态向量。在真实 Mamba 中，n 通常为 16。这是每个通道的「记忆容量」——即每个通道能同时记住多少种不同的信息。

为什么任何地方都没有 N²

你可能预料到某个地方会出现 O(N²)——毕竟 Transformer 就有。但 Mamba 没有注意力机制，因此也没有 N × N 的相似度矩阵。 以下是每个模型在解码期间计算的内容：

Transformer 解码

新的查询 q 关注 所有 N 个已缓存的 key：
scores = q · KT → 每个 token O(Nd)
attn = softmax(scores) · V → O(Nd)

成本随 N 增加而增长，因为查询必须「查看」每一个过去的 key。

Mamba 解码

新 token 原地更新状态：
h = Ā × h + B̄ × x → O(En)
y = C · h → O(En)

成本始终相同。状态 h 的大小为 E×n，与前面有多少 token 无关。

取舍：Mamba 的固定状态意味着它是对过去信息进行压缩，而不是原样存储。 具有全注意力的 Transformer 可以在 token 100,000 处回忆起 token 1 的任何细节（代价是巨大的 KV cache）。 Mamba 的状态是一个有损摘要——旧信息呈指数衰减（由 Ā 控制）。 这就是为什么混合架构（Mamba + 少量注意力层）正在成为实用的最佳方案。

关键洞察

Transformer 的 KV cache 是无损的——它存储每个过去 token 精确的 K 和 V。 Mamba 的状态是有损的——它通过递推 ht = Āt × ht-1 + B̄t × xt 将所有过去 token 压缩成一个固定大小的向量。 选择性机制（Δ）确保重要的 token 被强力记住，而 噪声 token 迅速衰减。这就是为什么 156 KB 可以取代 781 MB——因为那 781 MB 中的大部分 都在存储诸如「the」「of」「is」这样模型根本不需要的 token 信息。

完整图景

关键要点

1
Mamba 用一个单一模块取代了 Attention 和 FFN。

参数减半，表达能力相同。选择性 SSM 处理跨 token 混合（Attention 的职责），而门控处理逐 token 处理（FFN 的职责）。

2
选择性 SSM 从输入中计算 B、C 和 Δ——内容相关的处理。

与这些参数固定的经典 SSM（S4）不同，Mamba 让它们依赖于输入。每个 token 都有自己的动力学。

3
Δ（delta）控制遗忘/写入的平衡——选择性的核心。

较大的 Δ = 抹除旧状态、强力写入新内容。较小的 Δ = 保留状态、几乎不写入。模型学会了何时记住、何时遗忘。

4
Conv1D 提供局部上下文，SSM 提供长程上下文，门控提供输出控制。

三种互补的机制在一个单一模块中协同工作。

5
推理期间：每个 token O(1)，恒定内存。没有 KV cache！

隐藏状态 h 是一个固定大小的向量（每个通道 N 个元素）。与 Transformer 的 KV cache 随序列长度线性增长不同，Mamba 的内存恒定不变，无论处理了多少 token。

Transformer 推理

O(n)

KV cache 随每个 token 增长。
内存：每层 O(n × d)。

Mamba 推理

O(1)

状态固定，每个 token 恒定。
内存：每层 O(E × N)。
