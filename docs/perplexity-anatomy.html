困惑度
的解剖

你的语言模型有多「惊讶」？我们将从一个 token 开始，一步一步、小心翼翼地搭建答案——直到一个数字就能告诉你，模型到底有多困惑、又有多自信。

最终目的地
困惑度 = exp(− 1/N · Σ log P(xi | x<i))

到最后，这个公式会显得理所当然。我们会从一个几乎有点孩子气的问题出发，推导出每一个符号：当模型猜测下一个词时，它猜对的频率有多高？

§ I

模型是下一个 token 的猜测者。

暂时忘掉你听说过的关于 Transformer、注意力（attention）和数十亿参数的一切。把模型剥离到它在推理时真正做的唯一一件事。

一个语言模型，在其不可再约简的核心上，反复地玩同一个游戏：给定到目前为止的文本，预测接下来会出现什么。不是一句话，不是一段话。只是下一个单独的片段——下一个 token。

给它看「The cat sat on the」。模型并不「知道」答案。它在词表中的每一个可能 token 上产生一个概率——一张长长的排序列表。mat 可能拿到 41%。floor 12%。roof 4%。banana，谢天谢地，只有 0.001%。

那张排序列表就是模型对这个世界的信念，在这个确切时刻、给定这个确切前缀时被冻结下来。我们接下来要做的一切——每一个公式、每一个指标——都只是从不同的视角问同一个问题：

当真相揭晓时，模型的赌注下得是否明智？
§ II

token，以及它们所处的概率。

「token」不是一个词。token 是你的分词器（tokenizer）说它是什么就是什么——是模型当作一个原子来处理的一段文本。

对于 GPT 风格的模型，单词 "unbelievable" 可能会被切成三个 token：un · believ · able。单词 "the" 是一个 token。空格很重要。标点很重要。一个拼写错误可能把一个词打散成一长串细小的碎片。

这对困惑度很重要，有一个具体的原因：困惑度是按 token 计算的。两个使用不同分词器的模型，在同一个英文句子上打分，其结果并不能直接比较。始终要检查分词器。

概率单纯形

每当模型看到一个上下文，它都会输出一个长度为 |V| 的向量（词表大小——通常是 30,000 到 200,000 个条目），其中每个条目都是非负的，且整个向量之和为 1。

这个对象住在数学家所说的概率单纯形（probability simplex）上。对于一个小小的三 token 词表，你可以把它想象成一个三角形：

§ III

惊讶度：用比特度量。

如果我们想给模型打分，就需要一个数字：当模型错的时候很大，当模型对的时候很小。最自然的这样一个数字就是惊讶度（surprise）。

想象一下，我告诉你今天早上太阳升起了。你并不惊讶。你给这个事件分配的概率基本上是 1。现在想象我告诉你有一颗陨石落在了你的厨房里。你会极度惊讶——你给它分配的概率几乎为 0。

所以惊讶度是概率的某个函数，当 P → 1 时趋于 0，当 P → 0 时趋于无穷。许多函数都能做到这一点，但有一个特定的选择——负对数概率——它的性质如此优美，以至于整个信息论都建立在它之上。

惊讶度(x) = − log P(x)

为什么是这一个确切的公式？三个原因，每一个都是我们使用它的全部理由。

为什么是这个函数，而不是别的？

① 它有一个单位：比特。

如果 P = 1/2，惊讶度恰好是 1 比特——也就是回答一个是/否问题所需的信息量。P = 1/256 呢？那是 8 比特，一个字节的大小。惊讶度变成了一个你可以存储的量。

② 它在独立事件上可加。

如果两个独立的事情都发生了，它们的概率相乘（P(A,B) = P(A)·P(B)），但它们的惊讶度相加：−log P(A,B) = −log P(A) + −log P(B)。惊讶度表现得像一个预算。

③ 它会对过度自信进行灾难性的惩罚。

如果你的模型说「这个 token 的概率是 0.0001」，而那个 token 正是接下来实际出现的，你就要付出 −log₂(0.0001) ≈ 13.3 比特 的惊讶度——相当多。如果你的模型说「0」，你会被收取无穷大。这正是正确的行为：一个自信地排除真相的模型，理应受到无限惩罚。

在本文中，做数学时我们使用自然对数（以 e 为底），因为困惑度公式用到了 exp。概念上，以 2 为底的对数（比特）更容易感受。它们之间的比值只是一个常数——它们表达的是同一个意思。

§ IV

从一个 token 到一句话。

模型不会孤立地预测一个 token。它预测的是整条流——一个 token 接着一个 token，每一个都以它之前的内容为条件。要在一句话上给它打分，我们就把它的惊讶度取平均。

拿这句话 "the cat sat on the mat" 为例。分词后——我们假装每个词是一个 token——它有 6 个 token。当我们从左到右滑动时，模型产生 6 个概率分布，每个位置一个：

那最后一行就是著名的交叉熵损失（cross-entropy loss）——用于训练每一个现代语言模型的损失函数。从机制上讲，它是负对数概率的平均值。从概念上讲，它是每个 token 的平均惊讶度。

L = − 1N Σi=1N log P(xi | x<i)

大声读出来：「负的 N 分之一，对所有位置求和，取模型在该位置给实际下一个 token 的对数概率。」这个公式里的每一项现在都已经熟悉了。

这个数字出现在每一篇 Transformer 论文的每一条损失曲线上。当你看到 GPT-2 达到 3.0 的训练损失时，它的意思是：平均而言，验证集中的每一个 token 都让模型付出了 3.0 纳特（nats）的惊讶度。

§ V

指数技巧。

交叉熵在数学上很干净——但它用纳特（nats）这个抽象单位来表述。研究者想要一个单位感觉上像你能看到的东西的数字。所以他们做了指数化。结果就是困惑度。

这就是那个动作。我们有一个平均对数概率。如果对它做指数化，就回到了概率。而这个概率的倒数有一个优美的解释：模型正在犹豫的等可能选择的有效数量。

困惑度 = exp(L) = exp(− 1N Σ log P(xi | x<i))

要理解为什么，假设模型在一个大小为 k 的词表上完全均匀。每个 token 得到概率 1/k。每个 token 的惊讶度是 log(k)。指数化后你就回到了 k。所以一个在 k 个 token 之间完全瞎猜的模型，其困惑度为 k。困惑度就是那个隐含的「猜测池」的大小。

同一个数字，三种说法

困惑度、交叉熵和平均对数概率携带的是同一个信息；它们只是说着不同的方言。

平均对数概率：
ℓ = (1/N) Σ log P(xi|x<i)
交叉熵（损失）：
L = −ℓ
困惑度：
PPL = exp(L) = exp(−ℓ)

如果你训练一个模型，看着它的损失从 4.0 降到 3.0，你就刚刚看着它的困惑度从 e⁴ ≈ 54.6 降到了 e³ ≈ 20.1。模型的有效「猜测池」几乎减半了。

3.0 的损失听起来很抽象。20 的困惑度听起来像个具体的东西。这正是这个单位存在的全部理由。
§ VI

困惑度：一个有灵魂的数字。

现在这个公式无处可藏了。每一个符号都有意义。让我们从左到右读它，感受每一个部分。

一个等价且同样优美的形式

把那个公式拿来做代数展开：

PPL = exp(− 1N Σ log Pi) = (P1 · P2 · ⋯ · PN)−1/N

大声读出来：困惑度是模型给实际 token 的概率的几何平均数的倒数。几何平均数会惩罚离群值——哪怕只是一个接近零的概率，也会把整个乘积拖垮。这正是为什么一个自信地猜错的预测就能毁掉一个模型的困惑度分数。

用几何平均数而不是算术平均数：概率是相乘的，所以对它们的贡献取平均也必须是相乘的。对数让我们能够相加；指数化再把它撤销。

§ VIII

这个数字能说明什么——以及不能说明什么。

困惑度是被引用最多的语言模型指标之一，也是被误用最多的指标之一。这里是对何时该信任它、何时该另寻他法的清醒看法。

1完美的预言机（始终 P=1）
≈ 30维基百科上的强 LLM
≈ 50K未训练的模型 · 词表大小
∞模型对任何真相给出 P=0

困惑度做对了什么

困惑度是回答一个具体问题的正确指标：这个模型对这个分布的文本压缩得有多好？更低的困惑度字面意义上意味着，在模型的分布下，编码语料所需的每 token 比特数更少。这就是为什么困惑度是训练目标的黄金标准，也是一个优美而有原则的缩放定律（scaling law）指标。

困惑度做错了什么

分词器毁掉了比较。

一个使用更细分词器的模型，在其它条件相同的情况下，会有更高的逐 token 困惑度——它把同样的惊讶度分摊到了更多的 token 上。跨不同分词器比较时，始终要用每字符比特数或每字节比特数，而不是原始困惑度。

它只衡量局部的流畅度。

困惑度是对单 token 预测取平均。一个模型可以有极好的困惑度，却仍然会幻觉出事实、在段落之间自相矛盾，或者在任何需要推理的任务上失败。困惑度给「词」打分，而不是给「思想」打分。

它对测试语料很敏感。

在维基百科上、在 Reddit 上、在 Python 代码上、在诗歌上的困惑度是四个不同的数字。一个按维基百科困惑度「更好」的模型，按代码困惑度可能更差。始终要注明语料。

它忽略了真相之外的校准。

困惑度只关注实际出现的那个 token 的概率。一个模型可能给「mat」99%、给「banana」1%，也可能给「mat」99%、给「floor」1%——困惑度相同，合理性却大不相同。

· · ·

把一切串起来

困惑度——终于——是我们一开始那个问题的答案：你的模型有多惊讶？它把模型在你打分过的每一句话的每一个 token 上犹豫的「猜测池」的平均大小，压缩进了一个数字。

越低越好。困惑度为 1 意味着完美的预测。困惑度为 |V| 意味着完全的茫然。介于两者之间的每一个值，都是你的模型内化了多少语言结构的度量。

一个模型的困惑度，是它仍然身处黑暗之中的那个房间的大小。

现在再最后读一遍这个公式。每一个符号都应该显得不可避免。

PPL = exp(− 1N Σ log P(xi | x<i))
