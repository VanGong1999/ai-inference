§ I

一张 Roofline 模型图，与第一次推理。

每一个推理工作负载都位于 Roofline 模型图上的某个位置。它位于哪里，是关于它最重要的一件事。

Roofline 模型是一张简单的图。横轴是算术强度 —— 内核每读取一字节内存所执行的 FLOPs 数。纵轴是达到的性能，以每秒 FLOPs 计。这张图有两条上限：右侧一条平坦的天花板（峰值算力），左侧一条倾斜的天花板（峰值内存带宽）。它们交汇之处是脊点。脊点之左，内核受限于内存；脊点之右，则受限于算力。

为什么解码会落在这么靠左的位置？因为它是自回归的。生成一个新 token，需要把模型的参数读一遍，用单个 token 的激活与之相乘，再写出一个新 token。读入的字节很多，用它们完成的 FLOPs 却很少。算术强度微乎其微。

预填充恰恰相反。整个 prompt 被一次性处理，因此同一组参数在多个 token 间被反复复用。每字节的 FLOPs 很多，这个点落在脊点附近。

这种不对称正是推理之所以困难的根源。训练看起来像预填充：大规模并行，点贴近脊点，GPU 很满足。推理看起来像解码：一股细弱的工作流，GPU 处于饥饿状态。从这里往后的每一章，都是让解码在 roofline 图上看起来更像预填充的一种方法。

Roofline 模型出自 Williams、Waterman 与 Patterson（2009）。它最初讲的是经典科学计算内核。结果它却比我们此后发明的几乎任何模型都更干净利落地描述了 LLM 推理。

§ II

KV 缓存，拯救者。

朴素的自回归解码做了大量重复工作。KV 缓存的意义在于：你其实可以不做这些重复。

没有缓存时，生成 token t 需要为所有先前的 token 重新计算键和值 —— t-1, t-2, … 1 中的每一个 —— 尽管这些 K 和 V 向量自上一步以来根本没有变化。在长度为 N 的序列上，总工作量为 O(N²) 次矩阵乘法，其中大部分是冗余的。

缓存是显然的修复。每计算一个新 token 的 K 和 V，就存下来。在第 t 步，只需计算一个新 token 的 K 和 V，其余都从缓存读取。每步的工作量从 O(N) 降到 O(1)，整个序列的总工作量从 O(N²) 降到 O(N)。

朴素总量  ∝  N² · d² · L    →    缓存总量  ∝  N · d² · L

在 roofline 图上，缓存把解码那个点向脊点实实在在地推进了一步。每个 token 的 FLOPs 更少了，同时读入的字节也少了很多 —— 我们不再重读所有过去的 token，只读那一小片 KV 缓存。净结果：算术强度攀升，那个点抬升。

KV 缓存是 GPU 不再挨饿的第一章，也是它变得幽闭恐惧的那一章。
§ III

同一个英雄，新的反派。

KV 缓存解决了一个问题，又制造了另一个。速度上来了，但现在内存会随着每个活跃会话中的每个 token 线性增长。

每个 token 的缓存大小正如书中第 7 章所推导：

每个 token 的缓存字节数  =  4 · H · D · L

K 两个字节、V 两个字节（FP16），乘以 H 个头、D 维头维度、L 层。代入 Llama-3-70B 式的数字 —— H = 64，D = 128，L = 80 —— 你会得到 每个 token 约 2.6 MB。在 32K token 的上下文下：每个用户约 84 GB。一张 H100 总共才 80 GB。在发生任何计算之前，一个用户就已经把 GPU 塞满了。

在 roofline 图上，缓存又把解码那个点往左拉回。现在每一步都要读更多字节 —— 整个缓存，全部，每一次。算术强度下降。计算很小，字节却很大，这个点再次深陷于带宽斜坡。

现在有两个瓶颈。内存容量（你确实会用光空间）和内存带宽（缓存每步都要读一次，主导了字节预算）。两者是同一个反派换了两身戏服，都是上面那个「每 token 字节数」公式。

缓存公式有四个因子。其中三个由模型架构固定：H、D、L。有趣的是 N —— 每当有人发送更长的 prompt，N 就会增长。这正是长上下文推理如此困难的原因。

§ IV

通过压缩字节来抬高 roofline。

如果字节是问题所在，那么字节就是杠杆。压缩它们，算术强度就会以完全相同的倍数攀升。

解码那个点在 roofline 图上的水平位置是

算术强度  =  FLOPs  /  读取的字节数

FLOPs 大多由模型固定。我们能动的只有分母。把字节砍掉 4 倍，那个点就向右移 4 倍。砍掉 64 倍，那个点就能抵达脊点。

在每 token 缓存公式 4·H·D·L 中，只有两项我们能在架构上动刀。H，即 K/V 头的数量，以及那个把每 token 成本放大为每会话成本的隐式 N 因子。书中把这两种攻击分别称为跨头压缩（第 8 章）与跨 token 压缩（第 9 章）。合在一起，它们是把缓存剪到合适大小的两把剪刀。

§ V

跨头压缩 —— MHA、MQA、GQA、MLA。

第一个杠杆。本节中的每一种变体都保留了全序列上的 softmax 注意力，但每个 token 存储的 K/V 投影更少。

在缓存公式中减小 H 是架构层面的操作。你要么从头预训练一个小 K/V 设计，要么用原始 token 的百分之几对 MHA 检查点做 uptrain。在推理侧，收益是直接的：缓存字节数恰好按你压缩的倍数下降。

MLA 的吸收技巧。

MLA 的优雅之处在于一个代数恒等式。模型不再存储每个头的 K，而是每个 token 存储一个小的隐变量 c_KV ∈ ℝ^R。在解码时，查询 q 对过去键的得分变为

Q · Kᵀ  =  (x · W_Q) · (c_KV · W_UK)ᵀ  =  x · (W_Q · W_UKᵀ) · c_KVᵀ

括号里的乘积是一个常量矩阵，可以在模型加载时一次性预计算并吸收进 W_Q。此后，内核只需用单个融合权重矩阵去乘 x，再点乘缓存的隐变量。完整的逐头 K 在解码时从不被物化。缓存保持小巧；逐头的多样性保持完整。

DeepSeek-V3 在 L = 61 层上使用 R = 512。每 token 缓存：2·512·61 ≈ 62 KB，而等效 MHA 约为 4 MB。约 64 倍压缩，在标准评测上几乎没有可测量的质量损失。

§ VI

跨 token 压缩 —— 滑窗、线性注意力、Mamba。

第二个杠杆。头压缩压缩的是 H，而 token 压缩则是约束 —— 甚至消除 —— 那个让缓存随序列长度增长的 N 因子。

三大家族，按压缩的激进程度排序：

滑窗 —— 一个环形缓冲区。

每个 token 只关注最近的 W 个键。缓存变成一个固定大小为 W 的环形缓冲区；随着新 token 到来，更老的槽位被覆盖。缓存完全不再随 N 增长 —— 它封顶于 4·W·H·D·L 字节，并且永远保持在那里。

线性注意力 —— 一个恒定大小的运行状态。

滑窗保留了 softmax，却丢掉了旧 token。线性注意力则反其道而行 —— 保留所有 token，但丢掉 softmax。诀窍在于结合律：

softmax(QKᵀ) V  (不可重排)   →  φ(Q) · ( φ(K)ᵀ V )  (可重排)

当 softmax 被一个核特征映射 φ 取代后，内积 φ(K)ᵀV 就变成一个与 N 无关的小 D × D 矩阵。过去的 token 被增量式地累加进这个矩阵：

St  =  St−1  +  φ(Kt)ᵀ Vt    (D × D，与 N 无关)

Mamba —— 选择性来救场。

解决上下文瓶颈的办法，是承认模型应当被允许选择记住什么。在线性注意力里，每个输入都以相同的权重折叠进状态。Mamba，这个选择性的状态空间模型，让递推的参数变得输入相关：矩阵 A、B 与时间步 Δ 都是当前 token 的函数。一个被模型判定为重要的 token 会以全部强度「通过」；一个填充词则被抑制。

Mamba 自带一个硬件感知的选择性扫描内核，这一点至关重要 —— 没有它，输入相关的递推在 GPU 上会太慢。这个内核正是 Mamba 在实践中具备竞争力的原因。

§ VII

三个维度。

质量、内存与吞吐并不在同一条线上。我们遇到的每一种变体都是三角形中的一个点，而正确的选择取决于你在乎哪个角。

§ VIII

现实中，模型什么都混用。

没有哪个生产模型只选一种变体就罢手。真实系统把头压缩、token 压缩以及一连串系统级技巧组合在一起。架构是一个栈，而不是一道选择题。

有两点值得注意。第一，每一种架构都同时组合了头选择和 token 选择 —— 它们是两个正交的杠杆。第二，内核这一列是不变的。FlashAttention 是基板。它不是菜单上的一项选择，而是这栋楼的地板。

§ IX

FlashAttention —— 位于一切之下的那一层。

FlashAttention 不是 GQA、MLA 或 Mamba 的竞争对手，它位于所有这些之下。你决定用什么注意力数学，它就计算什么 —— 但计算过程中从不把那块巨大的中间矩阵写进慢速内存。

要理解这个诀窍，先想象 GPU 的内存层级。HBM 又大又慢（H100 上约 3 TB/s，但与算力速度相比每纳秒都很金贵）。片上 SRAM 又小又快（每个流式多处理器约 228 KB，大约快两个数量级）。标准注意力内核会在 HBM 中物化 N × N 的得分矩阵，读回来做 softmax，再读一次去乘 V。这块矩阵就是瓶颈。

「online softmax」技巧让这一切成为可能。朴素 softmax 需要把所有 logits 扫两遍 —— 一遍找最大值以保证数值稳定，一遍做指数与归一化。FlashAttention 把它改写为一个流式归约：每当新的一块键分块到来，运行最大值、运行分母与运行输出都在单趟中更新。数学上与标准 softmax 完全相同，调度却面目全非。

与 MHA 输出相同  ·  分块循环  ·  online softmax  ·  常驻 SRAM
§ X

为什么 N²·d²/M 才是关键结果。

两种内核执行相同的 FLOPs。区别在于它们在 HBM 与芯片之间搬动的字节数。书中第 10 章用一行给出公式 —— 而那一行正是解释一切的那一行。

标准注意力为矩阵乘法做 O(N·d) 的工作，为得分矩阵做 O(N²) 的工作。它的 HBM 流量主要由读写那块 N × N 矩阵主导：

标准 HBM 流量  =  O(N · d + N²)

FlashAttention 从不写出得分矩阵。它的 HBM 流量主要由以 SRAM 大小 M 决定的方式反复读写 Q、K、V 分块所主导：

FlashAttention HBM 流量  =  O( N² · d² / M )

解释：d² 由模型架构固定且很小（典型头为 16K 个浮点数）。M 是 SRAM，在现代 GPU 上每个 SM 有数万个浮点数。 比值 d²/M 舒适地低于 1，FlashAttention 的 HBM 流量最终仍与 N 二次方相关，但系数极小，而标准注意力的流量与 N 二次方相关的系数是 1。在长上下文下，那个小系数就是救你的东西。

FlashAttention 不改变你计算什么，它改变的是中间结果的那些字节究竟会触及哪块内存。
§ XI

今日课程 —— vLLM 内部。

这个故事迄今的每一章都在讲数学与内核。再往上一层就是引擎：那个把所有这些技术拿起来、同时服务众多用户的运行时。

到此为止，你已经有了一个用 GQA 或 MLA 的模型，一个（如果你想要的话）token 压缩方案，以及其下的 FlashAttention 内核。你还没有的，是把 HTTP 请求流转化为 token 流的那个东西 —— 它要处理动态批处理、公平性、前缀共享、页表式的缓存分配，以及每秒几十个决定你的 H100 究竟是 30% 还是 90% 利用率的决策。

这就是推理引擎所做的事。最重要的开源实现就是 vLLM。它是今天这节课的主题。

今日白板

vLLM —— 包裹内核的引擎。

这个运行时把本文中的一切拿起来并提供服务。PagedAttention 把 KV 缓存变成一张操作系统式的页表。连续批处理在迭代边界而非请求边界上调度。前缀缓存分摊重复系统 prompt 的成本。分块预填充在不造成队头阻塞的前提下混排长预填充与短解码工作。

  • PagedAttention
  • 连续批处理
  • 前缀缓存
  • 分块预填充
  • 块池内存
  • 迭代调度

其中每一项在书里都各成一章。每一项都是引擎在回答本文一路悄悄铺垫的某个问题。得益于 MLA 或 GQA，KV 缓存现在很小了 —— 我们该如何在多个用户间分配它？解码那个点离脊点更近了 —— 当预填充在对话中途到来时，我们该如何把它留在那里？内核很快 —— 我们该如何给它投喂而不产生气泡？

这正是我们接下来要去的地方。
