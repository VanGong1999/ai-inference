并不是每一种「注意力加速」都是同一种对象。有些重排了 GPU 的调度，却不动数学。另一些则改变了架构本身——更少的 K/V head、一个窗口化掩码、没有 softmax——而模型必须被（重新）训练才能使用它们。这篇文章会梳理整个家族，并准确地告诉你：要亲自复现每一个变体，需要启动什么。

唯一的检验
attention(Q,K,V)  ≡  attention'(Q,K,V)  ?
如果相同 → 系统技巧（无需重训）。  如果不同 → 架构改变（需要重训）。

这篇走读横跨书中的三个章节。第 8 章压缩的是跨 head的缓存（MHA → MQA → GQA → MLA）。第 9 章压缩的是跨 token的缓存（滑动窗口、线性注意力、SSM、Mamba）。第 10 章是 FlashAttention——对同一数学做系统级的重排。采纳每一种所需的训练成本天差地别，而这正是本页要画的差异。

§ I

两种对象，一个共享的名字。

人们很容易把书中的第 8、9、10 章读成同一层架子上的「注意力变体」。术语掩盖了一条贯穿整个家族的清晰分界线。

你读到的每一种「更快的注意力」技术，都是两种截然不同的对象之一。第一种让算子的输入-输出关系保持不变，只是用不同的方式去计算它。第二种则定义了一个新算子——参数量不同、掩码不同、softmax 不同。第一种在推理时采纳不花任何成本。第二种至少要付出一次微调——而且往往是一次完整的预训练。

把它们都叫作「注意力变体」，就掩盖了这一区别。这篇文章的任务是把它变得清晰到像外科手术一样精确，并告诉你这条线的每一侧需要付出多少成本来复现。

通往同一目的地的更快路线是免费的。通往不同目的地的更快路线，要求你重新教会模型它要去哪里。
§ II

一条轴，三个桶。

把每一个注意力变体钉到一条轴上：给定相同的已训练权重，它是否产生与标准多头注意力相同的输出？

那么，三个桶：

① 系统级（第 10 章）。 在数值精度范围内输出相同。你可以拿一个用 vanilla 注意力训练的检查点，直接用 FlashAttention 或 PagedAttention 跑推理。损失不动。准确率不动。输出的 token 相同。

② 续训（第 8 章——跨 head）。 架构变了——更少的 K/V head，或一个潜在压缩——但模型仍然在整个序列上做 softmax 注意力。你可以通过以原始 token 预算的一小部分继续预训练，廉价地恢复失去的行为。Ainslie 等人（2023）报告 GQA 约为 5%。

③ 完全重训（第 9 章——跨 token）。 掩码、感受野或 softmax 本身变了。模型必须从头学习如何使用新算子。一般来说，没有任何「检查点洗白」的技巧能让你跳过这一步。

本文中的「重新训练」指的是用新算子继续预训练。任务级的微调太短、太下游，无法弥补一个算子层面的改变。

§ III

FlashAttention——同样的数学，更聪明的调度。

这就是第 10 章的一行总结。FlashAttention 是典型的系统级优化：输出与标准注意力逐位相等（在浮点运算顺序的范围内）。它重排的是计算发生在哪里，而不是计算什么。

标准注意力计算一个完整的 N × N 分数矩阵 S = QKᵀ/√d，逐行应用 softmax，再乘以 V。分数矩阵是一个内存大户——对于 32K 的上下文，它是十亿个浮点数，并且驻留在缓慢的 HBM 上。FlashAttention 从不物化它。相反，它把 Q、K、V 切成能装进快速 SRAM 的块，并用一个流式算法增量地计算 softmax。

因为算子是相同的，所以你不需要任何新的梯度步。每一个用 eager attention 训练的 Llama、Mistral、Qwen、GPT 检查点，在推理时都能用 FlashAttention。PyTorch 的 scaled_dot_product_attention 已经在形状允许时自动换入 FlashAttention 2。你改的是一个运行时标志，而不是一个权重。

FA1 / FA2 / FA3 的区别在于，调度有多聪明地在不同 GPU（A100 vs H100）上重叠内存移动与矩阵乘法，但数学契约是相同的。

一个微妙之处：浮点加法是不可结合的。FA 的输出并不是字面意义上与朴素实现逐位相等；它们在舍入范围内数值等价。这对下游任务准确率从来不构成问题。

§ IV

跨 head 压缩——MQA、GQA、MLA。

这就是书中第 8 章的三个架构。本节中的每一个变体都保留整个序列上的 softmax 注意力，但减少了 K/V 的占用。数学现在与 MHA 确实不同了——但改变足够小，可以通过继续预训练廉价地撤销。

在有 H 个 head 的 MHA 中，逐 token 的 KV 缓存是 4·H·D·L 字节。对于 Llama-3-70B，在 H = 64、D = 128、L = 80 时，每个 token 是 2.6 MB，在 32K 上下文下就是 84 GB——完全不切实际。几乎所有现代开源模型首先攻击的都是 H 因子，因为 H 是你在不改变算子结构的前提下，唯一能在架构上缩小的项。

两个后果。第一：参数量下降，所以一个用完整 MHA 训练的模型没有一组等价的权重可以「迁移」到 MQA 里。第二：归纳偏置变了——之前在不同 K 子空间上各司其职的 head，现在开始共享。从 MHA → GQA 做朴素的权重平均能给你一个起步，但在获得更多训练信号之前，模型是退化的。

好消息是这个差距会很快弥合。GQA 论文（Ainslie 等人 2023）发现，约 5% 的原始预训练计算就能恢复几乎全部的 MHA 质量，同时完整保留 GQA 的推理优势。这就是「续训」所在的格子：一次真正的架构改变，但学习新算子的成本只是最初学习语言成本的一小片。

cost(MHA → GQA)   ≈   0.05 · cost(预训练)

Llama-3（所有尺寸，G = 8）、Qwen-2/3（G = 4）、Mistral 和 Command-R 都采用了 GQA。它们要么从头用 GQA 预训练，要么从一个 MHA 的近亲续训而来。

MLA——把 head 压缩做到位。

生产中最精巧的 head 压缩是 DeepSeek-V3 的 多头潜在注意力（Multi-head Latent Attention）。MLA 不是丢掉 K/V head，而是把每个 token 下投影到一个小的潜在向量 c_KV ∈ ℝ^R（通常 R = 512），只缓存潜在量。在注意力时，一个吸收技巧把上投影合并进 W_Q，这样 K 和 V 就永远不会在 kernel 里被重建。每个 head 的多样性得以保留；缓存相对 MHA 缩小约 64 倍，且没有可测量的质量损失。

cache_MLA  =  2 · R · L  每 token 字节数   （对比 MHA 的 4 · H · D · L）

MLA 仍然是架构性的——模型的下/上投影被烘焙进了它的权重——所以你无法在运行时把一个 MHA 检查点迁移进 MLA。但就像 GQA 一样，算子仍然是整个序列上的 softmax 注意力，而且这种转换可以通过继续预训练来恢复。DeepSeek 从头用 MLA 预训练；对于已有检查点，GQA 风格的续训练配方是正确的思路。

§ V

跨 token 压缩——滑动窗口与稀疏。

这是第 9 章的前半部分。head 压缩缩小的是 H 因子，token 压缩攻击的是 N 因子——缓存不再随序列长度线性增长，因为存在模型完全看不到的位置了。

标准注意力是稠密的：每个 query 关注每个在它之前的 key。滑动窗口注意力把每个 query 限制在最后 W 个 key 上，逐 token 缓存变成 4·W·H·D·L——与 N 无关的常数。稀疏注意力（块局部 + 少量全局 token）同样去掉了对 N 的依赖。无论哪种方式，模型正在计算的函数都不再是同一个函数：关于掩码之外 token 的信息都没了。

滑动窗口注意力有一条部分逃逸路线。因为每一层都关注自己的窗口，深层堆叠会建立起更大的有效感受野——大约是 W × L。Mistral-7B（W = 4K，L = 32）通过层叠达到约 128K token 的有效感受野，KV 缓存变成了一个固定大小 W 的环形缓冲区。但 Mistral 是从头用窗口化掩码预训练的。你不能拿一个稠密的 Llama 检查点，打开窗口，然后指望得到好东西——直接注意力严格强于通过层间接的注意力，模型必须学会如何通过接力来路由信息。

稀疏注意力（Longformer、BigBird、DeepSeek 的 NSA）也类似。模型必须学会某些 token 是「全局汇总」token，而块局部注意力对其余部分已经足够。那是一项习得的技能，不是一次免费的调度替换。即便是 Gemma-2/3 的混合模式（每五层是完整注意力），也是从一开始就这样训练的。

一个细微之处：在冻结的主干上、带着小的窗口化扩展做短期微调，可以对某些下游任务有效。但除非你用新掩码继续预训练，否则底层的语言建模能力会退化。

§ VI

线性注意力、SSM 与 Mamba。

第 9 章的后半部分。滑动窗口保留了 softmax，但把感受野封顶在 W。这一族则迈出更激进的一步：完全丢掉 softmax，让整个过去坍缩成一个固定大小的运行状态。

标准 softmax 注意力计算 softmax(QKᵀ)V——逐行的 softmax 迫使 N×N 分数矩阵被物化。线性注意力用一个核特征映射 φ 把它替换为 φ(Q) · (φ(K)ᵀ V)。内积现在是 D×D 而不是 N×N，整个过去由一个恒定大小的运行状态 S = Σ φ(K_t)ᵀ V_t 概括。缓存完全不再随 N 增长。

因为 softmax 是赋予注意力那种尖锐的、依赖 query 的检索行为的东西，移除它并不是一次免费的替换。从头用线性注意力训练的模型可以在许多基准上匹敌稠密 softmax 注意力，但通常在需要精确长程查找的任务上失分（那个众所周知的「大海捞针」）。RetNet、Mamba、RWKV 和类似架构本质上是不同的模型家族，而不是对已有模型的补丁。

一条逃逸路线：线性化。近期工作（例如 Mamba-in-Llama、注意力蒸馏）表明，你可以拿一个 softmax 注意力检查点，换入线性注意力层，然后微调以恢复大部分原始质量。但这里的「微调」意味着对一个 7B 模型需要数百亿 token——远超任何任务微调的成本。

§ VIII

亲自跑一遍对比。

知道结论表是一回事。亲自跑一遍对比——面对面对决、同样的数据、同样的条件——才会把这张表变成你脑子里的一个校准。所以：什么样的模型大小和数据集，大到足以给出真实信号，又小到能装进一个合理的预算？

诚实的回答是：有一个甜点区，大约在 1.25 亿到 4.1 亿参数，用 50–200 亿 token 的 FineWeb-Edu 或 SlimPajama 训练。低于这个，数字太嘈杂，无法把架构选择与种子方差区分开。高于这个，可复现预算就崩了。

160M参数量 · 模型大小
10B每个消融的 token 数
2K上下文长度
~6h在单张 H100 上
~$15云端每个消融

这个规模大致是 Pythia-160M 的足迹。它大到足以显示架构之间有意义的困惑度差距，又小到足以在一天内跑完一个干净的网格。Pythia、GPT-Neo-125M、TinyLlama-1.1B 和 SmolLM-135M 都是合理的起点；nanoGPT 是最容易修改的脚手架。

模型

  • 仅解码器 Transformer，12 层，12 个 head，d_model = 768 → 约 1.6 亿参数。
  • RoPE 位置编码（这样窗口/稀疏变体就能像现代论文测试它们那样表现）。
  • 标准初始化：GPT-2 风格，不用花哨技巧。

数据

  • FineWeb-Edu（10B token 子集）——干净、精心整理的网页文本。
  • 或者把 SlimPajama-627B 采样到 10B，如果你想要更多样化的混合。
  • 使用同一个共享分词器（例如 Llama-2 32K BPE），这样困惑度才可比较。

每个变体的训练预算

  • 10B token · 上下文 2048 · batch 0.5M token · 约 20K 步。
  • AdamW，余弦调度，峰值学习率 6e-4，warmup 1%，权重衰减 0.1。
  • 单张 H100（或 8× A10G）→ 每次运行约 6 小时。每个变体三个种子以控制噪声。

要对比的变体

  • baseline——稠密 MHA + FlashAttention（控制 kernel 速度）。
  • gqa-2、gqa-4、mqa——改变 K/V 组数（第 8 章）。
  • mla-128——潜在秩 128，最便宜的严肃 MLA 测试（第 8 章）。
  • swa-256、swa-1024——两种宽度的滑动窗口（第 9 章）。
  • block-sparse——块局部 + 小型全局 token 集（第 9 章）。
  • linear-elu——用 ELU+1 特征映射的线性注意力（第 9 章）。

评估

  • 在留出的 FineWeb-Edu 分片上验证困惑度（头条数字）。
  • 这个规模下的 HellaSwag、ARC-easy、LAMBADA——它们有噪声，但能追踪真实能力。
  • 在 N = 1, 4, 32 的 batch 和 4K、16K 上下文下测解码吞吐，以暴露系统差距。
  • 每 token 的 KV 缓存内存——MQA/GQA 存在的真正原因。

好的结果长什么样

  • FlashAttention 替换：损失曲线完全相同，真实的墙钟加速。
  • GQA-4 vs MHA：困惑度差距 ≤0.05，KV 缓存缩小 2–4 倍。
  • SWA-1024：这个规模下困惑度小幅受损，长上下文下吞吐大幅提升。
  • 线性注意力：可见的困惑度差距；它的存在就是为了成为一个你可以超越的基线。

如果你只能挑一个配置：1.6 亿参数、100 亿 token 的 FineWeb-Edu、三个种子、一张 H100、每个消融六小时。 这能在一周内给出一个可信的网格，而且正是大多数现代注意力论文在扩展之前做受控消融的区间。关于 GQA、滑动窗口、MLA 和线性注意力的已发表结论，最初都是在这个规模附近验证的。

§ IX

挑选一个变体，看看代价。

一个小交互，让结论表变得可触摸。挑选一个变体，面板会更新，用最简单的语言告诉你，把这个变体放进一个运行中的模型，实际需要什么。

与 MHA 的数学相同吗？
是——在 FP 舍入范围内逐位相等。
改变了什么

GPU 上的调度。kernel 从不物化 N×N 分数矩阵——它把 Q、K、V 切成驻留在 SRAM 中的块，并流式地计算 softmax。

你要做什么

对权重什么都不用做。使用 torch.nn.functional.scaled_dot_product_attention 或 flash-attn 包，然后像以前一样跑推理。

§ X

结语。

把贯穿第 8、9、10 章的那条线磨利，你就得到了那条持久的规则。

FlashAttention（第 10 章）是系统优化的教科书案例：数学相同，调度更聪明，无需重新训练。跨 head 压缩（第 8 章）——MQA、GQA、MLA——是一次架构改变，但是一次宽容的改变；用原始 token 预算的一小片续训就足够了。跨 token 压缩（第 9 章）——滑动窗口、稀疏、线性、SSM、Mamba——是算子层面的改变，要求模型学会以新的方式计算注意力，你欠它们一次预训练。

复现配方——1.6 亿参数、100 亿 FineWeb-Edu token、一张 H100——小到足以让整个网格在一周的云花费内跑完。注意力文献里的大多数已发表结论，都是在被放大之前，恰好在这个规模上验证的。这些架构决策没有任何理由应该让人感到神秘。
