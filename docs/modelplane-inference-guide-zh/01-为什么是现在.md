## 1. 为什么是现在？

在以 AI 为核心的组织中，平台团队正在逐渐转变为推理团队。编码助手不能把源代码发送给第三方，而前沿模型的费用也在逐月增加。支持工具还需要访问托管模型无法触及的内部数据。

组织希望自行运行这些模型，而开放模型如今已经让这件事变得切实可行。

[Hugging Face](https://huggingface.co/models) 上托管着超过两百万个开放模型，其中最优秀的一批已经能够与闭源模型竞争。DeepSeek 于 2025 年 1 月发布了 R1；大约一个月后，它在数学和编程基准测试中达到了 OpenAI o1 的水平。当你自行运行模型时，可以控制延迟、可用性以及数据的去向。在高调用量下，还可能将成本降低约 80%。

这项工作很适合平台工程师。要获得固定水平的 AI 能力，成本大约每年下降 10 倍，其中大部分收益来自模型的服务方式，而不是更好的 GPU。Crossplane 和 Modelplane 背后的公司 Upbound 在这方面亲身验证了这一点：他们使用 Modelplane 运行自己的模型，发现 vLLM 和调度本身能够正常工作；真正耗费时间的是 TLS、身份认证、超时、存储、IAM 和可观测性。

### 可以迁移的技能

推理工程师需要选择模型、将模型部署到合适的 GPU 上、保持服务运行、让它更快更便宜，并在故障发生时响应。这本质上是针对一种新型工作负载的 SRE，许多已有技能都可以直接迁移：

| 你已经掌握的能力 | 在推理领域对应的能力 |
|---|---|
| 调度和节点池 | 使用设备选择器、污点和独占设备进行 GPU 放置 |
| 容量规划 | 计算 GPU 内存：权重、KV 缓存和运行时开销，并在运行时校验 |
| 负载均衡 | 具备缓存感知能力的路由，以及长连接流式传输 |
| 基于 CPU 的自动扩缩容 | 根据队列深度和 KV 缓存使用量扩缩容，并测量以分钟计的冷启动时间 |
| 发布与回滚 | 发布独占 GPU，以及维护模型、硬件和推理引擎构建版本矩阵 |
| SLO 和延迟百分位数 | 首 token 时间、每个输出 token 的耗时和有效吞吐量（goodput） |
| 可观测性 | 引擎指标、真实 GPU 活跃度和推测解码接受率 |
| FinOps | 每百万 token 成本和每个用户会话成本 |
| 身份与访问控制 | 生命周期与 agent 会话一样长的凭证 |

在产品生命周期早期，托管 API 仍然是正确选择。当 API 支出成为实际的成本项目、延迟或可靠性需求超出供应商能力，或者数据不能离开自己的网络时，自托管才开始体现价值。2026 年 8 月，Chris Zeoli 在公开招聘网站上统计到大约 58 个开放的推理相关职位，但这个领域还没有统一的职位名称。
