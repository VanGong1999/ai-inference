FlashAttention 演进

相同的注意力，更好的 GPU 调度。

FlashAttention-1 让注意力具备 IO 感知：不要把 N × N 的注意力矩阵写进 HBM。 FlashAttention-2 保持相同的数学，但把更多相互独立的工作暴露给 GPU， 尤其是在 batch 很小而序列很长的时候。

FA1并行工作主要来自 batch × head。
问题推理常常 batch = 1 且上下文很长。
FA2也把工作拆分到 Q 块上。
GPU 占用率图景 小 batch、长序列
FA1 风格的工作单元 FA2 序列拆分的工作单元 空闲容量
核心思想

FA1 找到了内存技巧，FA2 找到了更多并行工作。

两个版本都计算精确的注意力。它们把 Q、K、V 分块到片上内存，并 使用在线 softmax（online softmax），这样完整注意力矩阵就永远不需要被存储。区别在于 GPU worker 是如何分配的。

O = softmax(QKᵀ / √d) V    // 在 FA1 和 FA2 中结果相同
清晰的教学版本：当 batch × heads 给 GPU 提供了许多相互独立的任务时，FA1 非常出色。 FA2 则通过在单个 head 内沿序列/查询块拆分来增加并行度。
改变了什么？
25-40% 在 FA2 论文里，FA1 在 A100 上达到了理论峰值 FLOPs/s 的大致这个区间。
50-73% FA2 通过改进工作划分，更接近 GEMM 的效率。
相同的数学 提速来自调度、更少的标量运算，以及更少的共享内存流量。
循环顺序

看看到底是谁拥有输出行。

在 FA1 中，一个有用的心智模型是：加载一个 K/V 分块，然后遍历 Q 分块。这能复用 K/V， 但并行工作自然地组织在 batch 和 head 上。在 FA2 的前向传播中，一个 worker 拥有一块 Q 行，并流式遍历所有 K/V 块，因此不同的 Q 块可以同时运行。

重要：这并不是因为 K 块无法并行运行。而是因为把一行查询拆分到多个 K 块上， 会产生部分 softmax 片段，这些片段必须合并之后才能得到最终的输出行。

FlashAttention-1：只有当 B × H 很大时任务才足够

训练通常有很多 batch 和 head，因此 FA1 可以用相互独立的注意力问题填满 GPU。

并行轴：batch × 注意力头
外层循环：K/V 块
内层循环：Q 块，更新部分 softmax/输出

FlashAttention-2：把一个 head 拆分到 Q 块上

即使只有一个 batch 和几个 head，一个长序列也包含许多可以变成独立 GPU 任务的 Q 块。

并行轴：batch × head × Q 块
外层归属：Q 行 / 输出行
内层循环：流式遍历 K/V 块
令人困惑的部分

为什么不让 K0、K1、K2、K3 并行运行？

对于一行查询，注意力是对所有 key 做 softmax。如果四个 worker 各自处理一个不同的 K 块，它们并不会产生四个相互独立的输出。它们产生的是同一输出行的四个部分片段。 这些片段需要一次 max/sum/输出合并。

跨 K 块拆分会产生一个归约问题

同一行 Q 拥有一个最终的输出向量 Oᵢ。每个 K/V 块都为同一个 Oᵢ 做贡献， 而 softmax 归一化把所有 K 块耦合在一起。

跨 Q 块拆分则避免了那次合并

Q 行是相互独立的输出行。Q0 产生 O0。Q1 产生 O1。Q2 产生 O2。 每个 worker 都可以流式遍历所有 K/V 块，并在本地完成自己的行。

K 块并行是可能的，但它需要额外的合并步骤。这种风格出现在专门的长上下文解码 kernel 中， 那里的 Q 长度可能只有一个 token，跨 Q 行拆分没有并行度可言。FA2 干净的前向传播改进 就是跨 Q 块拆分。
小 batch、长上下文

推理暴露了只使用 batch × head 并行度的弱点。

在预填充期间，推理可能会以 batch 大小为 1 处理一个长 prompt。如果 kernel 只能 为每个 head 创建一个任务，GPU 就可能占用不足。FA2 通过拆分序列维度创建更多任务， 这样一个长 prompt 就能占用许多线程块（thread block）。

这是要用视觉展示的关键故事：FA2 并不会减少 N² 的注意力数学。 它给 GPU 提供更多可以同时执行的数学片段。

为什么峰值 FLOPs 更高？

张量核心喜欢大而稳定的矩阵工作。FA2 移除了周围更多的等待。

FA1 已经避免了大量的 HBM 写入。但与 GEMM 相比，它仍然有开销： 标量 softmax 工作、同步，以及 warp 之间的共享内存移动。FA2 改进了 工作划分，让更多时间花在高吞吐的矩阵乘法部分。

1. 更多块 一个长序列可以创建许多独立的 Q 块任务。
2. 更少等待 更高的占用率意味着更多 SM 同时拥有有用的工作。
3. 更好的 warp 拆分 FA2 减少了线程块内通过共享内存的通信。
FA2 提速 = 更好的并行 + 更少的非矩阵乘法 FLOPs + 更少的共享内存流量
训练 vs 推理

FA1 与 FA2 在预训练和推理之间会有所不同吗？

注意力公式并没有改变。改变的是工作负载的形态。 这个形态决定了 FA2 额外的序列并行度是否特别有价值。

预训练

通常有很多 batch 和 head。FA1 已经拥有大量独立的注意力任务，所以它表现良好。FA2 仍然能提高吞吐。

推理预填充

通常 batch 很小，但 prompt 很长。这正是 FA2 的 Q 块序列并行度帮助保持 GPU 忙碌的干净场景。

推理解码

通常 q 长度是 1 个 token，而 K/V 来自缓存。跨 Q 行拆分用处较小；专门的解码 kernel 会把工作拆分到长 K/V 缓存上。

要点

FA2 并不是一个不同的注意力层。它是 FlashAttention 思想的更好 GPU 实现： 完全相同的输出，更好的工作调度。当 batch × heads 单独不足以填满 GPU 时， 它的序列并行度最为重要，这在长上下文推理预填充中很常见。
