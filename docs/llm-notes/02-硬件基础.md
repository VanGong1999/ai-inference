# 第 2 章 · 推理的硬件基础（Hardware Foundations for Inference）

> Efficient LLM Inference — Interview Pocket Notes · 第 2 章

## 2.1 面向推理工程师的 GPU 架构

现代 GPU 采用层级化组织。以一块 NVIDIA H100 SXM5 为例，其顶层包含：

- **132 个流式多处理器（SM，Streaming Multiprocessor）**，每个 SM 含 128 个 CUDA 核心和 4 个第四代 Tensor Core。
- **80 GB HBM3 显存**，带宽约 **3.35 TB/s**。
- **共享内存 / L1 缓存**：每 SM 256 KB，比 HBM 快几个数量级。
- **L2 缓存**：50 MB，所有 SM 共享。
- **NVLink 4.0**：提供 900 GB/s 的双向带宽，用于多 GPU 通信。

内存层级对推理优化至关重要。能在共享内存中完成的运算（比如 FlashAttention 里的融合注意力），可以完全避免往返 HBM 的慢速开销。

## 2.2 Tensor Core 与混合精度

Tensor Core 是专门做矩阵乘法的硬件单元，以小分块（tile，例如 16×16×16）在低精度格式上运算。H100 的第四代 Tensor Core 支持：

| 格式 | 峰值 TFLOP/s | 用途 |
|---|---|---|
| FP64 | 67 | 科学计算 |
| TF32 | 989 | 训练默认 |
| FP16/BF16 | 1,979 | 推理标准 |
| FP8 | 3,958 | 量化推理 |
| INT8 | 3,958 | 量化推理 |

关键洞见：**推理可以比训练用更低的精度**，因为我们只需要保持前向传播的保真度——不需要高精度的梯度累积。这就是为什么 INT8 和 FP8 推理能达到约 2× FP16 理论峰值吞吐。

## 2.3 内存层级与带宽

时刻清楚你的数据「住在」哪里，对推理性能至关重要：

**GPU 内存层级（H100 SXM）**

| 层级 | 容量 | 带宽 | 延迟 |
|---|---|---|---|
| 寄存器（Registers） | 约 256 KB/SM | >20 TB/s | 约 1 周期 |
| 共享内存（L1） | 228 KB/SM | 约 10 TB/s | 约 20 周期 |
| L2 缓存 | 50 MB | 约 12 TB/s | 约 150 周期 |
| HBM3（显存） | 80 GB | 3.35 TB/s | 约 600 周期 |
| NVLink（多 GPU） | — | 900 GB/s | 微秒级 |
| PCIe（CPU–GPU） | — | 64 GB/s | 微秒级 |

FlashAttention 的核心洞见正在于此：标准注意力会在 HBM 中计算完整的注意力矩阵；而通过把运算分块（tiling）使其装进共享内存，我们可以避免绝大部分 HBM 流量，达到接近最优的内存效率。

## 2.4 CPU 与边缘硬件

并非所有推理都发生在数据中心 GPU 上。CPU 推理对延迟敏感应用、本地化部署和成本优化都至关重要：

- **现代推理 CPU** 使用 **AVX-512 VNNI**（Vector Neural Network Instructions，向量神经网络指令）高效执行 INT8 矩阵-向量乘。Intel 第四代 Xeon 可扩展处理器能提供约 **10 TFLOP/s** 的 INT8 吞吐，足以运行小模型。
- **Apple Silicon（M3 Ultra）** 把 CPU 和 GPU 内存统一到一个池中（最高 192 GB），带宽约 **800 GB/s**。这种统一内存架构（unified memory architecture）让它在运行那些否则需要多块独立 GPU 的大模型时表现出色。
- **Qualcomm Hexagon DSP** 和移动 SoC 里的 **NPU** 专为低功耗神经网络推理设计，在毫瓦级功耗预算下就能提供数个 TOPS（每秒万亿次运算）。

## 2.5 新兴硬件趋势

- **Google TPU v5p**：定制矩阵引擎，配合芯片间互连，可组成数千芯片的 Pod 用于大模型推理。
- **Groq LPU**：确定性推理加速器，**没有 DRAM**——所有权重存在片上 SRAM 中，单芯片可达约 **500 token/s**，延迟极低。
- **Cerebras WSE-3**：晶圆级引擎，44 GB 片上 SRAM，对能装下的模型彻底消除了 HBM 瓶颈。
- **光计算（Photonic computing）**：早期技术，用光而非电子做矩阵乘法，有望大幅降低功耗。

## 面试准备 · 模拟问答（Mock Q&A）

### Q2.1 解释 HBM 带宽与 NVLink 带宽的区别。它们各自在什么时候成为瓶颈？

**答**：**HBM（High Bandwidth Memory）** 是单块 GPU 上的片上内存——在 H100 上提供 3.35 TB/s，是单 GPU 推理逐 token 加载权重时的瓶颈。**NVLink** 是同一节点内多块 GPU 之间的高速互连，在 H100 上提供总计 900 GB/s 带宽。NVLink 在**张量并行（tensor-parallel）推理**时成为瓶颈：当把大模型切分到多块 GPU 时，每层的每个注意力头输出都要在 GPU 之间做 all-reduce。如果模型切分到 8 块 GPU，每次 all-reduce 都会消耗 NVLink 带宽。对于超大模型（175B+），NVLink 会限制张量并行的扩展效率。

### Q2.2 为什么 Apple Silicon 峰值 FLOP/s 低于独立 GPU，却能在 LLM 推理上有竞争力？

**答**：Apple Silicon 使用**统一内存架构**，CPU、GPU 和 Neural Engine 共享同一物理内存池——M3 Ultra 上最高 192 GB。这消除了独立 GPU 配置的 PCIe 瓶颈（后者必须跨 64 GB/s 总线拷贝数据）。800 GB/s 的统一内存带宽与独立 GPU 相当；关键的是，一个 70B 模型（FP16 下 140 GB）可以**不经量化**完全装进内存，这在当前任何单块独立 GPU 上都不可能。对于内存带宽受限的 decode 负载，真正相关的指标是「每美元的带宽」，而不是「每美元的 FLOP/s」。

### Q2.3 Tensor Core 的格式（FP16 vs INT8 vs FP8）对推理有什么意义？你何时会选哪个？

**答**：Tensor Core 以特定低精度格式加速矩阵乘法，在 H100 上 INT8/FP8 提供约 2× FP16 的吞吐。我的选择：**FP16/BF16** 用于精度至上、且硬件原生支持的场景——这是安全的基线。**INT8**（通过 GPTQ、AWQ 或 LLM.int8()）非常适合最高 70B 模型的权重量化，多数任务上约 2× 内存缩减、精度损失极小。**FP8**（H100 原生支持）正成为甜点——比 INT8 动态范围更好、有硬件加速、在 TensorRT-LLM 等生产系统中越来越多地被使用。对于 H100 级硬件上的新部署，我会选 FP8。

### Q2.4 你如何给一个 LLM 推理负载做性能剖析（profiling），判断它是算力受限还是内存带宽受限？

**答**：我会用 **NVIDIA Nsight Systems** 看时间线视图（SM 活动、HBM 传输、PCIe 传输），用 **Nsight Compute** 看内核级剖析（实际 FLOP/s vs 峰值、内存吞吐 vs 峰值）。具体地：(1) 测量实际内存带宽占峰值 HBM 带宽的比例；(2) 测量实际 FLOP/s 占峰值 Tensor Core FLOP/s 的比例；(3) 计算关键内核的运算强度（operational intensity）。如果内存带宽接近饱和而 FLOP/s 利用率很低，就是内存受限。我还会扫一遍批大小：如果吞吐随批大小线性扩展，说明在内存受限区；如果趋于平台，说明已到算力饱和。

### Q2.5 描述在 Groq LPU 与 NVIDIA H100 之间部署推理的权衡。

**答**：Groq LPU 优先「确定性的超低延迟」：所有权重存在片上 SRAM，没有 DRAM 延迟，单流吞吐极其稳定地达到约 500 token/s。但 SRAM 昂贵且有限，所以 LPU 每芯片只能服务一定规模以下的模型，扩展到大模型需要很多芯片、成本高。**H100 灵活性大得多**：每 GPU 80 GB HBM、跨多 GPU 几乎可支持任意模型规模、通过 CUDA 可编程、有庞大的优化库生态。我会为「延迟关键、模型规模固定」的应用（比如已知 7B 模型的生产聊天机器人）选 Groq；为灵活性、大模型（70B+）或对绝对延迟不敏感的高吞吐批量推理选 H100。
