# 第 5 章 · 投机解码（Speculative Decoding）

> Efficient LLM Inference — Interview Pocket Notes · 第 5 章

## 5.1 核心洞见：草稿与验证（Draft and Verify）

**投机解码**（Leviathan et al., 2023；Chen et al., 2023）利用了一个根本的不对称性：**验证**一串 token 是否会被大模型生成，可以在单次并行前向传播中完成；而**自回归地生成**这些 token，则需要每 token 一次前向传播。

算法很优雅：

1. 用一个小**草稿模型（draft model）**（3–7B 参数）便宜地自回归生成 `K` 个候选「草稿」token。
2. 对大**目标模型（target model）**对这 `K` 个草稿 token **并行**执行一次前向传播。
3. 用拒绝采样（rejection sampling）把每个草稿 token 与目标模型的分布做对比验证。接受匹配的 token，在出现分歧处拒绝（并带一个修正步骤）。
4. 结果可证明等同于从目标模型分布采样。

期望加速比约为 `(1 − α^(K+1)) / (1 − α)`，其中 `α` 是单 token 接受率。对 `α = 0.8`、`K = 5`，每步期望接受的 token 数约为 3.3，带来理论上约 **3.3×** 的 decode 吞吐提升。

## 5.2 Token 树验证（Token Tree Verification）

基础投机解码只生成单条草稿序列。**基于树的投机解码**生成一棵草稿序列树：在每个位置，草稿模型提出多个候选 token，形成分支树结构。目标模型用**树掩码注意力模式（tree-masked attention）**在单次前向传播中验证所有树分支。这通过同时探索多个备选，大幅提高了高接受率的概率。

## 5.3 Medusa：多头投机解码

**Medusa**（Cai et al., 2024）消除了对独立草稿模型的需求。它在目标模型之上加 `K` 个额外的「Medusa 头」——轻量线性层。每个头 `k` 在单次前向传播中预测 `t + k`（第 k 个未来）token：

```
logits_{t+k} = MedusaHead_k(h_t)
```

其中 `h_t` 是位置 `t` 的最后一个隐藏状态。这让模型能「自我投机」地提出多个未来 token。**Medusa-2** 加入自蒸馏（self-distillation）进一步提升草稿质量，在生成基准上达到 2–3× 加速。

## 5.4 EAGLE：高效自回归生成

**EAGLE**（Li et al., 2024）解决了 Medusa 的一个关键局限：仅从最后一个隐藏状态预测未来 token，会丢失确切的 token 序列信息，限制接受率。EAGLE 改用一个轻量草稿模型，输入**同时包含**隐藏状态和此前生成 token 的特征嵌入，从而能产生准确得多的下一 token 预测。**EAGLE-2** 进一步引入**动态草稿树（dynamic draft tree）**，根据草稿预测的置信度自适应地调整树结构，在编程和推理任务上达到 3–4× 加速。

## 5.5 投机解码何时有用（何时无用）

**有利于投机解码的条件**

- **单流、低延迟服务**：批大小 1 时目标模型利用不足，投机解码摊薄了闲置算力。
- **高接受率**：输出可预测的任务（代码补全、结构化生成、事实问答）有高 `α`，加速大。
- **充足 GPU 显存**：需要同时容纳草稿模型和目标模型。

> **注意**：在高批大小的服务场景中（GPU 已饱和），投机解码**不提供任何吞吐收益**。它是一种**延迟优化**，而非吞吐优化。

## 面试准备 · 模拟问答（Mock Q&A）

### Q5.1 证明投机解码产生的输出与目标模型同分布。

**答**：证明依赖**拒绝采样**。假设草稿模型以概率 `q(x)` 提出 token `x`，目标模型分布为 `p(x)`。我们以概率 `min(1, p(x)/q(x))` 接受草稿 token。若被拒绝，则从残差分布 `p′(x) ∝ max(0, p(x) − q(x))` 采样。任意一步的边际接受概率是 `Σ_x q(x)·min(1, p(x)/q(x)) = Σ_x min(q(x), p(x)) = 1 − TV(p, q)`。最终输出分布是：被接受的 token 服从 `q(x)·min(1, p(x)/q(x))`，修正项确保剩余概率质量匹配 `p(x)`。合并后的分布精确积分到 `p(x)`。

### Q5.2 投机解码中的接受率 `α` 是什么？哪些因素影响它？

**答**：接受率 `α` 是单个草稿 token 被目标模型拒绝采样准则接受的概率。它由草稿模型分布 `q(x)` 与目标模型分布 `p(x)` 的重叠决定：`α = 1 − TV(p, q) = Σ_x min(p(x), q(x))`。**提高 `α` 的因素**：(1) **任务可预测性**：编程和结构化文本的下一个 token 更确定；(2) **草稿-目标对齐**：同族或蒸馏自目标的草稿模型；(3) **温度**：更低的采样温度让两个分布更尖、更容易一致；(4) **更小的投机窗口**：更少的草稿 token（K）降低累积拒绝概率。典型值：代码生成 `α = 0.7–0.9`，开放式聊天 `0.5–0.7`。

### Q5.3 Medusa 与独立草稿模型的方法有何不同？权衡是什么？

**答**：**独立草稿模型**是一个有自己的权重、KV Cache 和前向传播的独立小模型。优点在灵活性：草稿模型可以是任意兼容的小模型，其质量可独立提升。缺点在内存开销（存两个模型）和复杂度（管理两个 KV Cache）。**Medusa** 在目标模型的隐藏状态上叠加轻量线性头，不需要独立模型。它直接使用目标模型更丰富的内部表示。权衡：Medusa 头不如完整草稿模型表达能力好（只看最后一个隐藏状态，不看完整上下文），所以接受率可能更低。Medusa-2 用自蒸馏缓解。Medusa 部署更简单；精心挑选的独立草稿模型质量可以更高。

### Q5.4 在什么场景下你**不**推荐投机解码？

**答**：我不推荐投机解码的场景：(1) **高批量生产服务**：批大小 32+ 时 GPU 算力已饱和，并行验证步骤消耗的算力本可用于服务更多请求，吞吐反而下降。(2) **内存受限环境**：投机解码需要额外内存放草稿模型（独立模型方案）或 Medusa 头。若显存已全部用于 KV Cache 和权重，就不可行。(3) **天然低接受率的任务**：高温、多样词表的开放式创意生成 `α < 0.5`，频繁拒绝、加速甚微。(4) **极短输出**：草稿循环的开销是固定的，1–5 token 的输出没有收益。

### Q5.5 描述 EAGLE 架构，并解释为什么它比基础 Medusa 接受率更高。

**答**：**EAGLE**（Extrapolation Algorithm for Greater Language-model Efficiency）训练一个轻量自回归草稿模型，其输入不只是目标模型的隐藏状态 `h_t`（如 Medusa），还包括最近生成 token 的 **token 嵌入 `e_t`**。这个联合输入 `[h_t; e_t]` 送入单个 Transformer decoder 层，预测下一隐藏状态 `h_{t+1}`，再从中预测未来 token。相比 Medusa 的关键优势是**自回归草稿生成**：EAGLE 能按顺序生成多个草稿 token，每个都以上一个为条件，而不是都从同一个固定隐藏状态预测。这种顺序条件化捕获了 Medusa 并行头错过的 token 间依赖，接受率高出 5–15 个百分点。EAGLE-2 再加入基于置信度的动态树扩展。
