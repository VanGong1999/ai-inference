# 第 14 章 · 推理的未来（The Future of Inference）

> Efficient LLM Inference — Interview Pocket Notes · 第 14 章

## 14.1 基于扩散的语言模型

自回归生成——一次一个 token——不是唯一的范式。**扩散语言模型**（MDLM、Plaid、LLaDA）把扩散过程应用到离散 token 序列上：前向过程逐步 mask token，模型学习去噪（unmask）它们。与自回归模型不同，扩散 LLM 能并行（或半并行）生成所有 token，可能在生成阶段实现高得多的硬件利用率。

挑战：文本扩散模型在质量上尚未匹敌自回归模型，且迭代去噪过程（通常 10–100 个去噪步，每步触碰所有 token）可能比预期更昂贵。不过，LLaDA 等近期模型已大幅缩小差距。

## 14.2 多 Token 预测

Meta 的**多 token 预测**（Gloeckle et al., 2024）用多个输出头训练模型，同时预测接下来的 `k` 个 token，而非一个。推理时，这可类似 Medusa（自我投机解码）地每步生成多个 token，或多个头可用于为下游任务生成更好的内部表示。用 4-token 预测训练的模型，相比标准 next-token 预测，样本效率和表示质量都更好。

## 14.3 神经形态与光计算

**神经形态芯片**（Intel Loihi 2、IBM NorthPole）实现类神经元的脉冲计算，对稀疏激活极其节能——每操作效率比 GPU 深度学习高几个数量级。IBM 的 NorthPole 芯片对稠密神经推理达到 22 TOPS/watt，而 GPU 约 2 TOPS/watt。随着 LLM 架构向稀疏化演进，神经形态硬件可能变得相关。

**光子矩阵乘法器**（Lightmatter、Luminous Computing）用光做矩阵-向量乘，理论上带宽无限、每次乘法能耗近零。光计算处于早期阶段，但可能从根本上改变内存带宽瓶颈——让权重加载几乎免费。

## 14.4 Inference-First 设计哲学

这个领域越来越趋向于**从一开始就把推理放在心上**来设计模型：

- **面向 KV 效率的架构选择**：MQA、GQA、MLA 和 SSM 层减少 KV Cache 占用。
- **激活稀疏性**：用 ReLU 或 top-K 激活函数训练的模型有稀疏激活，可被利用来加速 FFN 计算。
- **深度混合（Mixture of Depths）**（Raposo et al., 2024）：动态计算，token 根据难度attend到更少的层。
- **早退（Early exit）**：对简单 token 在中间层做基于置信度的提前停止。
- **字节级模型**：在字节而非子词 token 上运行，消除分词瓶颈，实现更好的多语言性能。

## 面试准备 · 模拟问答（Mock Q&A）

### Q14.1 扩散语言模型生成文本与自回归模型有何不同？推理含义是什么？

**答**：自回归模型通过一次预测一个 token 生成文本，条件在所有先前 token 上——天然串行、内存带宽受限。**扩散语言模型**同时在整个序列上运作：从目标长度的全 mask 序列开始，用预测「哪些 token 去 mask」的模型，在 `T` 步内迭代去噪（unmask）。关键推理含义：(1) **并行性**：每个去噪步同时触碰所有位置——不像自回归 decode 那样充分用满 Tensor Core；(2) **可控性**：扩散模型天然能填充被 mask 的部分（infilling/editing），无需从头重新生成；(3) **成本结构**：每生成一次要 `T × N` 次 token 预测，而自回归是 `N`——相同输出长度下可能更贵；(4) **长度灵活性**：需要提前知道输出长度（或把它当超参）。当前 LLaDA 等模型用 `T = 64` 到 256 步，蒸馏可降到 4–8 步。

### Q14.2 什么是深度混合（Mixture of Depths）？它如何实现自适应推理算力？

**答**：**深度混合（MoD）**（Raposo et al., 2024）是一个框架，其中并非所有 token 都通过所有 Transformer 层。每层的路由器决定一个 token 是应该由该层的注意力和 FFN 处理，还是直接通过残差连接跳过（跳过该层）。简单/可预测的 token 跳过层，复杂/不确定的 token 获得完整处理。推理时这提供自适应算力：一个简单的事实查询可能只有效使用模型 30% 的层，而复杂推理查询用所有层。这与早退不同（早退在固定层停止生成）：MoD 继续在后续层处理被跳过的 token。训练需要仔细路由——通常每层按 token 做 top-K 选择。对许多 token 分布，MoD 在 50% 的 FLOP 成本下达到与稠密模型相似的困惑度。

### Q14.3 为什么光计算可能从根本上改变 LLM 推理？当前局限是什么？

**答**：光子矩阵乘法用光波的干涉计算点积，速度是光速，每次乘法能耗近零（光子不加热电阻）。对 LLM 推理的理论收益：(1) **带宽墙消失**：光互连单根光纤就能携带每秒太比特，远超 HBM 限制；(2) **能效**：每 FLOP 能耗比 GPU CMOS 低 100–1000×；(3) **延迟**：光速传播消除了电子开关延迟。**当前局限**：(1) **数-光转换**：把权重和激活载入光学形式仍需电子 ADC/DAC，既慢又耗电；(2) **精度**：当前光子系统达到 4–6 bit 等效精度，推理够用但需量化；(3) **可编程性**：重编程光学矩阵元素比在 GPU 上加载新权重慢；(4) **可扩展性**：当前光子芯片只实现小规模（64×64 到 512×512）矩阵乘，远小于 LLM 权重矩阵。截至 2025 年，Lightmatter 的 Passage 芯片是最先进的商用光子推理加速器。

### Q14.4 多 token 预测如何同时提升训练与推理效率？

**答**：多 token 预测用 `k` 个预测头训练模型，每个头多预测一步未来：头 1 预测 `t+1`，头 2 预测 `t+2`，依此类推。所有头共享同一 body 表示。**训练收益**：(1) 每次前向传播更多梯度信号——模型同时优化 `k` 个预测目标；(2) 更好的长程表示——要预测 `t+4`，模型必须捕获超越局部共现的高层模式；(3) Meta 实验表明 3–4 token 预测提升基准表现和编程能力，尤其对更小的模型。**推理收益**：额外的预测头在不增加模型大小的前提下实现自我投机解码：用头 2–k 草拟 token `t+2` 到 `t+k`，再用下一个主前向传播验证。这提供 Medusa 式加速，无需独立草稿模型。接受率中等（每头约 0.7–0.8），编程任务上产生 1.8–2.5× decode 加速。

### Q14.5 描述「inference-first」模型设计哲学。哪些架构选择反映了这一思路？

**答**：inference-first 哲学从「生产部署施加了什么约束？」这个问题出发，反向推导架构决策，而不是训练时最大化基准分数、事后才去优化。反映 inference-first 思维的关键架构选择：(1) **GQA/MQA/MLA**：更少的 KV 头大幅减少 KV Cache 内存，直接支持更大批大小和更长上下文；(2) **SwiGLU FFN**：门控架构允许基于路由分数剪枝 MoE 变体中的整个专家，实现条件计算；(3) **激活稀疏（ReLU 变体）**：稀疏激活模式（Mistral 声称 ReLU 下 89% FFN 稀疏度）能跳过 FFN 计算的大部分；(4) **更小的词表**：更小词表意味着更小的嵌入表和更快的采样；(5) **字节级或字符级分词**：消除分词瓶颈，改善多语言处理；(6) **深度优先于宽度**：更窄更深的模型可能更难训练，但在 GPU 上并行更高效。Phi-3 和 Gemma 体现 inference-first 哲学：刻意小、按「每参数质量」优化，而非绝对基准最大化。
