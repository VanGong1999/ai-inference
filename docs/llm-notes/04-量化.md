# 第 4 章 · 量化（Quantization）

> Efficient LLM Inference — Interview Pocket Notes · 第 4 章

## 4.1 量化为什么重要

一个 70B 模型在 FP32 下需要 280 GB 显存——光装权重就要三块以上 A100 80GB。用 FP16/BF16，降到 140 GB。用 INT8 量化，变成 70 GB（可装进一块 H100，还留得下 KV Cache 的空间）。用 INT4，降到 35 GB，单卡轻松装下。量化不是学术好奇心——它决定了一个模型「能不能被服务」。

## 4.2 数值格式

| 格式 | 位宽 | 范围 | 特点 |
|---|---|---|---|
| FP32 | 32 | ±3.4×10³⁸ | 全精度，训练标准 |
| BF16 | 16 | ±3.4×10³⁸ | 指数范围与 FP32 相同，尾数精度更低 |
| FP16 | 16 | ±65,504 | 常见推理格式；有溢出风险 |
| FP8 E4M3 | 8 | ±448 | H100 原生；用于推理和微调 |
| FP8 E5M2 | 8 | ±57,344 | 范围更大、精度更低 |
| INT8 | 8 | −128 ~ 127 | 广泛支持；比 FP16 省 2× 大小 |
| INT4 | 4 | −8 ~ 7 | 省 4× 大小；需仔细校准 |
| INT2 | 2 | −2 ~ 1 | 极端压缩；质量损失显著 |

## 4.3 训练后量化（Post-Training Quantization, PTQ）方法

### 4.3.1 GPTQ

**GPTQ**（Frantar et al., 2022）是一种逐层二阶 PTQ 方法。它逐行量化权重，并利用逆 Hessian 更新剩余权重，以补偿已量化权重带来的误差：

```
δW = − (w_q − w) / [H⁻¹_F]_qq · [H⁻¹_F]_{:,q}
```

GPTQ 对 ≥30B 参数的模型可实现近无损的 4-bit 权重量化，是许多流行量化工具（AutoGPTQ、ExLlamaV2）的基础。

### 4.3.2 AWQ（激活感知权重量化）

**AWQ**（Lin et al., 2023）观察到并非所有权重同等重要——对应大幅值激活的权重对量化误差更敏感。AWQ 通过在量化前对通道做缩放来保护这些显著权重：

```
Q(W · diag(s)⁻¹) · diag(s) ≈ W
```

这在保持数学等价的同时，缩小了关键通道的有效量化范围。AWQ 在 4-bit 精度上持续优于 GPTQ，广泛用于生产。

### 4.3.3 QuIP# 与 AQLM

**QuIP#**（Tseng et al., 2024）使用**非相干处理（incoherence processing）**——量化前随机旋转权重和激活——把数值分布「摊平」，实现近无损的 2-bit 量化。**AQLM**（Additive Quantization of Language Models，语言模型加性量化）用基于码本（codebook）的方法，把权重向量编码为若干码本条目的和，实现相当于 2-bit 的压缩，质量却更接近 4-bit 方法。

## 4.4 量化感知训练（QAT）

PTQ 方法在小数据集上校准、事后应用量化，限制了精度恢复能力。**QAT** 在微调时把「伪量化算子」放进前向传播：

```
x̂ = round(x / s) · s
```

其中 `s` 是可学习的量化步长。梯度通过**直通估计器（Straight-Through Estimator, STE）**穿过取整运算。QAT 在极端位宽（2–3 bit）下精度高于 PTQ，但需要大量算力预算。

## 4.5 激活量化的挑战

权重量化相对简单（权重是静态的，其分布可以离线分析），而**激活量化**困难得多。激活的动态范围随输入变化，且 LLM 有一个已被充分记录的现象：少数通道（「离群值 outlier」）的激活幅值比典型通道大 **100×**。天真地把激活量化到 INT8，会迫使量化步长去迁就这些离群值，导致所有正常范围的激活坍缩成区区几个不同的值。

解决方案包括：

- **LLM.int8()**（Dettmers 等）：分解矩阵乘法，把离群通道留在 FP16，其余用 INT8。
- **SmoothQuant**：通过逐通道缩放，把量化难度从激活迁移到权重：`Y = (X diag(s)⁻¹) · (diag(s) W)`。
- **FP8 激活**：FP8 比 INT8 更宽的动态范围天然能容纳离群值。

## 面试准备 · 模拟问答（Mock Q&A）

### Q4.1 你需要在 2 块 A100 80GB 上部署一个 70B LLM。你会选什么量化策略，为什么？

**答**：两块 A100 80GB 给我们 160 GB 总显存。70B 模型 FP16 光权重就要 140 GB，只剩 20 GB 给 KV Cache 和激活——太紧张了。我会用 **AWQ 4-bit 量化**，把权重大小降到约 35 GB，留出约 125 GB 给 KV Cache、批量激活和开销。AWQ 4-bit 在通用推理任务上通常能保留原模型 >99% 的基准分数。我也会评估 GPTQ 作为备选。如果部署场景是特定领域的，我会在领域数据上做校准。服务框架上，我会用支持 AWQ 的 vLLM，并在两块 GPU 之间做张量并行。

### Q4.2 解释「仅权重量化」与「权重+激活量化」的区别。各自在什么场景适用？

**答**：**仅权重量化（W4A16、W8A16）**把模型参数量化到 INT4 或 INT8，但运行时激活仍用 FP16。权重在矩阵乘法前反量化回 FP16。这减小了模型大小和加载权重的内存带宽（对 decode 至关重要），但实际 GEMM 计算仍在 FP16 进行。方法：GPTQ、AWQ。**权重+激活量化（W8A8、W4A4）**同时量化权重和激活，让矩阵乘法本身在 INT8 或 INT4 下运行，从 Tensor Core 加速中获得额外算力吞吐。但这需要谨慎处理激活离群值。方法：SmoothQuant、LLM.int8()。对纯内存受限的 decode 负载，W4A16 往往就够；对算力受限的 prefill 或大批量，W8A8 或 FP8 提供额外加速。

### Q4.3 什么是直通估计器（STE）？为什么 QAT 需要它？

**答**：量化中的取整运算（`x̂ = round(x/s) · s`）几乎处处导数为零——它是个阶梯函数。这意味着天真地在量化节点上反向传播会产生零梯度，使学习无法进行。**直通估计器（STE）**（Bengio et al., 2013）在量化范围内把 round 函数的梯度近似为 1（恒等）：`∂x̂/∂x ≈ 1_{|x|≤threshold}`。这在数学上不严谨，但经验上有效——它让梯度在反向传播中「假装取整没发生」地穿过量化运算，使模型能学到「取整友好」的权重值。

### Q4.4 SmoothQuant 如何解决激活离群值问题？它的局限是什么？

**答**：SmoothQuant 观察到激活离群值难量化（动态范围大、少数极端值），而权重容易量化（分布平滑）。关键洞见是可以通过一个数学等价的变换，把量化难度从激活迁移到权重：若 `Y = XW`，则对任意正缩放向量 `s`，有 `Y = (X diag(s)⁻¹) · (diag(s) W)`。通过选取 `sⱼ = max(|X_{:,j}|)^α / max(|W_{j,:}|)^{1−α}`，我们均衡了二者的范围。**局限**：(1) 需要校准数据来估计逐通道激活统计；(2) 最优 `α` 依赖任务；(3) 不能在所有层完全消除离群值；(4) 某些模型（尤其词表或嵌入层很大的）仍表现出量化敏感。

### Q4.5 比较 GPTQ 与 AWQ。生产环境你会用哪个，在什么条件下？

**答**：**GPTQ** 用二阶（Hessian）信息最小化逐层量化误差，顺序更新权重以补偿先前量化的权重。它运行起来计算开销大，但产出的量化模型质量高，尤其对 Hessian 近似更准确的大模型。**AWQ** 更简单更快——它找出激活幅值最高的 1% 权重通道，通过在量化前缩放来保护它们，校准只需前向传播。实践中 AWQ 在 4-bit 精度上多数任务优于 GPTQ，且应用更快。**生产环境我会用 AWQ**，因为速度快、质量好、社区支持广（AutoAWQ）。对于值得在领域数据上仔细校准的专门任务、或使用 ExLlamaV2 高度优化的 GPTQ 内核时，我会考虑 GPTQ。
