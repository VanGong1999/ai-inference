# 第 12 章 · 推理时计算扩展（Inference-Time Compute Scaling）

> Efficient LLM Inference — Interview Pocket Notes · 第 12 章

## 12.1 新的扩展范式

多年来，主导的扩展定律是：更多训练算力 → 更好的模型。Chinchilla 最优训练建议把算力预算平均花在模型规模和训练 token 上。但 2024–2025 年出现了一个互补范式：**推理时计算扩展（inference-time compute scaling）**——在**推理时**花更多算力来提升输出质量。

关键洞见：对许多任务（尤其是推理、数学、编程），一个「想得更久」的小模型，能胜过「立刻回答」的大模型。问题从「我们能训练多大的模型？」转向「推理时我们能负担多少推理（reasoning）？」

## 12.2 思维链及其推理成本

**思维链（Chain-of-Thought, CoT）提示**（Wei et al., 2022）让模型在给出最终答案前产出中间推理步骤。这大幅提升多步推理任务的表现，但有代价：一个只需 10-token 答案的问题，可能需要 500 token 的推理，把推理成本放大 50×。

**推理时计算扩展的问题**：给定固定算力预算，是跑一次大模型更好，还是用更多推理 token 跑小模型更好？

近期结果（Snell et al., 2024，「Scaling LLM Test-Time Compute Optimally」）表明答案取决于问题难度：对难题，小模型多推理往往更高效；对简单题，延长推理的开销是浪费。

## 12.3 过程奖励模型与搜索

**过程奖励模型（Process Reward Model, PRM）**被训练来给中间推理步骤的质量打分，而不只是最终答案。PRM 使搜索成为可能：不是只跟一条推理链，而是生成多条候选推理路径，用 PRM 选出或重排最有希望的那条。

常见搜索策略：

- **Best-of-N**：生成 N 个独立解答，选 PRM 分数最高的（或多数投票）。
- **束搜索（Beam search）**：维护 K 条部分推理路径，每步扩展最有希望的。
- **蒙特卡洛树搜索（MCTS）**：把 PRM 当作树搜索中的价值函数。

`N = 64` 的 Best-of-N 在数学基准（MATH、AIME）上可以匹敌甚至超过大 10× 的模型。

## 12.4 DeepSeek-R1 与 o1 风格架构

OpenAI o1 和 DeepSeek-R1 代表了一种质变：不是提示出 CoT，而是这些模型被**通过强化学习训练去推理**。关键机制：模型在给出最终答案前生成延长的内部独白（「思考」）。这些思考通过 RLHF/GRPO 针对可验证的奖励（如数学答案正确性）训练：

```
L_GRPO = −E_o [ min( πθ(o|q)/πref(o|q) · A_o, clip(·, 1±ε) · A_o ) ] + β D_KL(πθ ∥ πref)
```

结果是模型能在难题上「思考」数千 token，用推理成本换精度。DeepSeek-R1-Zero 表明，这种推理行为可以**仅从纯 RL 中涌现**，无需监督推理轨迹。

## 面试准备 · 模拟问答（Mock Q&A）

### Q12.1 什么是推理时计算扩展？它与训练时计算扩展有何不同？

**答**：**训练时计算扩展**（Kaplan et al., 2020；Hoffmann et al., 2022 — Chinchilla）研究模型能力如何随训练 FLOP 预算增长——更多参数和更多训练 token 产出更好的模型。**推理时计算扩展**是更新的范式：给定一个固定的已训练模型，当我们在**推理时**花更多算力，性能如何扩展？更多推理算力可通过：(1) 生成更多推理 token（思维链）；(2) 生成多个候选解答并选最优（Best-of-N 采样）；(3) 用验证器或奖励模型做树搜索；(4) 迭代精炼（模型自我批评并改进输出）。关键洞见是推理算力可以**替代**训练算力：一个花 64× 更多推理算力的 7B 模型，在某些推理任务上能匹敌 70B 模型。这改变了 AI 部署的经济学：算力预算从一次性训练成本转向按查询的推理成本。

### Q12.2 解释过程奖励模型（PRM）。它与结果奖励模型（ORM）有何不同？

**答**：**结果奖励模型（ORM）**给一个完整解答打单一奖励分数，只基于最终答案是否正确。它无法区分「通过有缺陷的推理得到正确答案」和「通过有效推理得到正确答案」。ORM 无法指导中间步骤的搜索。**过程奖励模型（PRM）**被训练来给每个单独的推理步骤打正确性分数，在整条推理链上提供密集反馈。PRM 需要训练数据中的步骤级标注（收集费时，尽管有自动化方法）。推理时，PRM 使步骤级搜索成为可能：MCTS、束搜索、步骤级重排都能实现。对复杂多步推理（中间路径重要，防止模型「因错误的原因得到正确答案」），PRM 优于 ORM，但训练和应用的成本显著更高。

### Q12.3 什么是 Best-of-N 采样？它何时高效、何时低效？

**答**：Best-of-N（BoN）采样从模型生成 N 个独立候选输出（temperature > 0），用奖励模型或验证器给每个打分，返回最高分的输出。它是最简单的推理时计算扩展方法之一。**高效时**：(1) 有可验证正确答案的任务（数学、编程、形式逻辑），验证器便宜可靠；(2) 生成多样性高时——若所有 N 个样本都一样，BoN 无收益；(3) `N` 小（≤32）且单样本推理成本低时。**低效时**：(1) 没有可靠评估器的开放式任务（创意写作）——主观质量难以自动打分；(2) `N` 很大——许多场景下 BoN 质量按 `O(log N)` 增长（N 个样本期望最大值），收益递减；(3) 模型昂贵时，N 个样本成本是单样本的 N×——同等算力预算下用束搜索或步骤级精炼更好。

### Q12.4 描述 DeepSeek-R1 中使用的 GRPO 训练目标。它与 PPO 有何不同？

**答**：**GRPO（Group Relative Policy Optimization，分组相对策略优化）**是 LLM 微调的 RL 算法，它避免了对独立价值网络（critic）的需求。PPO 用价值网络估计优势函数 A，GRPO 则对同一问题生成的一组输出，相对**组内**计算每个输出的优势：`A_i = (r_i − mean(r)) / std(r)`，其中 `r` 是该组奖励向量。这消除了训练价值函数的需求（省内存省算力），通过组内归一化降低方差，并避免了价值函数估计的不稳定问题。**相比 PPO**：GRPO 更简单（更少超参）、更省内存（无价值网络），但每步更新方差可能更高，因为基线是从当前批估计的。DeepSeek-R1-Zero 表明，仅 GRPO + 简单可验证奖励就能诱导出自我验证、延长思考等复杂推理行为。

### Q12.5 对一个数学辅导应用，你会用更大的基座模型，还是用延长推理算力的小模型？论证你的答案。

**答**：我会选**延长推理算力的小模型**，理由有几点：(1) **数学是可验证的**：正确答案可程序化检查，无需人工评估即可可靠地做 Best-of-N 或 PRM 引导搜索；(2) **推理轨迹有教学价值**：一个展示逐步过程的数学辅导老师，比只给答案的更有用；推理时的 CoT 是特性而非开销；(3) **成本效率**：服务一个 7B R1 风格模型并延长推理，每查询比服务 70B 密集模型更便宜，即便计入额外 token；(4) **可自适应算力预算**：简单题用更少推理 token，难题用更多——提供固定大模型无法提供的算力自适应服务。实际选择会是 7B 或 14B 的微调推理模型（DeepSeek-R1-Distill 或类似），配可配置的推理预算，而非 70B 基线模型。
