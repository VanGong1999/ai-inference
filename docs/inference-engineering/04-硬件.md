# 第 3 章 · 硬件（Hardware）

> Inference Engineering — Philip Kiely · Chapter 3

推理工程依赖**加速器（accelerators）**：为每秒加载 TB 级数据、执行万亿次运算而设计的强大硬件。

推理最常见的加速器类型是 **GPU**，而推理 GPU 的市场领导者是 **NVIDIA**。本书聚焦数据中心内 NVIDIA GPU 的推理工程，但本章 3.4 节覆盖其它数据中心加速器厂商，3.5 节覆盖本地推理。

跨厂商，市场上有三种类型的 GPU：

- **数据中心 GPU（Datacenter GPUs）**：机架式服务器，配备互连的高性能 GPU。例如 NVIDIA B200。
- **工作站 GPU（Workstation GPUs）**：用于专业工作流的独立桌面 GPU。例如 NVIDIA RTX Pro 6000。
- **个人计算 GPU（Personal computing GPUs）**：用于日常使用的独立桌面 GPU。例如 NVIDIA GeForce RTX 5090。

规模化推理使用安装在机架上的数据中心 GPU：冰箱大小的机箱，带标准化的供电、网络和散热。

NVIDIA B200 等数据中心 GPU 提供最高的单卡性能，但更重要的是，它们包含高带宽的 GPU 间互连、以高度标准化的配置安装，并在全球数据中心里以百万计地可用。

我猜你桌子底下没有一块 B200 在跑。如果你有，给我发张照片！相反，数据中心 GPU 上的推理以三种模式之一运行：

- **云（Cloud）**：在他人的数据中心租 GPU，通常是 AWS、GCP 等超大规模云，或 Coreweave、Nebius 等新云（neocloud）。
- **本地（On-premise）**：购买 GPU 并安装在你直接控制的数据中心。
- **物理隔离（Air-gapped）**：GPU 安装在本地，你需要物理接触 GPU 才能运行推理。

大多数推理工程师用云 GPU。大型企业和政府运行本地和物理隔离部署，但基于云的 GPU 提供了快速增长的 AI 产品扩展所需的灵活性和可及性。

即便有这些约束，导航硬件版图也是复杂的。从云提供商之间的差异，到 NVIDIA 自己的命名惯例，选择正确的加速器有许多微妙之处。

## 3.1 GPU 架构（GPU Architecture）

GPU 是吞吐机器。CPU 擅长复杂的串行执行，GPU 则为简单、大规模并行的负载而设计。

具体说，GPU 擅长对数千个独立数据块执行同一个统一运算。鉴于 AI 模型推理是一系列向量和矩阵乘法，GPU 是天然之选。

虽然高度并行计算的原理很简单，GPU 本身却是极其复杂的技术。硬件工程是一个迷人的多学科领域，从芯片供电和散热的物理，到制造每个组件时严苛到不可能的容差。

推理工程师在 GPU 硬件之上一个舒适的抽象层级工作，但要对「盒子内部发生了什么」有强健的心智模型，这对构建高性能系统至关重要。

### 3.1.1 算力（Compute）

如果你熟悉 CPU，你可能听说过核心（core），比如高端游戏电脑里的 8 核 Intel i9 CPU。

在 GPU 中，核心有不同含义。GPU 有**流式多处理器（SM, Streaming Multiprocessors）**，每个 SM 包含多个核心。GPU 中有三种算力：

- **CUDA Core**：对单个数字（标量）运算。
- **Tensor Core**：对向量和矩阵运算。
- **特殊函数单元（SFU, Special Function Unit）**：加速 sin、cos、log 等特定数学运算。

衡量 GPU 推理算力时，以 **Tensor Core 算力**衡量。SFU 对 softmax 至关重要，但 Tensor Core 负责**矩阵乘累加（MMA, Matrix Multiply and Accumulate）**指令，这是推理的基础。

MMA 中的「累加」步骤，指把两个矩阵的乘积加到一个基础矩阵上以产生输出，如图 3.1 所示。

> **图 3.1**：矩阵乘累加（MMA）把矩阵 A 乘矩阵 B，加上矩阵 C，结果存为矩阵 D。

与核心不同，**线程（thread）**的概念在 CPU 和 GPU 之间是相似的。CPU 有几十到几百个线程，GPU 则有数万到数十万个线程，能并发工作、在单个时钟周期内切换任务、并行执行简单指令。

算力以 **FLOPS**（每秒浮点运算次数）衡量，数据中心 GPU 能达到万亿或千万亿 FLOPS（分别为 teraFLOPS 和 petaFLOPS）。然而，当你读规格表时，会看到两种 Tensor Core 算力测量：

- **稠密（Dense）**：张量的每个元素都被用到的原始每秒浮点运算次数。
- **稀疏（Sparse）**：在 2:4 结构化稀疏的张量中（50% 的值是 0），Tensor Core 可以跳过乘 0。

给定精度下，带稀疏的 GPU FLOPS 常常（但不总是）是同一精度稠密运算的两倍。默认推理是稠密的，所以务必看的是**不带稀疏**的 FLOPS。

精度每减半，FLOPS 通常翻倍。一块 16 位数字能做到 1 petaFLOPS 的 GPU，在 8 位数字上能做 2 petaFLOPS。这与推理相关——务必在相同精度下跨 GPU 比较 FLOPS。

算力是 LLM prefill 以及图像和视频生成的瓶颈。如果你带着这些用例之一来选硬件，选 FLOPS 更高的加速器。

### 3.1.2 内存与缓存（Memory and Caches）

GPU 包含称为 **VRAM** 的高速板载内存。就像「G」在 GPU 里代表 graphics（图形），「V」在 VRAM 里代表 video（视频）——呼应这些加速器最初的用途。

如今，VRAM 以 HBM3、HBM3e 或 HBM4 的形式加到 GPU 上，都是高带宽内存的不同世代。GPU 有几十到几百 GB 的 VRAM。

任何芯片（CPU 或 GPU）上都有两种内存：

- **DRAM（Dynamic RAM，动态 RAM）**：通用片外内存，以 GB 计。
- **SRAM（Static RAM，静态 RAM）**：更快、更贵的片上内存，以 KB 或 MB 计。

VRAM 是 DRAM 的一种。GPU 还有以缓存形式存在的片上 SRAM。GPU 有三级缓存：

- **L0**：单个 Tensor Core 的指令缓存。
- **L1**：每个流式多处理器的共享内存。
- **L2**：跨流式多处理器的全局缓存。

一块 H100 GPU 每个流式多处理器有 256 KB 的 L1 缓存，片上总 L2 缓存 50 MB。

**VRAM 带宽**衡量 GPU 核心与 VRAM 之间经内存总线的峰值传输速率。实践中，它决定 VRAM 能以多快把数据送进 GPU 的缓存层级。

> **图 3.2**：GPU 有多个 SM，每个 SM 有多个 Tensor Core。L1 缓存在 SM 内，L2 缓存是共享的。

GPU 上 VRAM 的总量限制了你所能加载的模型大小。VRAM 应容纳模型权重，外加至少 50% 的余量给 KV Cache（长上下文、大批量或视频生成模型需要更多）。

如果没有足够 VRAM 放权重，加载模型会以 OOM（内存不足）错误失败。如果余量不够，推理会变慢或 OOM 崩溃。

内存带宽是中低批大小下 LLM decode 的瓶颈。高端 GPU 有每秒 TB 级的内存带宽。如果你在选 GPU、想每秒生成更多 token，选内存带宽更高的加速器，比如 H200 而非 H100。

## 3.2 GPU 架构世代（GPU Architecture Generations）

硬件迭代周期很慢。从敲定架构设计到出货 GPU，有数年交付周期。

鉴于 AI 行业的速度，这个流片（tapeout）和测试过程意味着：即便是下一代 GPU，也是在 AI 模型能力与今天截然不同的时候设计的。设计一个在市场上有持久力的 GPU 架构，需要预判用例在 GPU 预期生命周期内会如何演进。

多年来，训练 AI 模型是 GPU 的主要用途。现在，随着推理上升为主导用例，最新架构正在引入面向推理的特性。

GPU 名称（如 B200）有两个部分：

- **字母**：表示芯片所用的架构世代。
- **数字**：标识该世代内的具体型号。

例如，H100 直接取代上一代 A100，而 H200 是同一世代内更大的 GPU（它又被 B200 取代）。

编号看起来有些随意，不同世代用不同的数字集，但一般规律是：数字越大，意味着更大、更强、更贵的 GPU。另一方面，架构的字母则非常有意义。

每一到两年，NVIDIA 会发布一个新的 GPU 架构，驱动他们从数据中心到个人电脑的所有产品。每个架构世代既提升算力和内存的基础速度，也引入更高效推理的新特性。

自 1998 年以来，NVIDIA 用杰出科学家的名字命名他们的 GPU 架构。

> **图 3.1**：2017 年至所有已公布未来架构的 NVIDIA GPU 架构名。

虽然 GPU 架构可追溯到几十年前，推理工程师通常在最近三到五代 GPU 内工作。即使对成本敏感的负载，现代架构的效率往往也让它们在大规模流量下更划算，当然，更新架构的性能也更好。

你可能偶尔在低流量或遗留系统中看到 Turing（T4）和 Ampere（A10、A100）GPU，但今天大多数部署用 Lovelace（L4、L40）、Hopper（H100、H200）或 Blackwell（B200、B300）GPU。

Hopper 和 Blackwell 架构提供低精度 Tensor Core、高带宽内存和面向推理的特性，而 Lovelace GPU 用于小模型的低成本推理。即将到来的 Rubin 和 Feynman 架构分别在 2026 年和 2028 年发布时，将承诺更强大的性能。

### 3.2.1 Hopper GPU

| GPU | FP8 算力（稠密） | 内存 | 带宽 |
|---|---|---|---|
| H100 | 1,979 teraFLOPS | 80 GB | 3.35 TB/s |
| H200 | 1,979 teraFLOPS | 141 GB | 4.8 TB/s |

Hopper 架构以海军少将 Grace Hopper 命名，2022 年 3 月随 H100 GPU 首发。

Hopper 引入了对 **FP8** 的支持，一种 8 位精度的浮点数格式。FP8 Tensor Core 比 FP16 Tensor Core 快两倍，搬移 FP8 值只花一半的内存带宽。如 5.1 节所讨论，这不会线性地翻译成两倍性能，但对能跑在 FP8 的负载，这是显著增益。

Hopper 架构在比前几代更多、更快的流式多处理器中加入了第四代 Tensor Core。连同动态编程指令、线程块簇（thread block clusters）和分布式共享内存，Hopper GPU 给 CUDA 工程师提供了更多写高性能内核的工具。

其中一个内核是 **FlashAttention 3**，它提升了 Hopper GPU 上注意力的性能和内存效率。FlashAttention 3 利用了 Hopper 引入的新异步数据传输和执行特性。

H100 和 H200 GPU 是最广泛使用的推理加速器之一，而且理由充分。Hopper 架构足够新、性能好，又足够成熟、有全行业支持和高度优化的内核；H100 和 H200 GPU 大小正适合所有模态的常见负载。

### 3.2.2 Ada Lovelace GPU

| GPU | FP8 算力（稠密） | 内存 | 带宽 |
|---|---|---|---|
| L4 | 242 teraFLOPS | 24 GB | 300 GB/s |
| L40 | 362 teraFLOPS | 48 GB | 864 GB/s |

Ada Lovelace 架构以第一位计算机程序员命名，比 Hopper 晚六个月首发。

这两个架构相似，Lovelace 更像是 Hopper 的对位而非后继。Lovelace 也支持 FP8 推理。

Hopper 聚焦 AI 应用，Lovelace GPU 则更面向图形。**Lovelace GPU 不支持 NVLink 互连**。这是一个重大局限。八块 Hopper 或 Blackwell GPU 的节点用这些高带宽互连做高效并行。Lovelace GPU 只能单独使用，或通过流水线并行等低效并行方法使用。

L4 GPU 是运行文本嵌入、计算机视觉等模态小模型的便宜便捷之选。

但 L40 GPU 通常不是推理的好选择。相同内存占用下，多实例 GPU（3.3.2 节）在 H100 的切片上提供高得多的算力和内存带宽。

### 3.2.3 Blackwell GPU

| GPU | FP8 算力（稠密） | 内存 | 带宽 |
|---|---|---|---|
| B200 | ~5 petaFLOPS | 192 GB | 最高 8 TB/s |
| B300 | ~5 petaFLOPS | 288 GB | 最高 8 TB/s |

Blackwell 架构以数学家 David Blackwell 命名，2024 年 11 月随 B200 GPU 首发，随后是 B300。虽然 B100 确实存在，但不常用于推理。

Hopper 引入了 FP8，Blackwell 则在低精度计算上更进一步，引入 **FP4**（4 位浮点格式），外加一组**微缩放格式（MXFP8、MXFP4、NVFP4）**，在推理中更好地保留质量。5.1 节详解这些格式。

Blackwell 在 Hopper 的异步编程范式上构建，加入了更多张量内存与全局内存之间的加载存储特性。更新的 **FlashAttention 4** 内核，很大程度上依赖异步流水线中的分块加载、计算和写入。

B200 和 B300 是推理的新黄金标准，为大型语言模型和视频生成等吃资源的负载提供最高性能。软件支持、优化内核和 Blackwell GPU 的普遍可用性，都在近几个月陆续上线，标志着推理行业的重要转折。

### 3.2.4 Rubin GPU

Rubin 架构以天文学家 Vera Rubin 命名，将于 2026 年作为 NVIDIA 下一代 GPU 架构发布。

评估新架构时，重要的是保留判断，直到你能跑真实世界的性能基准。新架构推出后，随后的全行业软件支持大约需要一年才能完全饱和。

截至出版时，关于 Rubin 有一些具体细节。Rubin 架构使用 **HBM4**，从驱动前几代 GPU 的 HBM3 和 HBM3e 升级而来。LLM decode 等内存带宽受限的推理任务，将受益于这种更高吞吐的 VRAM。

Rubin 还引入了新的 **CPX**，一块为 LLM prefill 等算力受限任务打造的独立芯片。CPX 将成为 NVIDIA 机架级系统的一部分，用于高吞吐推理。

Rubin 之后，NVIDIA 将在 2028 年发布 Feynman。关于 Feynman 细节甚少，但它很可能支持更大、更强的芯片和更快的内存架构。

### 3.2.5 Grace 与 Vera CPU

NVIDIA 也提供自己的 ARM 架构 CPU，它们与 GPU 集成在 GH200、GB200 等超级芯片（superchips）上。「G」代表「Grace」，即 Grace Hopper（以匹配 Hopper GPU）。

NVIDIA Grace CPU 整体算力性能强劲，但对推理重要的是：它们有**高得多的 CPU 与 GPU 之间的带宽连接**。Grace CPU 用 NVIDIA NVLink Chip to Chip，在 CPU 与 GPU 内存之间实现最高 900 GB/s 的双向带宽。

> **图 3.3**：Grace CPU 到 GPU 的互连带宽高于标准 CPU。

这种 CPU 到 GPU 的互连比 PCIe 或其它 CPU-GPU 之间的标准连接快数倍。

一些推理设置需要把 LoRA 微调权重、先前推理调用的 KV Cache 等重要信息卸载到 CPU 内存（远大于 GPU 内存）。用 Grace CPU，这些信息能快得多地取回。

对 Rubin 架构，Vera CPU（以 Vera Rubin 命名）取代了 Hopper 和 Blackwell 系统上使用的 Grace CPU。

## 3.3 实例（Instances）

云上 GPU 分配的原子单位是**实例（instance）**。实例是一台虚拟机，包括：

- **GPU（device，设备）**：一块或多块用于推理任务的 GPU。
- **CPU（host，主机）**：不在 GPU 上跑的任何任务的通用算力。
- **内存（host memory，主机内存）**：CPU 运算的通用内存（传统 RAM）。
- **存储（Storage）**：加载和存储大文件的磁盘内存。
- **网络（Networking）**：到数据中心、最终到公网的物理网络连接。
- **互连（Interconnect）**：同时运行多块 GPU 所需的物理 GPU 间、节点间连接。

并非所有 GPU、所有实例都生而平等。取决于你的云提供商，实例在算力、内存、存储和互连上各不相同。虽然 NVIDIA 提供自己的参考架构，每个云提供商最终都按自己的偏好构建系统。

甚至 GPU 本身也因实例而异。例如，NVIDIA A100 GPU 有两种形态：PCIe 和 SXM。但 A100 上的大多数推理跑在 SXM GPU 上，因为它的内存带宽比 PCIe 变体高 5%。

配给实例时，关键是要确切理解你拿到的是什么。实例的任何组件——不只是 GPU——都可能成为推理中的瓶颈或故障点。

### 3.3.1 多 GPU 实例（Multi-GPU Instances）

通常，模型太大、单块 GPU 放不下，或者推理工程师想同时用多块 GPU 提升性能。跑 DeepSeek 等大模型、视频生成等吃资源模态，常常需要两块、四块、八块甚至更多 GPU。

GPU 的标准单位是**节点（node）**，包含八块独立 GPU。例如，一个 B200 节点包含八块 B200 GPU。

这些 GPU 通过两个系统连接起来：

- **NVLink**：GPU 之间一对一的通信层，Blackwell 上最高 1800 GB/s、Hopper 上 900 GB/s。
- **NVSwitch**：NVLink 之上的全对全（all-to-all）通信层，用于节点内所有 GPU 之间的协调。

这些高带宽互连，使单个模型的推理能分散到多块 GPU 上，最多到完整的 8-GPU 节点。

但有时一个节点不够。在超过八块 GPU 上运行极其吃资源的推理负载，需要节点之间的高带宽互连。

NVIDIA GPU 节点间互连的标准是 **InfiniBand**。InfiniBand 与以太网等网络技术竞争，2019 年 NVIDIA 收购了制造 InfiniBand 的 Mellanox。

InfiniBand 比 NVLink 慢得多，规格最高每网络接口控制器（NIC）400 Gb/s。但它是市场上最快的节点间互连——以太网每 NIC 最高 100 Gb/s。

> **图 3.4**：NVLink、NVSwitch 和 InfiniBand 协同工作，实现 GPU 到 GPU 的通信。

并非每个云提供商都用 InfiniBand。有些提供自己的互连，有些只在部分 GPU 上有 InfiniBand 而非全部。配给 GPU 时，仔细检查提供的是什么互连、该互连交付什么带宽。

除 InfiniBand 外，NVIDIA 还为超过八块 GPU 的 NVLink 连接提供高端解决方案。他们的 **NVL72 GB200** 系统在一个完整机架系统上组合 72 块 Blackwell GPU 和 36 块 Grace CPU。这些系统为服务全球最大模型、应对密集流量提供海量吞吐。

NVIDIA Vera Rubin NVL 144 CPX 是这个庞大系统的下一代，配更新的 Vera CPU、Rubin GPU，以及新的 Rubin CPX。

处理多 GPU、多节点系统时，要记住相对带宽。当 NVLink 等互连比 InfiniBand 快一个数量级时，它在成为瓶颈前能处理多得多的数据。5.4 和 5.5 节讨论的并行和分离式技术，就是在导航这个拓扑，以跨多 GPU 交付高性能推理。

### 3.3.2 多实例 GPU（Multi-Instance GPUs）

有时推理工程师会遇到相反的问题：GPU 对模型来说太大了。

用 Hopper、Blackwell 等更新的高性能架构，需要 H100、B200 等 GPU，它们的算力和内存分配相对较大。对只有几十亿或更少参数的模型，很难有效利用这些 GPU。即便用大批量，宝贵的 GPU 资源也被浪费了。

与其在小模型上跑更旧、更低性能的 GPU，有一种方法能在更新、更高性能 GPU 的切片上运行这些轻量负载。

**多实例 GPU（MIG, Multi-Instance GPU）**是 A100、H100、H200、B200 等较大 GPU 中的硬件级能力。这些 GPU 最多可切成七块。这些切片 GPU 也获得形成实例所需的 CPU、RAM、存储和其它资源的一部分。

> **图 3.5**：H100 有八个内存切片和七个算力切片，用于组装多实例 GPU 实例。

例如，一个三切片的 H100 MIG 有约 3/7 的可用算力，最多可访问总 VRAM 的一半，即 40 GB。它还包含分配给底层 H100 的约一半 CPU 核心、CPU 内存、存储和网络带宽，以形成一个实例。

软件工程通常以 2 的倍数工作，所以看到七个算力切片可能显得奇怪。算力切片由 GPU 中的流式多处理器组成。GPU 通常没有干净的 2 的倍数 SM 数量，例如，一块 SXM H100 GPU 有 132 个 SM。因此，创建七个等大小的算力切片，剩下的 SM 闲置。

对 Orpheus TTS（一个 3B 参数模型）等小模型，有时用两个 MIG 实例比把整块 GPU 分配给单个实例更高效。

## 3.4 其它数据中心加速器选项

NVIDIA 在 AI 硬件市场的领导地位，使它成为全球最有价值的公司。但它远不是唯一能跑 AI 推理的硬件制造商。

从 Amazon、Google 等同行巨头，到一大批初创公司，竞争者正投入数十亿美元开发和制造 NVIDIA GPU 的替代品。

虽然本书聚焦 NVIDIA GPU 上的推理优化，这里简短列出其它值得注意的运行模型推理的硬件选项。

| 公司 | 阶段 | 旗舰产品 |
|---|---|---|
| AMD | 上市 | MI350 GPU：在 AMD 自有软件栈上规格有竞争力的数据中心 GPU |
| AWS | 上市 | Inferentia 和 Trainium：AWS 上分别专为推理和训练打造的一对芯片 |
| Cerebras | 初创 | WSE-3：晶圆级芯片，极高内存带宽，消除 decode 瓶颈 |
| Etched | 初创 | Sohu：面向 transformer 架构的专用集成电路（ASIC） |
| Furiosa | 初创 | RNGD：为张量收缩运算设计的高能效加速器 |
| Google | 上市 | TPU：Tensor Processing Unit，为推理和训练打造的 AI 专用 ASIC |
| Groq | 初创 | LPU：可组合的语言处理单元，依赖 SRAM 获得高内存带宽 |
| Qualcomm | 上市 | Cloud AI 100 Ultra：由多块高能效移动 GPU 组成的全尺寸 GPU |
| Sambanova | 初创 | RDU：可重构数据流单元，为万亿参数模型提供大内存分配 |

GPU 是相当通用的加速器。每家想从 NVIDIA 手中赢得推理负载的硬件公司，都在押注自己产品能赢的特定优势：

- **内存带宽**：Cerebras、Groq 等初创通过在超高带宽内存上加速 decode，实现高每秒 token 数。
- **能效**：Furiosa、Qualcomm 等公司为更低功耗设计芯片，带来更低的运营成本。
- **平台整合**：Amazon、Google 等企业与它们的云服务平台和专有闭源模型深度整合。

虽然每个加速器选项都有其制胜用例，它们也共享共同挑战：

- **软件**：没有 CUDA，硬件提供商必须为他们的加速器重建整个推理栈。
- **制造**：公司需要组装人类有史以来创造的最复杂物体。
- **分销**：制造芯片后，提供商需要它安装并上线，把容量推向市场。

竞争加速创新。数据中心有更多硬件选项的市场，对每个推理工程师都是好事。随着推理负载变得更有价值，这一领域的竞争只会更加激烈，对数据中心之外的本地推理等选项的探索也会如此。

## 3.5 本地推理（Local Inference）

**本地推理**，又称边缘推理（edge inference）、客户端推理（client-side inference）或端侧推理（on-device inference），指直接在终端用户设备上运行 AI 模型推理，而非在集中式服务器上。

客户端推理相比服务器端推理有四大优势：

- **零网络延迟**：没有通信开销，省下几十甚至几百毫秒。
- **独立性**：不依赖网络连接，不受高服务器流量或宕机影响。
- **更好的隐私**：终端用户的数据从不离开设备。
- **成本**：数据中心 GPU 昂贵，而边缘推理对开发者免费，解锁新商业模式。

本地推理理论上听起来完美。实践中，大多数推理发生在云端是有原因的。本地推理有四个局限其应用的弱点：

- **硬件能力**：即便是高端发烧级台式机，速度和算力也只是数据中心 GPU 的一小部分。
- **散热约束**：本地设备散热不如数据中心，进一步限制速度和算力。
- **碎片化的支持矩阵**：无穷无尽的软硬件组合，使标准化充满挑战。
- **电池寿命**：推理是吃资源的负载，会迅速耗尽笔记本和智能手机的电池。

用本地推理构建时，牢记你的受众很重要。AI 爱好者可能有最新最强的手机和强大的电脑，但普通用户更可能有更旧、组件更弱的设备。

本地推理正从实验转向生产，有跨软硬件的强健生态，以及一个与开源模型世界紧密相连的活跃社区。

### 3.5.1 桌面推理（Desktop Inference）

经典的本地设备是配备一块或两块 NVIDIA 或 AMD 高端消费级 GPU 的工作站或游戏 PC。虽然研究者和爱好者确实用这些配置，他们只占桌面推理市场的一小部分。

越来越多地，**Apple 是桌面推理市场的领导者**。Apple 定制的 M 系列 CPU 和 GPU 从单一统一内存取数，让 GPU 上的推理能访问多得多的内存，尽管速度更慢。

Apple 和 NVIDIA 当前市场上最高端的产品，说明了内存容量与速度之间的权衡。

| 硬件 | NVIDIA RTX 5090 | Apple M3 Ultra |
|---|---|---|
| 内存 | 32 GB | 512 GB |
| 带宽 | 1,792 GB/s | 819 GB/s |
| 成本（整机） | $5,000 | $10,000 |

这一趋势延续到价格更合理的中端硬件。Chromebook 等低端电脑无法运行任何有意义的本地推理。

爱好者主导的开源生态聚焦在台式机和笔记本上运行前沿开源模型。今天，用 Ollama、llama.cpp 等工具，在高端个人硬件上运行激进量化的 100B+ 参数模型是可能的。

混合专家日益流行，也是桌面推理的顺风。这些模型的活跃参数更少，意味着单个用户的单次请求只触及模型总权重的一小部分。

图像生成在个人电脑上也相当流行，尤其是通过 ComfyUI——一个把多个图像模型组件组装成单一流水线的工具。

更小的语言模型和语音等其它模态在中端电脑上也可行，行业正在快速开发 WebLLM 等浏览器推理库和其它跨平台标准，把这些能力从早期采用者带向主流。

### 3.5.2 移动推理（Mobile Inference）

移动设备上的本地推理，代表今天端侧负载的大多数。两大主流操作系统都为开发者提供给应用加边缘推理的工具：

- **Android**：Google 的 AI Edge SDK 和 ML Kit GenAI API，接口 Gemini Nano 和开源的 Gemma 模型。
- **iOS**：Apple 的 Foundation Models 和 Core ML 框架，为跨模态模型提供 API。

移动设备的硬件能力和电池容量极其有限，使推理更具挑战性。即便是高端手机，跑超过一二十亿参数的模型也很吃力。

不过，有些模态很适合手机上的边缘推理。例如，转写和语音合成模型对延迟敏感，有些模型小到能在现代手机上实时运行。翻译等其它离散任务，可由小型微调模型在边缘设备上处理。

和任何其它软件一样，推理的未来不是本地或云端，而是**两者协同工作**，驱动快速无缝的用户体验。小模型和快速查询在终端用户设备上运行，而更吃资源的负载留在云中的数据 GPU 上。
