# 第 0 章 · 推理（Inference）

> Inference Engineering — Philip Kiely · Chapter 0

推理是生成式 AI 模型生命周期中的第二个阶段：

- **训练（Training）**：从数据中学习模型权重的过程。
- **推理（Inference）**：在生成式 AI 模型的生产环境中服务（serving）。

在过去十年的机器学习（ML）浪潮中，数十万数据科学家和 ML 工程师熟悉了 ML 模型的完整生命周期——包括训练和推理。

经典 ML 模型的推理相对直接。在 Baseten 早期，我们用 XGBoost 等工具构建的模型，在轻量 CPU 上、用一个简单的软件栈跑推理。

相比之下，生成式 AI 模型的推理是复杂的。你不可能简单地拿到模型权重、搞几块 GPU，就指望推理在大规模生产中足够快、足够可靠。做好推理需要**三层**：

- **运行时（Runtime）**：优化单个模型在单块 GPU 实例上的性能。
- **基础设施（Infrastructure）**：跨集群、跨区域、跨云扩展，不制造孤岛，同时保持出色的可用性。
- **工具（Tooling）**：为做推理的工程师提供恰当的抽象层级，在控制力与生产力之间取得平衡。

这三层必须协同工作，才能构建一个能在大规模下处理关键任务级推理的系统。

## 运行时层（Runtime）

运行时层负责确保在 GPU 上（或单实例内跨多块 GPU）运行的单个模型，尽可能高性能、高效率地运行。

这一层依赖一个复杂的软件栈：从 CUDA，到 PyTorch，再到 vLLM、SGLang、TensorRT-LLM 等推理引擎。底层优化很重要，FlashAttention 等内核能带来显著的性能收益。

运行时层依赖一系列**模型性能技术**，它们把新研究应用到生成式 AI 模型推理的独特挑战上：

- **批处理（Batching）**：并行处理进来的请求，在逐 token 的基础上把它们交织在一起，以提升吞吐。
- **缓存（Caching）**：在共享前缀的请求之间复用 KV Cache——注意力算法缓存的结果。
- **量化（Quantization）**：降低模型某些部分的精度，以获取更多算力、减少内存负担。
- **投机（Speculation）**：生成并验证草稿 token，让 decode 阶段每次前向传播产出不止一个 token。
- **并行（Parallelism）**：高效利用多块 GPU 加速大模型，而不引入新瓶颈。
- **分离式（Disaggregation）**：把 LLM 推理的两个阶段——prefill 和 decode——分离到可独立扩缩的 worker 上。

这些模型性能技术适用于**所有模态**的模型，而不只是 LLM。视觉语言模型、嵌入模型、自动语音识别、语音合成、图像生成、视频生成等模态扩展了 AI 系统的能力，也需要各自的推理优化。

## 基础设施层（Infrastructure）

光有运行时优化还不够。无论单个模型服务器实例的性能多好，它最终都会收到超出处理能力的流量。

这不是 CUDA 问题，也不是 PyTorch 问题。这是需要在基础设施层解决的**系统问题**。

基础设施问题的性质随每个规模层级而变化。最初，问题是**自动扩缩（autoscaling）**：知道何时添加、移除副本，以及如何快速地做到。

超过某个规模（通常是几百块 GPU）后，基础设施问题由**容量（capacity）**定义。为了获得足够的 GPU，推理工程师开始把负载分散到多个区域、多个云提供商。

这很快就会导致**孤岛（silos）**：一个集群里的模型可能资源饥饿，而其它集群却有闲置容量。基础设施的最终规模层级是一个全球系统，把所有可用资源当作**单一统一的计算池**。

> **图 0.2**：投机等运行时性能优化（此处图示）能改善推理延迟。

精心设计的多云基础设施还能提升可靠性，抵御任何单个区域或云提供商的宕机。对全球应用，把推理跑到离终端用户近的地方，还能改善端到端延迟。

## 工具层（Tooling）

当这些运行时和基础设施能力构建好之后，需要以恰当的抽象层级把它们呈现出来。无论是 Baseten 这样的推理提供商，还是做推理的内部团队，都需要考虑作为完整推理平台中关键的第三层——提供什么样的工具和开发者体验。

开发者体验是主观的。对推理而言，一个极端是**黑盒**：给平台模型权重，拿回一个 API。另一个极端是只提供计算、网络、磁盘等基础构件。

正确的开发者体验在中间某处：推理工程师有足够的控制力来安心地运行关键任务级推理，同时又有足够的抽象来高效地工作。

## 本书结构

《Inference Engineering》呈现了一张在运行时、基础设施、工具三层上驱动推理的技术与技巧的地图。

- **第 1 章「先决条件」**：覆盖推理工程介入之前需要做的产品思维和 AI 工程工作——用例定义、延迟与成本预算、选择并评估要优化和部署的生成式 AI 模型。
- **第 2 章「模型」**：介绍 AI 模型的技术架构——从大语言模型到图像和视频生成模型——并确立推理的瓶颈所在，特别聚焦注意力优化。
- **第 3 章「硬件」**：从现代 GPU 的规格表出发，拆解计算与内存，然后厘清 NVIDIA 数据中心级产品中的架构与 SKU，再简要扫视市场上的其它加速器。
- **第 4 章「软件」**：从 CUDA 到 PyTorch、Transformers、Diffusers 等框架，再到 vLLM、SGLang、TensorRT-LLM 等推理引擎，逐层构建抽象。还介绍了 Dynamo——NVIDIA 最新的大规模分布式模型服务系统。
- **第 5 章「技术」**：讨论从前沿研究改编的关键模型性能优化技术并在生产中应用：量化、投机解码、KV Cache 复用、模型并行、分离式服务。
- **第 6 章「多模态」**：把推理工程扩展到 LLM 之外，覆盖语音和视觉。许多类型的生成式 AI 模型——视觉语言模型、嵌入模型、自动语音识别（ASR）模型、语音合成模型——都改编自 LLM 架构，推理工程师可以用与 LLM 相同的工具和技术来运行它们。图像和视频生成模型则有各自的架构和相应的性能优化技术。
- **第 7 章「生产」**：以一份重要问题清单结束全书——在优化的模型推理服务之上运营基础设施、构建高性能应用时需要解决的问题。
- **附录 A 和 B**：分别给出推理工程术语表和进一步阅读的推荐资源。

和 LLM 一样，书也有知识截止点。本书完成于 2026 年 1 月。虽然细节会变，但书中的原则、概念和基础技术，为你提供了一份能服务多年的推理工程坚实背景。
