# 第 2 章 · 模型（Models）

> Inference Engineering — Philip Kiely · Chapter 2

推理工程是让生成式 AI 模型更快、更便宜、更可靠的实践——同时不牺牲让它们如此有价值的质量。既要提升性能、又要保持质量，都需要对模型「底层如何运作」有很强的直觉。

生成式 AI 模型是庞大复杂神经网络的组合。

神经网络的历史可追溯到 1950 年代，当时第一批用于简单二分类的感知机（perceptron）在硬件上实现。此后几十年，感知机被抛弃、又重新发明，从单层进化到多层感知机，并引入了一个新概念——**反向传播（back-propagation）**，它在层之间引入隐藏状态，以及一种反复调整网络内权重的学习过程。

这些神经网络只有少数几层。2000 年代，研究转向几十层的深度神经网络。2012 年，AlexNet 成为第一个展现出真实世界能力、并证明 GPU 对深度学习有效性的深度神经网络，催生了文本词嵌入模型、图像的生成对抗网络（GAN）等新架构。

但故事真正始于 2017 年，Vaswani 及其同事发表了奠基性论文「Attention Is All You Need」，引入了 **transformer**。transformer 是一种带注意力机制的神经网络，能学习序列各部分之间的关系。

Transformer 是生成式 AI 的基础。Transformer 不只用于 LLM，它驱动着每一种模态的模型——从嵌入、语音到图像和视频生成。

跨模态，基于 transformer 的模型有两种重要风格：

- **自回归 token 生成（Autoregressive token generation）**：从 token 化序列出发，预测最可能的下一个 token。
- **迭代去噪（Iterative denoising）**：从随机噪声出发，通过扩散向最可能的输出精炼。

本章探讨 LLM（自回归 token 生成）和图像生成模型（迭代去噪）的架构细节。

## 2.1 神经网络（Neural Networks）

一代代神经网络研究构成了生成式 AI 的理论基础。

要成为高效的推理工程师，你需要对神经网络的核心概念有基本直觉。本节做高层介绍；附录 B 提供进一步阅读的推荐。

神经网络的基本单元是**节点（node，又称神经元 neuron）**。节点是一小段程序：接受输入、乘以一些权重、加上一些偏置、返回结果。

一组节点组成一层（layer）。层内的节点彼此独立——它们各自计算。节点之间的连接，即神经网络中的「网络」，发生在**层与层之间**，其中一层的节点接收上一层的输出。

LLM 背后的神经网络包含几十到几百层。层有三种类型：

- **输入层（Input layer）**：第一层，接受并处理神经网络的输入。
- **隐藏层（Hidden layers）**：第一层与最后一层之间的每一层，迭代地变换输入以得到输出。
- **输出层（Output layer）**：最后一层，返回网络的预测。

每层产出一个输出，供下一层作为输入读取。对隐藏层，这些输出称为**隐藏状态（hidden states）**。

隐藏状态是神经网络内部数据的一种内部表示（internal representation）。内部表示的一个关键方面是它的**维度（dimensionality）**，即所用向量的实际大小。

> **图 2.1**：多层神经网络有一个输入层、许多隐藏层和一个输出层。

文本输入的内部表示会**提高维度**，把文本块编码成几百或几千个数字的向量以捕获语义。但图像模型的内部表示会把几百万像素**降低维度**到可管理的大小。

有用于创建这些内部表示的神经网络，也有用于使用它们的：

- **编码器（Encoder）**：接受文本或图像等输入，创建包含额外信息和语义含义的内部表示。
- **解码器（Decoder）**：使用内部表示生成文本或图像等输出。

神经网络是可组合的。你可以把多个神经网络组合成一个模型，或顺序使用它们构建流水线。

现代 LLM 是**仅解码器（decoder-only）**的，而仅编码器模型如今相当少见，BERT 家族的老式文本嵌入模型是一个突出例子。

许多其它模态的模型使用编码器-解码器架构。Whisper（一个流行的音频转写开源模型）用编码器处理音频输入、用解码器生成文本 token。

### 2.1.1 线性层与矩阵乘（Linear Layers and Matmul）

神经网络中最基本的运算是**矩阵乘法（matrix multiplication，简称 matmul）**。matmul 接受一个输入向量（一组数字）和一个矩阵（一个数字网格），把向量乘过矩阵，产生一个输出向量。

在神经网络内，**线性层（linear layer）**是 matmul 的最简单形式。给定输入向量，线性层应用一个权重矩阵并加上一个偏置向量：

> **图 2.2**：在 matmul 中，输出向量 y 是输入向量 x 与权重矩阵 W 的乘积，再加偏置向量 b。

任意给定线性层的权重是生成式 AI 模型总权重的一小部分，权重矩阵中的单个值在训练期间被设定。

### 2.1.2 激活函数（Activation Functions）

矩阵乘法是可组合的，即把一个向量乘以两个矩阵，等价于把该向量乘以这两个矩阵的乘积。

> **图 2.3**：表示两个独立层的两个 matmul 方程，因线性组合而坍缩。

这对多层神经网络是个问题，因为一系列线性层（每个都是一次 matmul）会坍缩成单个层，其中所有矩阵相乘在一起。

深度多层神经网络之所以有用，是因为更多层能更有效地使用更多参数，并在隐藏状态中编码更多含义。

神经网络通过用**激活函数**打破线性来分隔层。激活函数是非线性的，以防止可组合的 matmul 把层坍缩；并且是可微或基本可微的，以支持反向传播。

推理中最基本的激活函数之一是 **ReLU**，即「整流线性单元（Rectified Linear Unit）」。ReLU 是个简单函数：如果 X 大于零就返回 X，否则返回零。有几十种激活函数——包括一种因形似 Nike 标志而被称为「Swish」的——但大多数遵循同样的通用模式：把负值映射到零或接近零，同时保持正值不变。

ReLU、SiLU、Swish、SwiGLU 等激活函数运行快、易训练（因为基本可微，至少对大多数值有梯度），并且打破线性以支持多层神经网络。

> **图 2.4**：ReLU 等激活函数用于打破多层神经网络的线性。

## 2.2 LLM 推理机制（LLM Inference Mechanics）

LLM 是自回归 token 生成模型。LLM 基于所有先前的 token，一次生成一个新 token。

这些 token——语言模型的原子单位——是表示文本块的数字。现代 LLM 使用**子词分词（subword tokenization）**，即每个 token 是一个词或一个词的一部分。

> **图 2.5**：子词分词对常见词和标点每个用一 token，但把不常见的词拆成多个 token。

文本转 token、token 转文本不需要任何神经网络。相反，**分词器（tokenizer）**是字符串与其数值 token 表示之间的简单映射。

语言模型的**词表（vocabulary）**是 token 与字符串之间的完整映射。词表和分词器因模型而异，更新的模型采用更高效的分词方案；生成一个输出所需的 token 越少，端到端推理越快。

大多数模型词表有超过 100,000 个 token。在语音合成等其它模态中，模型词表被扩展，让 token 能表示音频波形等其它信息。

推理涉及两到三个 token 序列：

- **输入序列（Input sequence）**：传入 LLM 的 prompt、聊天、上下文、函数等输入。
- **推理序列（Reasoning sequence）**：可选，对推理模型而言，是用于思考的中间输出序列。
- **输出序列（Output sequence）**：LLM 生成的响应。

合起来，这些序列受模型的**上下文窗口（context window）**限制——模型每个请求能处理和生成的总 token 数。请求还可以通过 `max_tokens` 参数进一步限制输出序列长度。

虽然输入序列是单个字符串，但 LLM 被训练来接受多样化的输入，如带角色的多轮聊天序列、工具调用的函数签名，有时还有多模态输入。这些输入需要合并成单一序列。这由**聊天模板（chat template）**处理，它因模型而略有差异，必须在推理引擎中正确实现。

对应用了聊天模板的输入序列做分词，是推理的第零步。然后，推理有两个主要阶段：

- **Prefill**：处理输入序列，为每个输入 token 计算注意力，并把那些值存入 KV Cache。
- **Decode**：通过模型做前向传播，自回归地生成 token。

decode 阶段的每次前向传播必须生成一个 token。这需要几个额外步骤，因为神经网络输出的是向量，而非 token。

LLM decode 所用神经网络的输出层生成一个 **logits 向量**。该向量的长度等于模型词表大小。归一化后，这些 logits 表示词表中每个潜在 token 是正确输出的概率。

> **图 2.6**：一次 decode 为词表中每个 token 生成一个 logit，然后把 logits 归一化成百分比。

输出 token 基于归一化后的概率向量，通过加权随机数生成选出。你可以通过推理参数来微调这个过程：

- **温度（Temperature）**：在归一化前调整 logits 本身。
- **Top-k**：归一化后选出 k 个最可能的 token，然后在它们之间重新归一化。
- **Top-p**：归一化后选出概率之和达到 p 的最小 token 集合。

更低的 temperature、top-k 或 top-p 让 LLM 输出更可预测，因为模型被限制选择高概率 token。把 temperature 设为 0 或 top-k 设为 1，会让 token 选择变为确定性（总是选最高概率 token）。

生成**结构化输出**（输出符合 JSON 等 schema）时，还有 **logit 偏置（logit biasing）**等额外工具进一步引导 LLM 的输出。这些在每次前向传播后应用，支持工具使用等重要 LLM 能力；它们的正确实现对高质量推理至关重要。

这个 logit 生成与 token 选择过程持续进行，直到模型决定生成**停止 token（stop token）**——一个表示输出序列结束的特殊值（除非先撞上上下文窗口或 max tokens 限制）。

这个推理循环的两个关键环节是：prefill 期间生成 KV Cache，以及 decode 期间生成输出 token（更确切地说，是变成 token 的 logit 向量）。这些步骤占用了推理中绝大部分时间和资源，因为它们依赖庞大的神经网络。

### 2.2.1 LLM 架构

Hugging Face（最大的开源模型仓库）上的每个 LLM 都包含一个 `config.json` 文件：几十行内容，详述模型的架构。

模型的**架构（architecture）**是训练过程中关于模型每个组件的性质和形状所做的一系列决策。在单一架构内，可能有：

- **多种尺寸**：不同参数量的模型，如 Llama 8B 和 70B。
- **多种变体**：给定模型的「base」和「instruct」变体共享同一架构。
- **无限微调**：LoRA（Low-Rank Adaptation，低秩适配）等方法改变行为而非架构。

这些架构之所以重要，是因为它们决定运行时和引擎的支持。如果你对某个架构有高度优化的部署，你可以部署同架构的另一个变体，享受同样的性能提升。

模型架构是大多数配置文件的第一行之一。以解析 `Qwen3MoeForCausalLM` 这样的架构名为例：

- **Qwen**：模型家族，即模型的品牌名。
- **3**：家族内架构的主版本号。
- **MoE**：表示混合专家模型（见 2.2.4）。
- **CausalLM**：表示因果语言模型（causal language model）。

**因果语言模型**基于先前的 token 预测序列中的下一个 token；与之相对，**掩码语言模型（masked language model）**则基于左右两侧的 token 填空。今天所有生成式 LLM 都是因果语言模型。

除架构名外，`config.json` 文件还包含关于构成模型底层神经网络的各层的性质和维度、以及推理时穿过它们的向量的信息。

### 2.2.2 Transformer 块（Transformer Blocks）

LLM 的主体是一系列几十到几百个 **transformer 块**。这些块构成一个大型神经网络的核心，包含三类层：

- **嵌入层（Embedding layer）**：神经网络的输入层，接受 token、返回嵌入。
- **Transformer 块（Transformer blocks）**：网络内的隐藏层是 transformer 块，生成预测。
- **输出层（Output layer）**：又称语言建模头（LMHead），把 transformer 块的隐藏状态转换成 logits 向量，词表中每个 token 一个。

在 transformer 块内部，有注意力、前馈神经网络和归一化等子层。

> **图 2.7**：Transformer 块图示，改编自「Attention Is All You Need」（Vaswani et al., 2017）。

前馈神经网络是一个多层感知机。这些线性子层占了 LLM 内可训练权重的**大部分**，注意力子层是第二大的组成部分。归一化、激活函数等其它组件在模型大小里只是舍入误差。

虽然线性子层是权重的最大部分，但对推理而言更复杂的运算是**注意力**。

### 2.2.3 注意力（Attention）

注意力是 transformer 用来把给定 token 与序列中其它 token 关联起来的机制。人类善于解读词与词之间的关系。注意力把同样的能力带给 LLM。

考虑这句话：「I decided to write a book because I thought it would be easy, but it was actually hard.」（我决定写一本书，因为我以为它很容易，但它实际上很难。）注意力表明句中的「it」指的是写书这件事。

注意力的标准形式是**缩放点积注意力（scaled dot-product attention）**，如下式所示。

> **图 2.8**：注意力方程，改编自「FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness」（Dao et al., 2022）。

注意力接受三个输入：

- **Q（queries，查询）**：正在被生成或更新的 token 的嵌入表示。
- **K（keys，键）**：所有先前 token 的表示。
- **V（values，值）**：所有先前 token 已计算出的注意力值。

模型内的注意力子层是**多头（multi-head）**的，每个头是一次注意力运算。如果可视化神经网络的架构，这些头在同一子层上彼此平行。每个头可能负责关注 token 间不同种类的关系，如主谓一致和共指消解。

注意力有两种主要类型：

- **自注意力（Self-attention）**：Q、K、V 都来自同一序列。
- **交叉注意力（Cross-attention）**：Q 来自与 K、V 不同的序列，让 Q 以外部信息为条件。

LLM 使用自注意力（带因果掩码以防向前看序列）；图像生成和多模态模型也使用交叉注意力（例如，正在生成的图像与相关文本 prompt 之间）。

因为注意力寻找当前 token 与序列中每个先前 token 的关系，它是一个关于序列长度的**二次时间**方程。上下文越长，注意力越慢。

实践中，注意力是**线性而非二次**的，多亏了 KV Cache。KV Cache 是注意力实现中的标准组件，为每个先前 token 存储 key-value 对。通过查 KV Cache 而不是每次重新计算，注意力以线性时间运行。

KV Cache 在 LLM prefill 期间构建，在 decode 期间使用和更新，默认存在于 GPU 显存上。存储、访问和复用 KV Cache 是推理工程的一个大主题，详见 5.3 节。

### 2.2.4 混合专家模型（Mixture of Experts Models）

神经网络的**密度（density）**由层之间连接的数量决定。更密的网络保留更多信息，更稀疏的网络运行所需计算和内存更少。

**混合专家（Mixture of Experts, MoE）**是一种给线性层增加稀疏性的架构优化。MoE 模型不是单个巨型矩阵，而是有几百个更小的矩阵（专家），并把每个输入路由到一小部分专家。这称为**激活专家（activating the experts）**。

对一个 MoE 模型如 Qwen3-235B-A22B，模型 2350 亿总参数中，每请求只激活 220 亿参数。由于活跃参数少，MoE 模型对单请求本地推理非常高效。然而，在生产服务器上的批量推理中，不同请求激活不同专家，除非在大规模专家并行中实现稀疏性（见 5.4.2），否则你应当预期几乎全部模型参数在任一时刻都是活跃的。

专家路由是细粒度的。每次前向传播通过模型的每一层，生成一个 token。**路由器（router）**——LLM 内的一个小模型——在模型的每一层挑选激活哪些专家。在 Qwen 的例子中，有 128 个专家，路由器在 94 层中的每一层、为生成的每个 token 挑选 8 个专家。

MoE 架构对 100B+ 参数的大模型尤其流行，不过也有小到 200–300 亿参数的 MoE 模型。混合专家解锁了一种新的推理并行形式，称为**专家并行（Expert Parallelism）**，它让大模型在多 GPU 上实现高吞吐推理。

> **图 2.9**：混合专家架构同时包含分片（sharding）和复制（replicating），以利用多 GPU 推理。

32B 参数以下、尤其是 8B 以下的模型，往往能高效地使用传统密集架构。Tab 补全等任务的领域专用模型也从 MoE 中获益甚微，因为整个模型实际上就是一个专家。

## 2.3 图像生成推理机制（Image Generation Inference Mechanics）

图像生成模型接受文本 prompt，基于 prompt 创建图像。这类模型比 LLM 的公开崛起稍早，Midjourney 的闭源模型和开源的 Stable Diffusion 模型都首发于 2022 年夏天。

图像生成模型不像 LLM 那样是单体模型。相反，它们是**多个模型协同工作的流水线**。在一个图像生成基础模型内，有三个基本组件：

- **文本编码器（Text encoder）**：把文本 prompt 转换成图像生成模型能理解的指令。
- **去噪模型（Denoising model）**：模型的核心，基于 prompt 从噪声迭代到图像。
- **变分自编码器（VAE, Variational Autoencoder）**：把模型输出从潜在空间转换到像素空间。

这种流水线思维贯穿整个图像模型生态。除基础模型外，图像推理通常还包括：

- **LoRA**：轻量微调，改变风格、提升质量。
- **ControlNet**：用轮廓和边缘来引导输出图像匹配大致的形状和颜色。

围绕图像生成模型的庞大而丰富的开源生态，包括 ComfyUI 等工具，用于构建基础模型和适配器的复杂流水线，交换组件以产生独特输出。

整个图像生成流水线都在**潜在空间（latent space）**中运行。一张普通高清图可能是 1024×1024 像素，即超过一百万像素。由于去噪模型需要并行计算整张图像的注意力，在像素空间中工作是不可行的。

潜在空间是图像的低维表示。一张图像的潜在空间矩阵可能是 128×128，约为它所表示的像素空间总值的百分之一。

潜在空间被初始化为随机值，即**噪声**。去噪模型基于文本 prompt，经过一系列步骤把噪声精炼成图像。每步更新整个潜在空间，而不像 LLM 那样一次处理一个 token。大多数图像生成模型需要 **30 到 50 步**才能创建高质量图像。

> **图 2.10**：基于扩散的模型从噪声迭代生成图像，通常 30 到 50 步。

在每一步内，模型跑两次前向传播：一次带条件（文本 prompt），一次不带条件。然后基于**引导尺度（guidance scale）**把两次生成结合起来。由于这种两步式，一个 50 步的图像生成实际上要跑 100 次前向传播。

这个过程以及图像生成的其它基本部分，通过推理参数按请求控制。最重要的参数是：

- **Prompt**：描述图像应该长什么样。
- **负向 prompt（Negative prompt）**：单独描述不应出现在图像中的风格或对象。
- **步数（Number of steps）**：用去噪步数权衡速度与质量，大多数模型 30 到 50 步。
- **引导尺度（Guidance scale）**：控制创造性与 prompt 遵循度之间的平衡，整数，通常约 4。
- **图像尺寸（Image size）**：从固定的分辨率与宽高比菜单中为输出图像选择。

虽然这些核心机制在图像生成模型中是共通的，但它们的架构在过去几年里已大幅演进。

### 2.3.1 图像生成模型架构

图像生成模型构建在 transformer 之上，具体是**扩散 transformer（diffusion transformers）**。扩散 transformer 与 LLM 使用的 transformer 非常相似，但它处理的是图像数据，而非离散 token 的嵌入表示。

扩散 transformer 以**补丁（patches）**来看图像。训练文本转图像模型时，训练数据中的图像以 2×2 或 4×4 像素的重叠补丁送入，然后嵌入潜在空间。推理则方向相反，一旦图像生成完成，就把潜在空间变换回像素。

图像生成模型是多个模型的流水线，包括文本编码器、去噪模型和变分自编码器。这个流水线的一个清晰例子是 **Stable Diffusion XL（SDXL）**。SDXL 是个老模型，但其架构仍有意义。

> **图 2.11**：SDXL 架构流水线，改编自「SDXL: Improving Latent Diffusion Models for High-Resolution Image Synthesis」（Podell et al., 2023）。

SDXL 的流水线包含两个用于去噪的扩散模型：**base** 和 **refiner**。这些模型为不同任务训练：base 模型从纯噪声到连贯图像，refiner 模型添加细节并确保 prompt 遵循度。

现代模型在 prompt 遵循度、准确的脸/手/细节、清晰的文本渲染、以及图生图推理支持上都大幅超越 SDXL。这些模型（如 Qwen Image 家族）与 SDXL 流水线大致相似，但每一步的模型都更大、更强。

| 组件 | SDXL (2023) | Qwen Image (2025) |
|---|---|---|
| 文本编码器 | 基于 CLIP 的模型 | Qwen 2.5 VL (7B) |
| 去噪器 | <4B 参数 | 20B 参数 |
| VAE | 单编码 | 双编码 |

Qwen Image 等现代图像生成模型能力的巨大增长，来自更大的组件模型和更复杂的流水线。清晰的文本渲染、逼真人脸等新能力，来自把微小的 NLP 模型换成完整 LLM 做文本编码，以及把去噪器参数量提升五倍。

这些更大的模型需要更多资源来运行。幸运的是，随着模型变大，GPU 也变强了，不过推理工程师不能只靠硬件增益来高效运行这些模型。

图像生成模型最新的研究方向，是**把扩散 transformer 架构与 LLM 架构融合**。

任何能被 token 化的东西都能被建模为 LLM。LLM 的优势在于内置的文本理解，而且它们已经是图像生成流水线的重要组成部分。

LLM 解决了扩散模型固有的许多问题。扩散模型只能产生固定大小的输出，而 LLM 是自回归的，能产生变长输出；图像模型需要多达 100 次前向传播才能生成图像，而 LLM 在单次前向传播中生成 token。HunyuanImage-3.0 等模型就使用这种 LLM 风格架构。

虽然这是图像生成的新前沿，但还有其它已有架构用于加速图像创建，以及把图像模型扩展到视频生成。

### 2.3.2 少步图像生成模型（Few-Step Image Generation Models）

图像生成最耗时的部分，是那 30 到 50 个去噪步。与其让每步更快，有没有办法通过**干脆用更少的步数**来优化图像模型？

少步图像生成模型就是为此训练的：用 8 个或更少的去噪步创建高分辨率图像。这些模型开箱即用比传统图像生成模型快 80–90%，不过输出质量明显更低。

创建这些模型有两种主要方法：

- **潜在一致性（Latent consistency）**：训练模型直接预测目标潜在图像向量，并重复预测两到四次以提升质量。
- **蒸馏（Distillation）**：用对抗蒸馏和/或渐进蒸馏，训练小模型在更少推理步内模仿大模型。

如今蒸馏比潜在一致性更常见。当 FLUX、Qwen Image 等新图像模型发布时，开源图像社区成员会制作蒸馏版，以及面向质量和风格的 LoRA。

如果你有一个质量不那么重要、但对延迟敏感的场景（如实时生成滤镜），考虑少步图像生成模型。

### 2.3.3 视频生成（Video Generation）

视频生成模型在架构上与图像生成模型相似，只是更大。它们的参数量多三到五倍，在潜在空间中编码的信息多十到一百倍。

视频生成的天真做法是逐帧处理。早期视频生成用这种逐帧方式：先生成起始帧，再用该帧生成下一帧，以此类推。

逐帧方式的问题是**误差累积**。早期的小问题随每一帧复合，视频很快跑偏。

相反，现代视频模型把整个视频放在潜在空间中，在每次去噪步修改它。每一帧都关注其它每一帧，并在每次前向传播中被更新。

如果说图像模型的潜在空间表示 X 和 Y 两个物理维度，那么视频模型的潜在空间表示三个维度：X、Y 和 T（时间）。

这种方法的主要局限是：视频是固定帧数，就像图像生成模型有固定宽高比一样。现代视频生成模型创建几秒钟的序列。

视频长度的约束是计算资源。即使有最新的 GPU，对超大潜在空间做注意力也极其昂贵，每秒视频需要数秒推理。视频生成模型计算密集到通常以**批大小 1**运行，意味着一个八块 GPU 的完整节点在服务单个请求。

虽然每次去噪步的注意力很昂贵，视频生成模型的总步数与图像模型相同，通常约 50 步。

与 LLM 和图像生成相比，视频生成是较新的模态。它们的局限与两年前 LLM 的局限一致。

| LLM（2023 年末） | 视频生成模型（2025 年末） |
|---|---|
| 高 TTFT、低 TPS | 生成时间长 |
| 频繁幻觉 | 物理不真实 |
| Ampere GPU 被打满 | Blackwell GPU 被打满 |
| 上下文窗口受限 | 视频输出短 |

今天，这些局限大多已在 LLM 中消除。从电影级视频生成、以及世界模型、3D 对象生成（XYZ 维度而非 XYT）、其它生成式 AI 渲染等相关领域中消除这些局限，是一个高度活跃的研究方向。

研究的一个重要方向又绕回了自回归生成的想法，比如把 LLM 架构融合进图像生成模型。与其用误差累积到不可用的纯逐帧视频生成，Self Forcing 等新技术结合了全局质量视角与迭代生成方法。

给视频模型加入自回归组件可以部分缓解注意力瓶颈，尽管注意力仍是推理中最重要、最昂贵的组成部分。

## 2.4 计算推理瓶颈（Calculating Inference Bottlenecks）

在一个完美优化的系统中，每种资源始终被充分利用。GPU 有两种主要资源：

- **算力（Compute）**：GPU 每秒能完成的浮点运算次数。
- **内存带宽（Memory bandwidth）**：GPU 每秒能移动的字节数。

理想情况下，算力从不闲置等待内存信息，内存带宽也从不停摆等待算力完成。

在真实世界中，系统有**瓶颈（bottlenecks）**：一种资源闲置、另一种资源饱和的不平衡。发现这些瓶颈是提升性能的第一步。如果某个运算受内存带宽瓶颈制约，再多算力优化也不会让系统更快，反之亦然。

大多数情况下，推理系统有如下瓶颈：

- **LLM prefill（KV Cache 构建）是算力受限（compute bound）的。**
- **LLM decode（token 生成）是内存受限（memory bound）的。**
- **图像和视频生成是算力受限的。**

在优化每个阶段时，目标是让瓶颈对全系统性能的限制更小。例如，把多个请求批量在一起，能让 LLM decode 变得不那么内存受限，因为处理一批请求在相同内存流量下用了更多算力。

### 2.4.1 Ops:Byte 比与算术强度

每块 GPU 有特定的算力速度（以每秒运算次数衡量）和内存带宽（以 GB/s 或 TB/s 衡量）。对比二者，得到给定 GPU 的 **ops:byte 比**。

例如，一块 H100 GPU 在 FP16 下能执行 989 teraFLOPS 的密集计算，对应 3.35 TB/s 的内存带宽。这产生约 **295** 的 ops:byte 比。

要在 H100 上让 FP16 推理达到完美平衡（如其所应然），推理系统每访问一个字节内存，就需要执行 295 次浮点运算。

要算出这个比例，计算算法的**算术强度（arithmetic intensity）**。算术强度又称运算强度（operational intensity），是手头计算的「工作量」与「内存流量」之比。

> **图 2.12**：算术强度的方程。

ops:byte 在「每秒」尺度上衡量，而算术强度在单个函数或算法的执行过程中衡量。

算术强度用 **roofline 模型**可视化，它把性能画在带宽上限（一条对角线）和性能上限（一条水平线）之上。

> **图 2.13**：roofline 图显示基于算术强度，从内存瓶颈到算力瓶颈的切换。

对照 roofline 模型画图，可以揭示算法是：

- **算力受限**：当算术强度高于硬件的 ops:byte 比、撞上水平性能上限时，是算力受限。
- **内存受限**：当算术强度低于硬件的 ops:byte 比、撞上对角线带宽上限时，是内存受限。

要找到瓶颈，看系统中最昂贵计算的算术强度。对推理而言，其中一个这样的计算是注意力。

### 2.4.2 LLM 推理瓶颈

LLM 推理有两个阶段：

- **Prefill**：决定首 token 时间（TTFT），是算力受限的。
- **Decode**：决定每秒 token 数（TPS），是内存受限的。

对每个阶段，你可以通过比较最重要运算的算术强度与可用硬件的 ops:byte 比，来证明瓶颈的存在。

在 prefill 和 decode 中，最昂贵的运算都是**注意力**。注意力的精确算术强度取决于模型架构（维度、头数等）、输入序列长度，以及注意力算法的实现。

本质区别在于：prefill 并行处理整个输入序列，而 decode 一次生成一个 token。

对 prefill，模型权重只加载一次，然后在输入矩阵与注意力矩阵之间发生一系列大矩阵乘法。这是「大量计算对应一次内存读取」，产生高算术强度。

对 decode，每个 token 都要加载模型权重，而 token 是通过便宜得多的向量-矩阵乘法生成的。这时，相对加载整个模型权重，所需的浮点运算很少，所以算术强度低。

作为计算精确算术强度的例子，考虑一个注意力头维度 128（d=128）、序列长 4096 token（N=4096）的模型的 decode 步。这个分析用标准注意力算法，不做任何优化。

> **图 2.14**：标准注意力实现，改编自「FlashAttention」（Dao et al., 2022）。

基于本练习的参数，确立这些矩阵的大小：

- **N**：序列长度，定为 4096。
- **d**：注意力头维度，设为 128。
- **Q、K、V**：给定为 N×d，即 4096×128。
- **S、P**：计算为 N×N，即 4096×4096。
- **O**：计算为 N×d，即 4096×128。

假设 FP16 推理，矩阵中每个值是两字节。供参考：一个 4096×4096 矩阵约 32 MiB，约等于一张高分辨率 RAW 单反照片的数据量。

注意力算法的三行都遵循同一模式：从内存加载数据、执行计算、把结果存回内存。

这样计算算术强度是学术练习，不是推理工程师的日常任务。但看一次有助于建立直觉。

### 2.4.3 图像生成推理瓶颈

图像和视频模型相对较小——参数量是前沿语言模型的十分之一——但它们的注意力机制计算量同样大。

图像和视频生成模型使用迭代去噪，而非自回归 token 生成。

就像 LLM prefill 的注意力一次处理整个输入序列，生成媒体的注意力必须考虑潜在空间中表示的整个图像或视频对象。

也像 LLM prefill 一样，图像和视频生成模型推理受**算力**瓶颈制约。优化这些模态推理的特定技术见 6.5 和 6.6 节。

## 2.5 优化注意力（Optimizing Attention）

对 LLM，注意力随输入序列长度呈二次扩展。每次注意力计算都依赖每个先前 token 的 K 和 V 值。实践中，注意力在 decode 期间是线性时间运算，因为 KV Cache 存储了先前 token 的 key 和 value 计算结果。

即使线性扩展的算法也会变得非常昂贵。注意力是所有模型和架构中推理最昂贵的部分之一。自然地，优化注意力是一个重要且高度活跃的研究领域。

注意力是个敏感过程，因为每个 token 依赖每个先前 token。注意力中的小错误会迅速累积，使注意力优化成为精细活儿。

图 2.14 展示了注意力算法本身是直接的。然而，那个基本实现是低效的：中间矩阵 S 和 P 在一步结束时存储，下一步立即加载。

优化注意力有两种策略：

- **实现改进**：写更高性能的内核，更高效地使用内存和算力。
- **新算法**：创建优于二次时间扩展、且质量损失最小的注意力算法。

实现改进仍受注意力二次时间复杂度的限制，但是**无损的**（不影响质量），并让长序列推理在当前硬件上可行。其它算法方法以质量换时间和空间复杂度，尽管训练技术能最小化影响。

注意力最著名的实现是 **FlashAttention** 系列论文和内核。基本算法用几行代码就能实现，而 FlashAttention 用数万行代码，在针对特定 GPU 的手工融合内核中实现注意力——H100 的 FlashAttention 与 B200 的用的是不同代码。

FlashAttention 通过消除多余的内存读写、把注意力算法精确布局以贴合 GPU 能力来工作。FlashAttention 对 LLM prefill 和视频生成等算力受限运算尤其有用。

另一个重要实现是 **PagedAttention**。KV Cache 会迅速变大，填满 GPU 显存并耗时读取。PagedAttention 把 KV Cache 分区成可通过查找表访问的块（页）。这意味着 KV Cache 可以跨 GPU 的碎片内存存储，而不需要单一连续内存块。

虽然 FlashAttention 和 PagedAttention 是有价值的优化，但它们不改变「注意力是二次算法」这一事实。新的注意力变体改善了底层的时间和空间复杂度：

- **滑动窗口注意力（Sliding window attention）**：对先前 w 个 token 的滑动窗口计算注意力，把注意力从 O(N²) 变成 O(Nw)，w 常在 8K 到 32K 范围。
- **门控注意力（Gated attention）**：训练中引入的各种层，允许对某些上下文块以关于块长度的线性时间近似注意力。
- **线性注意力（Linear attention）**：用线性时间算法替换二次 softmax 方程，近似注意力。
- **压缩注意力（Compressed attention）**：周期性压缩序列较早的上下文，注意力同时考虑压缩的上下文和未压缩的近期 token。
- **多潜在注意力（Multi-latent attention）**：在低维潜在空间中近似注意力。

直觉上，序列中彼此靠近的 token 比早得多的 token 相互影响更大，这是合理的。我现在写的这句话紧跟上一句，但与本章开头的句子关系就小些。

这种直觉可以通过训练延伸。滑动窗口注意力等算法在训练时应用，能创造出「在推理中用同样技术时仍保持高质量」的模型。

研究的另一条路是：用不同于 transformer 的架构，彻底避免注意力。**Mamba** 是一种选择性状态空间模型（selective state-space model），用循环状态更新替换自注意力，实现序列长度的线性扩展。混合模型有时把 Mamba 风格的状态空间块与 transformer 块混合。状态空间模型的应用仍有限，尽管随着 NVIDIA Nemotron 3 Nano 等开源模型采用混合架构，混合模型正变得越来越流行。
