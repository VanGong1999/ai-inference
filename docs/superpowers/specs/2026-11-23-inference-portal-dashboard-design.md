# AI 推理工程门户视觉升级设计

## 意图

将现有静态 GitHub Pages 首页从“内容目录页”升级为更容易探索的动态知识控制台，让访客能够快速理解仓库覆盖范围、按主题找到资料，并被清晰的学习路径引导进入正文。

## 目标

- 保留现有页面链接、中文内容和 GitHub Pages 静态部署方式。
- 提升首屏的视觉识别度、信息层级和内容密度。
- 增加无需后端的前端搜索/筛选，让书籍、讲座、可视化和生产笔记更容易定位。
- 用轻量动态效果增强反馈：滚动入场、卡片悬浮、进度感、背景网格/光晕和可视化数据表达。
- 保持移动端可用，并尊重 `prefers-reduced-motion`。

## 非目标

- 不重写已有书籍、Markdown 或 walkthrough 内容。
- 不引入 React/Vue、打包器、后端或新的运行时依赖。
- 不改变现有 URL、GitHub Pages 部署方式或站内文档的阅读体验。

## 反目标

- 动效不能阻碍阅读、搜索和点击。
- 首页不能变成只有装饰、难以快速查资料的展示页。
- 不依赖外部 API、运行时数据请求或不稳定的第三方图表服务。

## 方案

### 方案 A：动态知识控制台（已选择）

在现有首页结构上做集中式升级：加入状态指标、内容筛选、学习路径时间线、可视化入口墙，以及暗色/浅色玻璃质感和轻量动效。优点是信息查找效率和视觉表现同时提升，改动集中、部署风险低。

### 方案 B：沉浸式推理实验室

以深色沉浸视觉、节点网络和强动画为主角。更有冲击力，但会降低目录效率，也更容易让内容退居次要位置。

### 方案 C：极简高密度索引

强化搜索、标签、分类和最近阅读，减少装饰。查询效率高，但无法充分满足“动态炫酷”的诉求。

## 页面结构

1. 顶部导航：品牌、锚点导航、主题切换和搜索入口。
2. Hero：明确的中文定位、统计指标、主 CTA，以及带有推理流水线视觉的动态面板。
3. 快速查找：搜索框、主题筛选标签和结果数量反馈。
4. 学习路线：从基础、缓存、内核、服务优化到生产系统的可视化路线。
5. 内容矩阵：书籍/指南/讲座/可视化四类卡片，保留原有链接并增加标签、摘要和入口。
6. 可视化实验室：突出可交互 walkthrough，提供更明显的视觉入口。
7. 底部资源区：环境搭建、术语表、部署说明和仓库信息。

## 视觉与交互

- 采用深墨蓝作为主背景，配合电光青、紫色和暖橙作为功能色，形成“推理系统控制台”观感。
- 使用半透明面板、细边框、渐变光晕和等宽字体标记技术信息。
- 使用 CSS 动画和少量原生 JavaScript：背景网格缓慢移动、指标数字渐入、卡片交错入场、筛选状态变化。
- 搜索使用现有页面中声明的内容索引，不请求网络；匹配标题、描述和标签。
- 主题切换使用 `localStorage` 记忆；无 JavaScript 时页面仍能正常阅读和跳转。
- 在窄屏下将多栏内容折叠为单列，搜索和主要 CTA 保持优先可见。

## 约束与实现决定

- 只改造 `docs/index.html`，必要时新增一个同目录 CSS/JS 文件，但优先维持单页可部署性。
- 不修改其他文档页面，避免影响原有资料。
- 使用语义化 HTML、键盘可操作控件、可见焦点态和足够的颜色对比度。
- 验收以本地静态服务器打开首页、关键链接可点击、搜索/筛选可用、响应式无横向溢出为准。

## 验收标准

- 首页首屏能清晰表达项目定位，并在视觉上明显区别于当前目录页。
- 访客可以通过关键词或主题筛选定位资源，且没有结果时有明确反馈。
- 学习路线和可视化资源在首屏后较短距离内可发现。
- 主题切换、动画降级和移动端布局可用。
- 本地静态服务器可正常加载，HTML/CSS/JS 无明显控制台错误，现有入口链接未丢失。
