为什么不用 token ID？

token ID 只能说明出现了哪个符号。隐藏状态包含上下文：这个 token 在本句中的含义，以及它可能扮演的角色。

为什么要用向量？

向量可以同时存储许多软特征：主题、实体、指令、变量名、答案锚点或约束。

为什么是可学习的？

矩阵 W_k^I 和 W_q^I 经过训练，使得有用的历史 token 在未来 token 需要它们时能得到高分。

让维度保持简单：512 是 DeepSeek V3.2 中 MLA 的潜在维度，所以每个 token 存储一个 512 个数的压缩内容向量。128 是索引维度，所以每个 token 存储一个 128 个数的查询向量。因为两者都以 FP8 存储，每个数大约 1 字节。

MLA 缓存

对于每个 token，DeepSeek 的 MLA 内容记忆存储一个 512 个数的潜在向量。这就是潜在维度。

512 个潜在数 × 1 字节 = 512B

量化还需要几个 scale 数，实现上还会保留一小部分位置信息。

512B 潜在 + 16B scale + 128B 位置 = 656B
656 × 128K × 61 ≈ 4.77 GiB
DSA 缓存

索引键更小，因为它不是内容记忆，只是一个查询标签。在 V3.2 中，索引键有 128 个数。这就是索引维度。

128 个索引数 × 1 字节 ≈ 128B

再加上一点点 scale 开销，查询条目大约是 132B。

656B MLA 内容 + ~132B 索引键 ≈ 788B
(656 + ~132) × 128K × 61 ≈ 5.73 GiB

所以是的：DSA 可能比单独用 MLA 占用更多缓存内存。收益在于，在长上下文下，HBM 带宽和注意力计算主要是被解码期间反复读取历史所主导。DSA 付出一点点查询缓存成本，来避免在重注意力路径中读取几乎所有的内容向量。

为什么不是端到端的 62.5 倍？

索引器仍然要扫描序列，top-k 有开销，kernel 有开销，其他模型层仍然在运行。所以端到端加速远小于原始内容读取的减少量。

是哪一种复杂度？

O(L^2) -> O(Lk) 是长度为 L 的序列的主要注意力工作：L 个查询位置分别乘以 L 个历史 token 或 k 个选中 token。在单 token 解码中，同样的表述变成重 MLA 注意力读取的 O(L) -> O(k)。

工作坊最佳措辞

不要说 DSA 让 KV 缓存比 MLA 更小。要说：MLA 让缓存更紧凑；DSA 让长上下文注意力读取更稀疏。

MLA 的 Roofline 故事

MLA 减少每个缓存 token 的字节数。对于相似的注意力工作，更少的字节提升了算术强度，让解码远离最糟糕的内存带宽受限区域。

DSA 的 Roofline 故事

DSA 改变了算法。在解码中，重注意力部分对选中内容的读取从 O(L) 变为 O(k)，外加一个更便宜的 O(L) 索引扫描。内存带宽受限时间下降，因为 HBM 流量下降了。

课堂措辞

对于 DSA，要说：缓存占用可能增加，但长上下文解码中每个 token 的 HBM 流量会下降。这就是推理能变快的原因。
