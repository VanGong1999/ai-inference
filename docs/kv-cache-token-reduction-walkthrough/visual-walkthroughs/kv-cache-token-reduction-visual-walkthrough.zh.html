减少 KV 缓存 跨 token

今天我们将学习如何跨 token 减少 KV 缓存。这是一段奇妙的旅程： 它将带我们走过滑动窗口、音乐、自然、状态空间模型，以及那些把冗长记忆变成紧凑表示的现代架构。

我们将把卷积听成音乐，把状态看成自然，然后带着一种新的直觉回到推理： 记忆并不总是需要一份不断增长的 token 列表。

第 1 章

KV 缓存有两条显而易见的轴

对于一个 decoder-only Transformer，每个生成的 token 都会在每一层留下两份纪念品： 一个键（key）向量和一个值（value）向量。如果你生成更多 token，缓存就会变大。如果你使用更多 KV 头，缓存也会变大。如果你的头维度更大，缓存同样会变大。

每层的 KV 缓存 ~= 2 × N × Hkv × dhead × 字节

头轴缩减

MQA、GQA 和潜在（latent）注意力会减少 Hkv，或压缩 K/V 表示。 你仍然为每个 token 存储一些东西，但每个 token 留下的占用更小。

token 轴缩减

滑动窗口只存储最近的 token。线性注意力和 SSM 走得更远：它们用一个可以原地更新的状态 来取代不断增长的 token 列表。

课程地图

我们先做简单的事：只保留最后 W 个 token。然后我们会问一个更深的问题： 我们能不能干脆不缓存单个 token，而改缓存一个压缩后的状态？

第 2 章

滑动窗口注意力（Sliding Window Attention）

滑动窗口注意力说的是：对于新 token，不要关注整个过去。只关注 前 W 个 token。所有比窗口更早的内容都在直接注意力视野之外。

直觉

新 token 看到一个明亮的近期窗口。一个远处的线索仍然存在，但它不再被直接看见。

只有最后 W 个 token 可见

关键之处在于，可见的过去并不是固定的。每当一个新 token 到来，它就成为当前的查询（query）， 注意力窗口也随之滑动。模型维护一个滚动缓冲区，存放最后 W 个键和值； 掉出该缓冲区的 token 就不再被直接看见。

到底保存了什么？

全注意力缓存

2 × N × Hkv × dhead

如果 N 持续增长，KV 缓存也随 N 增长。一个新查询可以看向任何地方，但内存和读取带宽会持续增加。

滑动窗口缓存

2 × min(N, W) × Hkv × dhead

滚动缓冲区只为局部注意力层保留最近的窗口。一旦 N > W，这些层的缓存就不再增长。

重要细节：如果一个模型在局部层和全局层之间交替，只有局部层会得到 W 大小的缓存。 全局层仍然需要更长的缓存。因此总节省量取决于层的组合。

缺点，用一句你会记住的话来说

滑动窗口注意力就像读一本推理小说，却用一把尺子遮住了除最后几行之外的所有内容。 它很快。它很省。但如果线索在第一章里，你可能会自信地错过答案。

远处的线索

「解药就藏在紫色的桥下。」数千个 token 之后：「Mira 应该去哪里找？」 如果「紫色桥」在窗口 W 之外，新 token 就无法直接关注到它。

局部的线索

「她打开蓝色的盒子，找到了钥匙。钥匙在哪里？」这正是滑动窗口发光的地方： 最近的局部细节仍然在 W 之内。

直观的失败模式：代码中的旧变量定义、系统提示词开头的指令、故事开头引入的人名， 或者只被引用过一次、却在很久之后才用到的法律条款。 堆叠的层可以逐步把信息向前传递，但新 token 失去了全注意力所提供的那种干净的一跳式查找。

使用局部/全局或混合思路的模型

实际的模式并不是「总是局部」或「总是全局」。最近的高效架构往往把局部注意力与偶尔的全局注意力混合起来， 或者把注意力层与状态空间层混合起来。

Mistral 7B

使用分组查询注意力（GQA）和滑动窗口注意力来降低推理成本，同时支持长序列。

Gemma 2

将局部注意力与全局注意力交错使用，并使用 GQA。局部层使用滑动窗口。

Jamba

这更接近你对 Mamba 的直觉：它把 Transformer 注意力层与 Mamba SSM 层混合起来。 纯 Mamba 并不会在滑动窗口和全注意力之间交替；像 Jamba 这样的混合模型把两个家族结合起来。

预备知识 1

只要有状态在演化，就会出现状态空间模型（State Space Models）

在深入之前，先暂时忘掉神经网络。状态空间模型是最简单的故事： 世界有一个隐藏状态，每一个新输入都会把这个状态向前推一点。

状态 + 输入

一个细胞、一只蜗牛和一个太阳系都携带状态。外部输入改变状态；下一个状态又改变未来。

yt = C ht
生物

一个细胞

状态是细胞内部的化学组成。外部输入是营养物质、激素、压力信号。 输出是细胞接下来要做的事：分裂、修复、发出信号或休息。

自然

蜗牛的轨迹

状态是位置、湿度、能量和轨迹历史。每一片叶子都会改变下一步行动。 路径并不是以一张巨大列表存储的；它作为状态被向前携带。

轨道

一颗行星

状态是位置和速度。引力是弯曲未来的输入。轨道是通过反复更新状态而生成的。

预备知识 2

卷积：音乐上的捷径

让我们像音乐制作人而不是数学家那样开始。拿一段熟悉的旋律，比如 《Twinkle, Twinkle, Little Star》（小星星）。现在想象你想重新混音它，让它听起来像是在音乐厅里演唱。 那个混响效果就是卷积。

制作人的问题

我们如何给一段干声旋律加上音乐厅的回声质感，而又不用做大量重复的工作？

第一性原理：从旋律到混音

当人们听到一首歌时，他们想到的是旋律：C, C, G, G, A, A, G。 但音频编辑器无法对「音符」这个概念施加混响。它是对歌手或乐器发出的实际声波施加混响。 所以我们从旋律放大到波形。

第 5 步 - 为什么直接方法会变慢

成本就藏在这些重复的 y 计算里

看看上面的公式。每个 y 都要扫过回声权重 1.0, 0.6, 0.3, 0.1。有 6 个波形快照和 4 个回声权重时，直接方法 大约做 6 x 4 次小的乘加运算。一般地：

N 个波形快照 × R 个回声权重 = O(NR)

如果音乐厅的尾音很长，R 会变得非常大。当 R 像 N 一样增长时，直接混音就呈现 N x N = O(N^2) 的形状。

玩具混音：6 个波形快照 x 4 个回声权重

行是波形快照，列是回声权重。直接卷积会填满这张工作量网格。

首先：频域是什么意思？

在音乐厅和 FFT 之前，先从一个微小的数字序列开始。时域视角说的是： 这是第 0 步、第 1 步、第 2 步……的值。频域视角说的是另一件事： 能否通过叠加简单的正弦波和余弦波来重建整个模式？

在公式之前：到底允许哪些波？

因为我们有 M = 8 个点，一个完整的圆被分成八个相等的角。 步长是 2π / 8 = π/4 = 45°。傅里叶基波是通过以不同速度绕这个圆行走而得到的： k = 0、k = 1、 k = 2……等等。

k = 0 平坦波

不旋转。这个基波给出平均水平。

k = 1 一个周期

横跨八个位置的一个正弦/余弦周期。

k = 2 两个周期

这正是我们的玩具序列实际包含的波。

k = 6 成对的波

k = 2 的伙伴，用于生成实数正弦摆动。

xn = coefficient0·wave0(n) + coefficient1·wave1(n) + ...

所以没错：在做任何公式之前，目标已经很清楚了。我们已经知道候选的波。我们需要找到 系数，也就是每种波要加多少，好让它们的和重建出原始序列。

转换公式

Xk = ∑n=0M-1 xn e-2πikn/M

它问的是：整个序列里有多少频率 k 的成分？ 复指数只是同时携带余弦和正弦的一种紧凑方式。

答案 Xk 被称为频率系数。它是一个复数， 同时存储两件事：该频率有多强，以及它具有什么样的相位/偏移。 你把序列与第 k 个正弦/余弦波相乘，再把所有乘积加起来，就得到了它。

eiθ = cos(θ) + i sin(θ)

重建公式

xn = (1/M) ∑k=0M-1 Xk e2πikn/M

它从频域视角走回时域视角。它把位置 n 处的所有频率波相加，恢复出原始数字 xn。

现在把公式应用到实际数字上

使用同一个序列： M = 8， x = [3, 5, 3, 1, 3, 5, 3, 1]。 转换公式为每个可能的频率 k = 0...7 计算一个数字 Xk。

频率系数 = 「对某个基波的打分」

如果序列与 k = 2 的波高度对齐，那么 X2 就很大。如果它与 k = 1 不对齐，那么 X1 就变成 0。 逆公式把这些打分当作混合旋钮：加入这么多 k = 0、这么多 k = 2、这么多 k = 6……等等。

k 是什么？它是频率索引

因为 M = 8，DFT 会测试八个基波。 k = 0 表示没有波，只是平坦的平均。 k = 1 表示横跨八个时间步的一个周期。 k = 2 表示横跨八个时间步的两个周期……等等。 对于实值序列，像 k = 6 这样的高索引表现得像负频率伙伴； k = 6 与 k = 2 配对以生成实数正弦波。

FFT 在哪里登场：同样的系数，更快的路线

上面的公式就是 DFT：它定义了频率系数 X0, X1, ..., X7。FFT 不是一种新的变换，也不会产生不同的 数字。FFT 是计算这些相同系数的快速算法： [24, 0, -8i, 0, 0, 0, 8i, 0]。

所以 FFT 的目的很简单：得到与 DFT 公式相同的频域表示， 但避免从头开始做每一个频率对每一个时间的乘法。

慢路线：每个频率扫描每个时间步

8 个频率系数 × 8 个时间值 = 64 个小乘积

一般地，这是 M 个频率乘以 M 个时间位置，所以直接傅里叶变换是 O(M²)。

复用的思路：把一个 DFT 问题拆成更小的 DFT 问题

FFT 计算出的正是我们已经推导出的同一个系数列表： X = [24, 0, -8i, 0, 0, 0, 8i, 0]。 它只是通过复用更小的计算来到达这个列表。数字 8 → 4 → 2 → 1 不是输出值，它们是更小的 DFT 问题的规模。

圆的图像：为什么可以复用

正弦和余弦在转过一整圈后重复。用弧度表示是 2π； 用角度表示是 360°。所以旋转 θ + 2π 与 θ 指向同一个位置。 FFT 利用了这种重复性。

8 点圆 45° 步长

完整序列使用绕 8 点圆的旋转：0°、45°、90°、……、315°。

偶数位置 同一个更小的圆

偶数索引落在 0°、90°、180°、270°：恰好是一个 4 点傅里叶模式。

奇数位置 同一个圆，旋转过

奇数索引落在同一个 4 点模式上，只是偏移了 45°。那个偏移就是 wk。

这是主要的洞见：拆分成偶数和奇数位置之后，正弦/余弦模式并不会变成新的随机模式。 它们变成同一模式的更小版本，外加一个旋转。这就是为什么更小的傅里叶变换可以被复用。

8 → 4 → 2 → 1：三次减半，因为 log2(8) = 3

对于 M 个值，在达到一个值之前你可以减半的次数是 log2(M)。在每一层，所有分块合起来仍然包含大约 M 个值，所以总工作量变成 M log M。

log 在哪里出现

问一个简单的问题：在达到 1 之前，我可以把 8 减半多少次？ 8 → 4 是一次减半，4 → 2 是 第二次减半，2 → 1 是第三次减半。 所以层数是 3 = log2(8)。

在每一层，我们并不是再次做 8×8 的工作。我们在合并小的答案。 每个原始数字在该层只参与一次小合并，所以该层的总工作量大约是 8。三层给出大约 8 + 8 + 8 的工作量。

第 1 层

把大小为 1 的分块合并成大小为 2 的变换。大约接触 8 个值。

第 2 层

把大小为 2 的变换合并成大小为 4 的变换。同样大约接触 8 个值。

第 3 层

把大小为 4 的变换合并成大小为 8 的变换。同样大约接触 8 个值。

每层 8 的工作量 × 3 层 = 8 × log2(8)
每层 M 的工作量 × log2(M) 层 = O(M log M)

慢公式要求每个频率系数扫描每个时间值： 8 × 8 = 64。FFT 让更小的 DFT 共享工作： 向下拆分 log2(8) 层，向上合并，每层大约 8 的工作量。确切的常数不是重点； 形状才是重点。

最终要点：慢速 DFT 把每个频率与每个时间点都扫描一遍。FFT 通过拆分和复用得到相同的系数，所以工作量变成每层 M 乘以 log M 层。
从这里开始：频域的意思是「用序列包含多少每种正弦/余弦波来描述整个序列」。 逆变换把那些波加回去，以恢复原始的时间序列。

回到混响：快速变换给我们带来了什么

现在这个故事有了坚实的基础。傅里叶转换把时间序列变成频率 系数。逆转换重建时间序列。FFT 更快地计算那些相同的系数： O(M log M) 而不是 O(M²)。

直接混响路径

时域视角：不断把音乐厅回声配方滑过干声波形。 这就是重复的「加权过去」计算。

频域混响路径

频域视角：转换干声波形和音乐厅预设，把匹配的频率系数相乘， 然后逆变换回带混响的波形。

1. 转换 x

用 FFT 把干声歌曲从时间值转换成频率系数。

2. 转换 h

用 FFT 把音乐厅预设转换成它的频率响应。

3. 相乘

对每个频率，把歌曲系数乘以音乐厅系数。

4. 重建 y

用逆 FFT 回到时域：这就是带混响的歌曲。

时域中的卷积变成频域中的乘法： FFT(x)、FFT(h)，逐频率相乘，然后逆 FFT。这就是音乐捷径之所以重要的原因。

直接时域卷积

对于每个混音点 yt：
回头扫过回声权重 r0, r1, r2, ...

这是慢方法：不断把音乐厅预设滑过干声波形。 有 N 个波形快照和 R 个回声权重时，工作量是 O(NR)。如果回声尾音足够长，使 R 表现得像 N， 它就变成熟悉的 O(N2) 故事。

快速的频域捷径

拆分成纯音层 → 应用音乐厅响应 → 重新组合

繁重的滑动工作变成逐频率的乘法。一次补零的完整卷积成本是 O(M log M)。对于分块处理的长信号，直觉变成 O(N log R)。 工程师把这种转换叫做傅里叶变换；那种快速的拆分-复用算法就是 FFT。

这对状态空间模型为什么重要：经典的线性时不变 SSM 具有固定的冲激响应。 在整个提示词上，那个递推可以看作同一种「加权过去」运算。这就是为什么「频率拆分」的思考方式有助于 解释 S4 这类较老 SSM 的并行预填充（prefill）/训练。

预填充（Prefill）

预填充是提示词处理阶段：你已经有了 N 个 token，想要高效地处理它们。 对于固定的线性 SSM，整个提示词上的递推可以表示成一个卷积。

x1:N * kernel → y1:N

这正是音乐「频率棱镜」类比最有用的地方：并行处理整个提示词，而不是逐个 token 地推进。

解码（Decode）

解码是生成阶段：一次只来一个新 token。你不会重新处理整个提示词。你保留预填充得到的 最终状态，并原地更新它。

h ← A h + B xnew

没有不断增长的 KV 列表。被缓存的对象就是状态本身。

每一行都使用同一个卷积核序列 K0, K1, K2, ...，在输入 token 上平移。 那种重复平移的模式正是卷积。
对心智模型的修正：卷积的故事干净地适用于训练或预填充阶段的固定、线性、时不变 SSM。 在解码阶段，你只需使用递推。对于 Mamba 的选择性 SSM， 参数依赖于输入 token，所以单个固定的卷积核就不再够用了。 Mamba 对提示词处理使用并行选择性扫描，然后对解码使用递推状态更新。

为什么选择性很重要

考虑一篇长文档：

「退款截止日期是 4 月 3 日。」…… 许多页的政策性文字 ……「这位客户仍然符合条件吗？」

一个非选择性的状态更新会用同一种动态来处理重要日期和周围的填充内容。 模型可能会慢慢把这个日期冲刷掉。这是错误的行为。它应该在 token 重要时强力写入， 在 token 是噪声时几乎不写入。

好记的直觉：固定的 SSM 就像一本每个字都用同样大小笔迹书写的笔记本。 Mamba 学会了什么时候写粗体、什么时候写轻一点、什么时候保留前一页。

结论

KV 缓存对比与性能直觉

每种方法都是在选择一种记忆叙事。你对记忆叙事理解得越好，就越容易预测 推理节省量和模型行为。

方法 缓存了什么？ 上下文长度为 N 时的内存 直觉 可能的取舍
全注意力 每个 token 的 K 和 V O(N × Hkv × d) 完美的过去通讯录。 回忆能力强，但长上下文推理昂贵。
MQA / GQA 更少 KV 头的 K 和 V O(N × fewer heads × d) 保留所有 token，减少头这一轴。 通常有出色的质量/速度平衡。
滑动窗口 局部层中最后 W 个 token 的 K 和 V O(W × Hkv × d) 近期的工作记忆。 局部效率高，但对旧线索的直接回忆较弱。
线性注意力 运行中的分子 S 和分母 z O(dφ × dv) 把所有过去 token 压缩成代数求和。 状态更新快，但 token 选择比 softmax 注意力更柔和。
SSM / Mamba 固定的 SSM 状态加上小的卷积缓冲区 O(状态大小)，与 N 无关 压缩的、不断演化的记忆。 内存节省巨大；质量取决于状态保存所需细节的程度。
混合模型 一部分注意力缓存加一部分固定状态 取决于层的组合 用注意力做精确查找，用 SSM/局部层提效。 通常是长上下文的务实中间路线。

当答案就在附近时

滑动窗口可以表现得很出色。大多数局部语法、短代码依赖和即时事实都在附近。

当答案在远处时

全注意力或偶尔的全局注意力会有所帮助。如果第一段包含密码，仅局部的模型可能会忘记。

当内存必须很省时

状态空间模型和线性模型会大放异彩。它们用精确的 token 存储换取压缩的、可更新的记忆。

句子层面的直觉

如果提示词说「Riya 的护照号码写在黄色信封上」，而五页之后又问道 「Riya 应该去哪里找？」，全注意力可以直接检查那条旧线索。滑动窗口注意力只有在线索仍然在 W 之内、 或者中间层把它向前传递时才能做到这一点。Mamba 尝试了另一种交易： 不要存储每一个词；学会在关键时候把「黄色信封」写入一个紧凑状态。

现代架构

现代长上下文模型常常混合这些记忆叙事：局部窗口、紧凑状态、稀疏路径，以及偶尔的全局注意力。

现代架构如何使用这些想法

实际上，这个领域正在向混合方案收敛。有些层保持精确的注意力。有些层只做局部观察。 有些层携带一个压缩状态。设计问题变成了：哪里需要精确查找，哪里用学到的记忆摘要就足够了？

局部注意力

Mistral 风格的窗口

使用滑动窗口，让每个 token 只读取一个有界的近期邻域，而不是每一层都读取整个过去。

局部 + 全局

Gemma 2 风格的混合

把局部注意力与全局注意力交错使用，让大多数层很便宜，而某些层仍然能做长距离查找。

选择性状态

Mamba / Mamba-2

用一个固定状态取代不断增长的 KV 列表，然后通过选择性让写入/读取动态变得内容感知。

混合

Jamba

把 Transformer 注意力块与 Mamba 风格的 SSM 块混合起来：需要的地方精确查找，可能的地方使用紧凑状态。

性能直觉：局部注意力通过从许多层丢弃旧 token 来节省内存。 SSM 通过把旧 token 压缩进状态来节省内存。混合模型试图两者兼得：足够的精确注意力用于困难回忆， 足够的状态/局部处理用于廉价的长上下文推理。
