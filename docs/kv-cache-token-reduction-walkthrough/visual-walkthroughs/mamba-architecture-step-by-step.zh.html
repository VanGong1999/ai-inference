第 1 章

什么被替换了

在标准 Transformer 中，每一层都有两个子模块：一个用于跨 token 混合（注意力 Attention），另一个用于逐 token 处理（FFN）。Mamba 用一个统一的模块同时取代了这两者。

第 9 章

什么被缓存——以及为什么 Mamba 永不增长

在推理过程中，每个模型都必须记住一些关于它已经见过的 token 的信息。问题是：需要记住多少？这正是 Mamba 与 Transformer 根本不同的地方。

Transformer 的问题：KV 缓存（KV Cache）永远增长

在 Transformer 中，在自回归生成期间，每个新 token 都需要关注（attend to）所有先前的 token。为了避免重新计算过去 token 的键（Key）和值（Value），它们被存储在 KV 缓存中。

Transformer KV 缓存 —— 每一层

存储： 到目前为止见过的每个 token的 K 向量 + V 向量 形状： 2 × N × d 当 N=100K 时： 2 × 100,000 × 2,048 × 2 字节 = 每层 781 MB

KV 缓存随序列长度线性增长。在长上下文中，它可能超出 GPU 内存。

Mamba 的状态：固定大小，无论序列多长

Mamba 没有 KV 缓存。相反，它维护一个固定大小的隐藏状态（hidden state），每处理一个 token 就更新一次——而不是追加。处理完一个 token 后，旧状态就消失了，只保留更新后的状态。以下是要存储的确切内容：

Mamba 推理状态 —— 每一层

1. SSM 隐藏状态
h ∈ ℝE × n

E 个扩展维度中的每一个都维护着自己的 n 维状态向量。这个状态总结了所有过去的 token——就像压缩后的记忆。

玩具模型：E=4，n=2 → 8 个数字
实际：E=4096，n=16 → 65,536 个数字
2. Conv1D 缓冲区
buf ∈ ℝE × (k-1)

Conv1D 需要看到前 k-1 个 token 的 x' 值（其中 k 是卷积核大小，通常为 4）。这是一个很小的循环缓冲区。

玩具模型：E=4，k=2 → 4 个数字
实际：E=4096，k=4 → 12,288 个数字
每层总状态： E × n + E × (k − 1)
玩具模型：8 + 4 = 12 个数字
实际：65,536 + 12,288 = 77,824 个数字
FP16 下：77,824 × 2 字节 = 每层 156 KB
关键点：这个状态是固定的。第 1 个 token 和第 1,000,000 个 token 使用完全相同数量的状态内存。状态不会增长——它是在原处更新的。旧信息通过递归被压缩到状态中，而不是原样存储。

为什么是 E × n？理解状态的形状

你可能会想：为什么状态是 E × n，而不是 d × d 或 N × d？让我们追踪每个维度的来源：

E （扩展维度） 输入 x（维度 d）被向上投影到维度 E = 2d。SSM 运行 E 个独立的递归副本——每个扩展维度一个。每个副本都有自己的状态。 n （状态维度） 每个独立的 SSM 副本都维护一个 n 维状态向量。在实际 Mamba 中，n 通常为 16。这是每个通道的"记忆容量"——每个通道能同时记住多少不同的东西。

推理期间每个 token 的 FLOPs

在解码（decode）期间（生成一个新 token），Mamba 模块中的每个运算都运行一次。让我们数一数 FLOPs：

为什么任何地方都没有 N²

你可能以为某个地方会出现 O(N²)——毕竟 Transformer 有它。但 Mamba 没有注意力机制，因此没有 N × N 的相似度矩阵。以下是每个模型在解码期间计算的内容：

Transformer 解码

新查询（query）q 关注所有 N 个缓存的键（key）：
scores = q · KT → O(Nd) 每个 token
attn = softmax(scores) · V → O(Nd)

成本随 N 增大而增长，因为查询必须"查看"每一个过去的键。

Mamba 解码

新 token 在原处更新状态：
h = Ā × h + B̄ × x → O(En)
y = C · h → O(En)

成本始终相同。无论前面有多少 token，状态 h 的大小都是 E×n。

权衡：Mamba 的固定状态意味着它压缩过去的信息，而不是原样存储。具有完整注意力的 Transformer 可以在第 100,000 个 token 处召回第 1 个 token 的任何细节（代价是庞大的 KV 缓存）。Mamba 的状态是有损摘要——旧信息呈指数衰减（由 Ā 控制）。这就是为什么混合架构（Mamba + 少量注意力层）正在成为实用的最佳平衡点。

关键洞察

Transformer 的 KV 缓存是无损的——它存储每个过去 token 的精确 K 和 V。Mamba 的状态是有损的——它通过递归 ht = Āt × ht-1 + B̄t × xt 将所有过去的 token 压缩到一个固定大小的向量中。选择性机制（Δ）确保重要的 token 被强力记住，而噪声 token 快速衰减。这就是 156 KB 能取代 781 MB 的原因——因为那 781 MB 中的大部分存储的是模型本来就不需要的 "the"、"of"、"is" 等 token 的信息。

完整图景

关键要点

1
Mamba 用单一模块同时取代了注意力（Attention）和 FFN。

参数减半，表达能力不变。选择性 SSM 处理跨 token 混合（原来由注意力完成），而门控处理逐 token 处理（原来由 FFN 完成）。

2
选择性 SSM 根据输入计算 B、C 和 Δ——内容相关的处理。

与这些参数固定的经典 SSM（S4）不同，Mamba 让它们依赖于输入。每个 token 都有自己的动态。

3
Δ（delta）控制遗忘/写入的平衡——选择性的核心。

大的 Δ = 抹掉旧状态，强力写入新内容。小的 Δ = 保留状态，几乎不写入。模型学会了何时记住、何时遗忘。

4
Conv1D 提供局部上下文，SSM 提供长程上下文，门控提供输出控制。

三种互补机制在单一模块中协同工作。

5
推理期间：每个 token O(1)，内存恒定。没有 KV 缓存！

隐藏状态 h 是一个固定大小的向量（每个通道 N 个元素）。与 KV 缓存随序列长度线性增长的 Transformer 不同，无论处理了多少 token，Mamba 的内存都是恒定的。

Transformer 推理

O(n)

KV 缓存随每个 token 增长。
内存：每层 O(n × d)。

Mamba 推理

O(1)

状态固定，每个 token 恒定。
内存：每层 O(E × N)。
