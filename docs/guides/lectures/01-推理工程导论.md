# 第 01 讲 · 推理工程导论

> Introduction to Inference Engineering

## 本讲讲了什么

这一讲是整门课的**入口**，回答两个根本问题：**推理工程（Inference Engineering）是什么，以及推理工程师（Inference Engineer）到底在做什么。**

核心观点：很多人以为大模型的「魔法」藏在预训练（pre-training）里，但真正决定一个产品能不能用、贵不贵、可不可能上线的是**推理（inference）**——也就是训练好的模型如何面对单块 GPU 的物理极限、面对上千用户的成本压力、面对发版期限。推理不是训练的注脚，而是主战场。

本讲引入几个关键概念：

- **三层架构（Three Layers）**：把推理系统分成「运行时（Runtime）」「基础设施（Infrastructure）」「工具（Tooling）」三层。运行时关心一个请求如何快速变成 token（KV cache、FlashAttention、PagedAttention）；基础设施关心服务如何扩展（路由、自动扩缩容、多区域）；工具关心可观测性与调试。
- **推理工程师的交叉点（intersection）**：推理工程师站在「模型 / 系统 / 硬件」三者的交汇处，既要懂模型结构，也要懂 GPU 与网络，还要懂服务化。
- **推理谱系（inference spectrum）**：从云端 GPU 到端侧（on-device）的连续谱，不同场景有不同的约束（成本、延迟、隐私、功耗）。
- **真实案例**：Vizz AI（一个实时语音家教）在推理侧的成本爆炸——每轮对话都要对「累计的全部上下文」计费，成本随对话时长复合增长，这是推理工程要解决的典型问题。

这一讲用「当所有开源模型都能免费下载时，为什么『如何服务它』仍然重要？」这个问题贯穿始终。

## 前置知识

- 了解大模型的基本概念（token、生成式模型、自回归）。
- 对训练（training）与推理（inference）的区别有初步直觉。
- 不需要 GPU 编程经验。

## 实践 / 作业

本讲以概念为主，无强制代码作业。建议：

1. 打开书籍 ch0–ch1，边读边对照上面的 Miro 笔记。
2. 点开 `DNA of a Transformer` 与 `Anatomy of a GPU`，建立「模型结构 + 硬件」的双重视角。
3. 思考题：为什么一个「免费下载的开源模型」服务起来仍然很贵？写出至少 3 个原因（提示：内存、带宽、并发）。
