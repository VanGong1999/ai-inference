# 第 08 讲 · 投机解码（Speculative Decoding）

> Speculative Decoding

## 本讲讲了什么

decode 阶段是 memory-bound 的：每生成一个 token，都要把模型权重与 KV Cache 从 HBM 读一遍，但只做很少的算。**投机解码（Speculative Decoding）** 的思路是：既然单个 token 的 decode 算力利用率低，那就用「小成本预测多个候选 token，再让大模型一次性并行验证」。

核心机制：

1. **草稿（draft）阶段**：用一个「便宜」的草稿模型（draft model）或其它机制，快速生成 `k` 个候选 token。
2. **验证（verify）阶段**：把草稿 token 拼进上下文，让大模型**并行**地对这 `k` 个位置做一次前向传播，得到每个位置的分布。
3. **接受/拒绝（accept/reject）**：对每个草稿 token，按概率决定接受或拒绝（类似拒绝采样，rejection sampling）。一旦某个 token 被拒绝，从该位置重新采样一个 token，后面的草稿全部丢弃。

关键性质：**只要接受/拒绝的采样方式正确，投机解码的输出分布与直接自回归解码完全一致（无损，lossless）**，因此不牺牲质量。加速取决于**接受率（acceptance rate）**——草稿模型与目标模型越「合拍」，接受率越高，加速越大。

几种草稿来源：

- **N-gram 方法**：用统计 n-gram 做草稿（简单但接受率低）。
- **Medusa（多头）**：在目标模型上额外加多个「预测未来 token 的头」，并行预测多个位置。
- **EAGLE**：用一个轻量的 draft 模型预测草稿。
- **Multi-Token Prediction（多 token 预测）**：训练时就让模型同时预测多个未来 token，从而天然支持草稿（DeepSeek 从零实现系列 ch05）。

本讲还会讨论「什么时候投机解码划算」：decode 是 memory-bound 时，并行验证 `k` 个 token 几乎不增加带宽，却能一次产出多个 token，所以加速明显；但草稿模型本身也有成本，接受率太低就得不偿失。
