KV 缓存驱逐
布局 评分 驱逐 进阶
以可视化方式讲解的 OpenVINO GenAI 概念

KV 缓存驱逐是一种选择性的内存压力。

运行时并不会永远保留每一个旧 token，而是保护开头、保护最新的 token， 并让注意力分数（attention scores）决定哪些中间块还值得占用内存。

生成过程中的一个序列 prefill 之后

缓存并不是逐个 token 删除的。OpenVINO 的算法以块（block）为粒度工作， 因此可驱逐区域中的整块才是候选对象。

1. 心智模型

缓存被划分为三个逻辑区域。

模型首先正常处理 prompt。在生成过程中，算法会对每个序列可占用的 KV 缓存大小施加一个上限。

prefill 阶段不会发生驱逐，因此非常长的 prompt 仍可能在生成期上限生效之前， 先产生一个很大的临时缓存。
起始区 指令、角色设定、早期锚点。永不被驱逐。
可驱逐区 较早的中间上下文。块之间通过累积的注意力分数来竞争。
最近区 新鲜的 token。在它们还属于最近时受到保护，之后逐渐老化进入中间区。

Prompt 填满缓存

prefill 阶段在完整 prompt 可见的情况下运行。驱逐并不是用来提升 prefill 速度的工具。

生成开始

新 token 进入最近区。较旧的 token 逐渐漂向可驱逐区。

分数累积

对保留 token 的注意力会跨层、跨生成步骤进行聚合。

块被移除

当超过上限时，中间区低价值的块会被驱逐。

2. 重要性分数

注意力变成了记忆分数。

如果后续 token 持续关注某个块，这个块很可能是有用的。如果某个块得到的注意力很少， 它就更适合作为驱逐候选。

这遵循 H2O 式的直觉：heavy-hitter token 应该保留，因为模型会反复回看它们。
按块累积的注意力 分数更高者保留
Q

每个新的查询 token 会关注被保留的 KV 块。

S

运行时把注意力聚合为块级的重要性分数。

K

分数强的块留在缓存中；弱中间块会先被移除。

3. 交互式驱逐

选择一种策略，观察中间部分的变化。

受保护的起始区和最近区保持稳定。策略只会改变哪些可驱逐块能够存活。

更小的缓存上限意味着更稳定的延迟和更低的内存占用，但如果被移除的块后来变得重要， 质量可能下降。
SUM / NORM_SUM 风格：保留注意力最高的块 预算：18 个中间块
4. 可选的改进

有些模式保护的不仅是「热门」，还有多样性。

纯注意力分数会保留被关注最多的块。自适应 R-KV 和 KVCrush 引入了第二种思路： 保留有代表性的块，使剩余的上下文不冗余。

OpenVINO 推荐在推理类场景使用自适应 R-KV，因为多样性有助于避免重复或冗余的推理轨迹。

自适应 R-KV

首先保留一个可配置比例的注意力质量。然后用与已保留块不相似的块来填满剩余的预算。

KVCrush

根据重要性分数构建二值指示器，把块模式与一个锚点比较，并从可驱逐区保留有代表性的块。

5. 缓存旋转

RoPE 不喜欢位置空间中出现空洞。

驱逐会移除旧块，但位置嵌入（positional embeddings）仍然记得这些块原来在哪里。 缓存旋转尝试重新旋转被保留的块，使它们的有效位置重新变得连续。

旋转是可选的，且依赖于模型。它针对规则的、线性的、类似 LLaMA 的 RoPE 布局， 在其他 RoPE 方案上可能会降低准确率。

驱逐之后

一些块消失了，在原始位置节奏中留下了空洞。

旋转之后

被保留的块被调整，使剩余的缓存更接近连续。

6. 实用调参

这些旋钮的核心是准确率与内存的权衡。

更大的保护区会保留更多上下文。更小的上限会降低内存占用，并在长生成期间 让 token 延迟更稳定。

使用针对具体任务的评测。聊天摘要可能可以容忍驱逐；而编程 agent 和深度研究 往往需要旧的约束、文件路径和工具输出。
旋钮 含义 需要留意
start_size 开头有多少内容始终被保留。 系统提示、任务设定和早期约束。
recent_size 有多少最新的上下文受到保护。 局部连贯性和即时指令遵循。
max_cache_size 生成期驱逐开始后的总缓存预算。 内存、并发和长生成稳定性。
aggregation_mode 注意力分数如何累积和解释。 推理质量、冗余度以及对较早细节的召回。
apply_rotation 驱逐后是否重新旋转被保留的 RoPE 块。 只有在模型的 RoPE 方案上测试后才启用。
