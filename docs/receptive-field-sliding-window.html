感受野追踪

一个小的滑动窗口如何在三层 transformer 之后看得更远。

滑动窗口注意力听起来像是模型被困在了一个狭小的局部邻域里。 但堆叠的 transformer 层会创建接力路径：token 12 可以通过较低层的中间 token， 从更远的 token 那里接收信息。

一个句子锚点

我们将跟随最后一个 token “chapel”。在一层时它只读取附近的词。 到了第三层，像 “violinist” 这样更早的词就能间接地影响它。

窗口 W = 4 · 层数 L = 3

精确的数量取决于约定。这里 W = 4 表示「当前 token 加上之前的 3 个」， 所以精确的可达跨度是 4 → 7 → 10。许多图把这一思想概括为约 W × L。

1. 句子

我们追踪什么能影响最后一个词。

这里是 12 个 token。目标是 token 12，chapel。在一个普通的因果 transformer 中， token 12 可以直接关注到每一个更早的 token。而在滑动窗口注意力中，它只能直接关注到局部窗口。

2. 单层

滑动窗口是一种局部读取规则。

在任意层，每个 token 只读取它附近的一小群。当 W = 4 时，token 12 读取： token 9、token 10、token 11 和 token 12。

这还不是循环缓冲。这是注意力规则：「不要回看超过最后 W 个 token 的范围」。 循环缓冲是推理引擎只存储这些最近 KV 槽位的一种高效方式。

3. 层堆叠

第 3 层并不直接读取旧的 token。它读取的是已经包含旧 token 的摘要。

4. 接力路径

远方的信息通过附近的 token 传递。

第 3 层的 token 12 并不会直接画一条注意力边到 token 3。相反，它可以在第 2 层读取 token 9。 第 2 层的 token 9 可以在第 1 层读取 token 6。第 1 层的 token 6 可以从输入中读取 token 3。

这条链条就是感受野的增长。每一层增加一次局部跳跃。模型获得了更远的上下文， 而无需每个单独的层都使用全注意力。

5. 注意力规则 vs 实现

循环缓冲是 KV 缓存的存储技巧，而不是整个数学思想。

滑动窗口注意力是模型规则：每个 token 只关注一个最近的窗口。 在推理期间，服务引擎可以利用这一规则，把 K 和 V 向量存储在一个固定大小的循环缓冲中。

slot = token_position mod W

槽位号只是存储用途。真正的 token 位置仍然需要用于因果掩码和 RoPE 等位置编码。
