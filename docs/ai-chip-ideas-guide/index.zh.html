第一性原理指南

从 GPU 推理开始，然后构想更好的芯片。

大多数人第一次接触 AI 基础设施都是通过 GPU 推理。本指南从这里出发，用通俗的语言解释重要的硬件术语，然后把瓶颈转化成创业创意。

从 GPU 开始 解释术语
第 1 步

今天每个人都在做什么。

今天大多数严肃的 LLM 推理都跑在 GPU 上。GPU 非常好用，但它们也带着来自图形学、CUDA、昂贵内存和主机-设备系统的假设。这为新创意留出了空间。

1. 请求

用户发送一个提示词。系统把文本变成 token。

2. GPU 内存

模型权重和 KV 缓存存放在昂贵的高带宽内存里。

3. 矩阵运算

大部分工作是注意力层和前馈层里的矩阵乘法。

4. 调度

kernel、批处理、路由和队列决定了 GPU 是否保持忙碌。

5. 成本

业务指标不只是速度，而是每一美元能换来的有效 token。

简单的框架

GPU 擅长许多种并行工作。但 LLM 推理是一个更窄的任务：搬运模型数据、做矩阵乘法、记住历史 token、生成新 token。如果我们理解了这个更窄的任务，就能问：换一种硬件-软件栈是否会更便宜或更容易编程。

第 2 步

在谈大创意之前的基础知识。

下面每个术语之所以出现，是因为它已经是当前 GPU 推理的一部分，或者因为它攻击了当前路径中的某个成本。目标不是为了背单词：而是要看清钱、延迟和复杂性都花在了哪里。

基本概念

什么是脉动阵列（systolic array）？

脉动阵列是一个由微小乘加单元组成的网格。数字以规律的节奏流过网格，所以芯片可以用极少的浪费搬运来完成矩阵乘法。

  • LLM 的大部分数学都花在矩阵乘法里。
  • 现代 NVIDIA GPU 已经在 Tensor 核心里包含了这种矩阵引擎，当前的 LLM 推理也在不断使用它。
  • TPU 把类似的引擎称为矩阵乘法单元（Matrix Multiply Units）。
  • 我们提到脉动阵列，是因为一块昂贵的 GPU 只有在这些矩阵引擎被好好喂数据、定尺寸、被调度时才有生产力。
基本概念

什么是 HBM、SRAM 和 SSD？

它们是存放数据的不同位置。内存离得越近、越快，就越贵。推理成本往往来自决定哪些字节必须靠近矩阵引擎、哪些字节可以放得更远。

  • SRAM：芯片上极小、极快的内存。
  • HBM：在 GPU 或加速器旁边的高带宽昂贵内存。
  • SSD：便宜得多的存储，但比 HBM 慢。
  • 我们提到内存层级，是因为许多 AI 芯片创意不是关于更多算力；而是关于把热数据放近、把冷数据放便宜。
基本概念

什么是 KV 缓存？

当 LLM 读取或生成 token 时，它会存储之前 token 的键（key）和值（value）向量，这样就不必每次都从头重算。这个存储就叫 KV 缓存。

  • K 表示键（key）；V 表示值（value）。
  • 当前的 GPU 推理通常把活跃的 KV 缓存放在 GPU 的 HBM 里。
  • 长对话和长文档会产生很大的 KV 缓存。
  • 我们提到 KV 缓存，是因为长上下文推理往往先变成一个内存管理问题，之后才变成纯算力问题。
基本概念

什么是 DMA？

DMA 意思是直接内存访问（direct memory access）。不必让 CPU 手动搬动每一小块数据，DMA 引擎会在后台把数据块从一个内存位置复制到另一个。

  • 把它想象成一条数据传送带。
  • 它可以在 SRAM、HBM、网络或 SSD 之间搬运数据。
  • 它可以让搬运与计算重叠，这样矩阵引擎就不必干等。
  • 我们提到 DMA，是因为许多改进提案其实都是关于更好的传送带，包括数据移动过程中的压缩。
第 3 步

GPU 推理在哪里变贵。

这些瓶颈是连接「我们用 GPU」和「也许有新的芯片、编译器、运行时和可观测性公司可以创立」的桥梁。

瓶颈

阵列可能会闲置。

在解码（decode）阶段，模型往往一次只生成一个 token。这会让矩阵引擎利用率不足，除非有批处理、GQA、投机解码或其他调度技巧来帮忙。

瓶颈

HBM 很贵。

模型权重和 KV 缓存消耗昂贵的内存。长上下文让情况更糟，尤其是旧上下文即使很少被用到也还待在 HBM 里。

瓶颈

GPU 软件强大但复杂。

CUDA、kernel、warp 和调度都很成熟，但也带来开销。如果编译器栈足够优秀，类 CPU 的加速器可以更容易编程。

第 4 步

大家都在做的 vs 我们可能做的。

关键是要避免把这些当成随机的架构术语。每一个都是对当前 GPU 推理某个痛点的回应。

通俗英语词典

不故弄玄虚的术语。

每当觉得某个术语陌生时，就来看这一节。每条定义也解释了为什么这个术语对当前 GPU 推理重要，以及它为什么出现在产品创意里。

GPU 推理

在 GPU 上运行训练好的模型来回答用户请求。没有训练发生；模型在提供输出。

为什么重要：这是基线。这里的每个创意都在问 GPU 已经做得好的是什么，然后寻找服务 token 仍然昂贵的地方。

脉动阵列

一个乘加单元网格，通过让数字以稳定模式流过网格来执行矩阵乘法。

为什么重要：它已经存在于当前 NVIDIA GPU 里，作为 Tensor 核心的一部分，当前的 LLM 推理依赖它。我们提到它，是因为让这个引擎保持忙碌是核心硬件问题。

Tensor 核心

NVIDIA 给加速神经网络矩阵运算的 GPU 单元起的名字。概念上，这就是脉动阵列式矩阵引擎所在的地方。

为什么重要：当 GPU 做 LLM 推理很快时，Tensor 核心承担了大量有用计算。任何竞争芯片都必须说明它如何同样好或更好地喂饱矩阵引擎。

矩阵乘法

把数字的行和列组合起来的核心运算。transformer 在注意力层和前馈层里用到它。

为什么重要：LLM 推理之所以昂贵，很大程度上是因为它执行海量的矩阵乘法。这就是矩阵引擎主导硬件讨论的原因。

HBM

高带宽内存（High Bandwidth Memory）。封装在加速器旁边的极快内存，但每 GB 很贵。

为什么重要：当前 GPU 推理依赖 HBM 来存模型权重、激活和活跃 KV 缓存。降低 HBM 压力可以提升每美元能换来的 token。

SRAM

芯片上极小、极快的内存。它比 HBM 离计算近得多，但容量有限。

为什么重要：kernel 把分块加载进类 SRAM 的快速内存，让 Tensor 核心能复用数据，而不是反复回 HBM。

SSD

便宜的大容量存储。比 HBM 慢，但对不需要每微秒都访问的数据很有用。

为什么重要：SSD 出现在这些创意里，是因为如果软件能智能地取回，更早的上下文或冷 KV 缓存数据就可以从昂贵的 HBM 挪出去。

KV 缓存

之前 token 存储的键和值向量。它让模型在生成期间能回看之前的上下文。

为什么重要：长对话和长文档在 GPU 内存里产生很大的 KV 缓存。这就是内存分层、压缩和稀疏注意力重要的原因。

DMA

直接内存访问（Direct Memory Access）。一个硬件复制引擎，在不需要 CPU 手动做每次复制的情况下，在内存区域之间搬运数据。

为什么重要：推理性能取决于在当前块计算时搬运下一块数据。DMA 是能让计算保持被喂饱的传送带。

DMA 压缩器

内置压缩和解压的 DMA 引擎，让更少的数据穿过内存或网络链路。

为什么重要：如果权重、激活或 KV 缓存在移动时被压缩，同样的 HBM 和网络带宽就能服务更多有效 token。

预填充（Prefill）

模型在生成之前读取提示词或文档。许多输入 token 可以被一起处理。

为什么重要：预填充通常能高效利用 Tensor 核心，因为许多已知 token 可以被批量成大的矩阵乘法。

解码（Decode）

模型生成输出 token。它往往一次一个 token，更难高效利用。

为什么重要：解码是延迟、KV 缓存读取和低矩阵引擎利用率经常出现的地方。许多服务创意都是解码创意。

GQA

分组查询注意力（Grouped-Query Attention）。一种 transformer 注意力设计，在查询头之间共享一些键/值工作。

为什么重要：使用 GQA 是因为解码可能很吃内存。它减少了 KV 缓存流量，这既帮助当前 GPU 推理，也帮助未来的加速器。

投机解码

一种服务技巧，用一个更小或更便宜的过程猜测未来 token，主模型再验证它们。

为什么重要：它能把一次一个 token 的解码变成更大的工作块，让矩阵引擎每一步都有更多有用工作。

CUDA、kernel 和 warp

CUDA 是 NVIDIA 的 GPU 编程平台。kernel 是一次 GPU 函数启动。warp 是一起被调度的一组 GPU 线程。

为什么重要：这是当前 GPU 推理背后的成熟软件模型。新的 AI CPU 创意只有在能既不损失性能又让编程更容易时才有意义。

算子融合

把多个模型运算合并进一个 kernel 或流水线，让中间结果留在计算附近。

为什么重要：融合减少回 HBM 的次数。这是编译器与运行时能在不改模型的情况下改变经济性的原因之一。

软件流水线

调度加载、计算和存储工作，让芯片的不同部分同时忙碌。

为什么重要：如果矩阵引擎在等内存，钱就在被浪费。流水线是软件隐藏搬运延迟的方式。

MoE

专家混合（Mixture of Experts）。一种模型设计，每个 token 只使用一部分专门的专家网络。

为什么重要：MoE 能降低每个 token 的计算，但当专家分布在多块芯片上时，会带来路由和网络问题。

环面网络

一种布局，芯片以带环绕链路的环或网格连接到邻近芯片。对某些 AI 通信来说，它可以比全路由更便宜。

为什么重要：大模型经常跨许多芯片运行。网络决定了 all-reduce、路由和模型并行会变多贵。

AI CPU

一种类 CPU 的加速器，带大缓存和附着在可编程核心上的矩阵引擎。

为什么重要：提案不是要移除矩阵引擎，而是要保留 LLM 数学引擎，但用一个更简单、更像 CPU 的编程模型把它围起来。

Y Combinator 问题

一份认真的创业申请应该能回答的问题。

这些问题把技术创意变成公司形态的思考。答案应该简短、具体，并扎根于一个可度量的推理痛点。

公司

你在构建什么？

用一句通俗的话说出产品。例如：「我们通过把冷 KV 缓存挪出 HBM 来降低 LLM 服务成本，同时保持回答质量。」

客户

谁有这个问题？

精确说出第一个买家：推理平台团队、模型实验室、云服务商、GPU 集群运营商，或有长上下文工作负载的公司。

痛点

今天什么是痛苦的？

把痛点连接到当前 GPU 推理路径：HBM 成本、解码延迟、闲置的 Tensor 核心、kernel 复杂性、KV 缓存增长或网络瓶颈。

洞察

你知道什么别人忽略的？

说出技术押注。例如：「瓶颈不只是 FLOPs，而是 HBM、SRAM 和矩阵引擎之间的字节搬运。」

演示

最小的令人印象深刻的 demo 是什么？

选一个窄的证明：一个模拟器、一个 vLLM 插件、一个压缩 KV 基准、一个更快的融合 kernel，或一个 FPGA DMA 压缩原型。

指标

哪个数字会变好？

用买家能理解的指标：每美元 token、输出 token 延迟、每请求 HBM GB、Tensor 核心利用率、每 token 瓦特，或每 token 网络字节。

竞争

客户现在用什么替代？

真正的竞争对手往往是「买更多 GPU」或「接受更低的利用率」。解释为什么你的方案更便宜、更容易或更可用。

时机

为什么是现在？

利用世界的变化：长上下文、推理模型、MoE、推理支出、HBM 稀缺、新的编译器栈，或对非 GPU 算力的需求。

风险

最难的技术风险是什么？

要直接。例如：稀疏注意力质量、压缩开销、编译器可靠性、客户模型变更、硬件验证，或多芯片调度。

进展

你怎么知道有人想要它？

展示 trace、基准、设计伙伴、意向书、付费试点，或一个当前 GPU 路径明显浪费的工作负载。

团队

为什么是这个团队？

指出已经做出来的东西：kernel、编译器、服务系统、硬件原型、真实用户使用的 infra，或异常强的技术执行力。

范围

第一个切入点是什么？

避免一开始就声称要拿下整个芯片市场。从一个痛苦的使用场景、一个模型家族、一个服务栈，或一个硬件原语开始。

一个好的答案模式

从当前 GPU 推理工作流开始，识别一个具体瓶颈，解释它存在的技术原因，展示你的方案能改进它的最小证明，并指出会在意的买家。
